## 零 · 一句话最成熟路径(批判者收敛全部 5 路后的裁决)

**核心两白板功能固化"零后端可用"为铁律 → Obsidian 插件先 BRAT 后官方商店分发 → 插件 first-run 向导(经用户确认)往 vault 铺资产 + 写入 skills marketplace 引用(不复制 skill 内容)→ 可选 RAG 后端照 LiveSync 模式做"一键 init 脚本 + Setup-URI 配置串 + 部署时生成 UUID vault_id 写入 vault 内配置"作隔离键。**

## 一 · 社区给出的最硬数据(方案的地基)

### 1. 后端形态直接决定采用率(20 倍差距实测)

| 插件 | 后端形态 | 下载量 |
|---|---|---|
| Smart Connections | **零后端**(transformers.js 内嵌 embeddings) | **105.8 万** |
| Obsidian Copilot | 无自带后端,外接用户已装的 Ollama | 百万级 |
| Self-hosted LiveSync | **必须自建 Docker CouchDB** | **75.4 万**(靠三件套压平摩擦) |
| Khoj | 独立 Docker/pip 多服务后端 | **5.1 万**(项目本身 3.5 万 star——"想用的人多,装得动的人少") |

→ **Docker 不是死刑,"多服务+手工配置+无自动初始化"才是**。LiveSync 能赢靠:①价值不可替代 ②一行 `curl init.sh | bash` ③加密 Setup URI 一键导配置。

### 2. 与 CLS 技术栈同构的死亡先例(最重要的警告)

**obsidian-neo4j-graph-view**:要求用户装 Python + Neo4j Desktop → 作者被迫弃用整个插件,重写为零依赖的 Juggl,README 原话把"Remove the need to install Neo4j and Python"列为重写首要目标。
→ **CLS 的 Neo4j+LanceDB+Ollama 四服务 compose 绝不能成为三大功能的必装前置**——好消息:检验白板 v1.1 已经天然零后端,这个现状必须固化成分发铁律而非巧合。

### 3. Claude Code 生态的分发正统已存在

- **kepano(Obsidian CEO)的 obsidian-skills**(12.9k star):skills 放 vault 根 `.claude/`,一条 `npx skills add` 安装——**与 CLS 的 8 个 skills 形态完全同构,这就是正统姿势**。
- **Claude Code plugin marketplace 官方机制**:vault 内提交 `.claude/settings.json` 声明 `extraKnownMarketplaces + enabledPlugins` → 用户信任文件夹时**自动提示安装**——把"铺资产"和"装 skills"缝成一键的官方路径。
- **claudesidian**(2.5k star):Claude Code + Obsidian 模板 vault 最成熟先例,其 `/init-bootstrap` 向导 + `/upgrade` 增量升级命令值得抄。

### 4. 合规红线(决定性,CLS 恰好站在对的一边)

Anthropic 2026-01 起**服务端封禁第三方工具使用 Claude 订阅 OAuth**(OpenCode 被迫移除,条款明文禁止)。**唯一允许:官方 Claude Code harness 内执行**——CLS 的"skills 放 vault、用户自己的 Claude Code 执行"正是唯一合规形态。⛔ 任何"插件后台代持订阅 token"的演化方向都会被封禁。

## 二 · 推荐架构:三层分发(每层都有社区先例)

### Tier 0 · Skills 内容层 → 独立 repo + marketplace(批判者裁决:不复制,引用)
- 8 个 skills 抽成独立 GitHub repo(如 `cls-skills`),按 Agent Skills spec 组织 → 兼容 `npx skills add` + 注册 Claude Code plugin marketplace。
- **为什么不由插件复制进 vault**:复制件没有升级通道(模板 vault 的公认死穴,claudesidian 被迫自建 /upgrade);marketplace 自带版本管理。先例:kepano/obsidian-skills、obra/superpowers。
- vault 内只留 `.claude/settings.json` 引用(官方"信任即提示安装"机制接管)。

### Tier 1 · Obsidian 插件层 → BRAT 起步,官方商店收尾
- **早期**:GitHub release 三件套 + `obsidian://brat?plugin=oinani0721/仓库` 一键链接(BRAT 自带自动更新)。
- **成熟**:提交官方商店(自动扫描审核;"带可选自托管后端"有 LiveSync 75 万下载先例,政策上**披露即合法**;硬禁止仅三条:客户端遥测/插件自更新/动态广告)。
- **first-run 向导**(照 Excalidraw Script Store 三原则):显式征求同意再写入、目录名可配置(防撞已有 vault 结构)、托管资产隔离在专用子目录且"可覆盖更新"语义;幂等 ensureFolder(缺则建,有则跳过)。manifest 标 `isDesktopOnly: true`(诚实声明,移动端=可看可批注,AI 功能桌面执行)。

### Tier 2 · 可选后端层(精确检索/长期记忆)→ LiveSync 化
- 一键 init 脚本(把"服务起了但没初始化好"类静默故障全部消灭在脚本内,含健康检查)+ **CLS Setup URI**(`obsidian://setup-cls?settings=<加密串>`,含后端地址/vault_id/token,点击即完成插件↔后端绑定——LiveSync 已验证的 onboarding 范式)。
- **插件必须内置后端健康检查 + 不可达时自动降级**到离线 skills 路径并明说"精确检索暂不可用"(Khoj 的"甩一句 ensure backend is running"是差评直接来源)。
- 中期评估:精确检索能否降级为**插件内嵌 embeddings(transformers.js)或复用用户自装 Ollama**(社区首选形态;注意 OLLAMA_ORIGINS CORS 经典坑——让请求从后端发起可根治)。→ 这是一个待你拍板的方向性问题。

## 三 · 多 vault 隔离方案(批判者裁决 1:显式 UUID,禁用 vault 名)

社区双层共识(File over app 宣言 + 全部头部插件实践):
1. **真相源放 vault 内**(你的 md/frontmatter/白板——已达成):整 vault 一个文件夹即完整备份,换设备零迁移。
2. **外部存储 = 可重建的派生层,按显式 vault_id 分桶**(LiveSync per-vault database / Remotely Save per-vault prefix 同构)。

**vault_id 生命周期协议**(全部对应社区踩坑证据):
- ① 部署时生成 **UUID** 写入 vault 内 `.canvas-config.yaml`;⛔ 绝不用 `app.appId`(官方开发者明确劝退:未文档化/跨设备不一致/随时移除)、vault 路径(移动即变)、vault 名(可重名——LiveSync 正因此被迫加防碰撞后缀)。
- ② 后端一切存储(Neo4j group_id=`vault:<uuid>`、LanceDB 表前缀)由它派生——与你现有 build_vault_group_id 规约同构,方向已被社区验证。
- ③ vault 改名/移动不影响身份(ID 随文件走)——恰好规避 Obsidian Sync 改名断连的坑。
- ④ **复制 vault 检测**:ID 会随复制带走,插件启动用 vault 名+路径指纹做变更检测,提示"疑似复制的 vault,是否生成新 ID"(防两个 vault 混写同一桶)。
- ⑤ 后端数据声明为可重建派生层,提供 rebuild-from-vault 兜底命令(vault_backfill 已有雏形)。

**vault 内文件分类铁律**(Smart Connections `.smart-env` git 冲突逼用户卸载的教训):
- 用户资产(节点/白板 md)→ vault 内,参与同步 ✓
- 派生缓存/索引/机器状态 → **绝不进 vault**(放 `.obsidian/plugins/<id>/` 或 vault 外)+ 提供 gitignore 模板
- ⚠ 需要逐项审查现有写入物:`calibration_log`、`mastery_score` frontmatter(用户资产,OK)vs 未来任何索引缓存(必须出 vault)

## 四 · 必须避开的 6 个坑(R5 对抗调研,每个带真实案例)

1. **强制后端 = 插件死亡**(Neo4j Graph View→Juggl 重写;Khoj 被迫转云端)
2. **vault 污染**(Smart Connections .smart-env 持续 git 冲突→用户实名卸载文)
3. **"全家桶"抵触**(Make.md 启动吃 90% CPU 被要求拆包)→ CLS 启动严禁全 vault 扫描;叙事上"三大功能=核心,其余=可选模块"
4. **移动端假装支持**(localhost 结构性不可达)→ `isDesktopOnly` 诚实声明 + 文档给 Tailscale/LAN 链接
5. **代持订阅 token**(Anthropic 服务端封禁)→ 只走官方 harness;目标人群明示"已在用 Claude Code 的学习者",保留 API key 路径
6. **整 vault 模板当主分发**(Ideaverse 官方自己都要求"开新 vault 别并入已有 vault";.obsidian 无官方合并机制)→ 模板 vault 只做 demo 试玩,主路径=插件向导增量安装

## 五 · 批判者揪出的 4 个盲区(下一步必须补的功课)

1. **许可证(阻断级)**:官方商店必须带 LICENSE、不收闭源新插件;Neo4j CE 是 GPLv3("用户自拉官方镜像"模式安全,但托管/商业化会踩线)——CLS 插件/skills/后端三件均无 license 决策。
2. **三层升级链**:插件层有答案(商店/BRAT),vault 资产层(claudesidian /upgrade 模式)和后端 schema/索引迁移(换 embedder=全量重建)无答案——"一键部署解决第 1 天,第 30 天的升级没答案用户就卡死在旧版"。
3. **安全面**:compose 模板必须强制随机密码 + 默认 127.0.0.1 绑定;"信任文件夹即装 skills"本身是把代码执行入口交给分发者(即你),需在 README 披露。
4. **门槛量化**:四服务内存门槛、Claude 订阅 5 小时限额对 8-skill 工作流够不够、一键脚本的 Windows/PowerShell 版——三项决定"别人"的实际范围。

## 批注回复(2026-07-10 · 你拍板:GitHub 发布,不上架商店)

**好消息:这个决定让方案更简单,且零返工成本。** BRAT 本身就是社区标准的"GitHub 发布"消费通道——原方案里它只是"早期过渡",现在升级为**长期主通道**。

### ① 简化了什么
- **Tier 1 = BRAT 单通道**:GitHub release 三件套(main.js/manifest.json/styles.css,tag=版本号)+ README 放一条 `obsidian://brat?plugin=<你的用户名>/<仓库>` 一键链接。零审核、零等待,**发 release 即全体用户自动更新**(BRAT 自带)。
- 官方商店的硬约束(自动扫描/safety scorecard/审核排队)全部退场;"插件禁自更新"规则也不再约束——但不必自造更新器,BRAT 已免费提供。
- 若未来想上架:BRAT 与商店消费**同一套 GitHub release**,无需任何返工,只是多提交一次。

### ② 不因此改变的(仍是铁律)
- **LICENSE 仍必做**,理由从"商店审核"变为"GitHub 公开分发的法律基础"——无 LICENSE 时别人**默认无权使用/复制**你的代码。建议:插件+skills 用 MIT;后端 MIT;Neo4j 保持"用户自拉官方镜像"边界。
- 合规红线(不代持订阅 token)、UUID vault_id 隔离协议、vault 文件分类铁律、六坑清单——全部与商店无关,照旧执行。
- Tier 0(skills 独立 repo + `npx skills add` + marketplace 引用)不变——它本来就是纯 GitHub 形态。

### ③ 客户的最终一键动线(GitHub 版)
README 三个按钮:
1. **[安装 CLS 插件]** `obsidian://brat?plugin=…`(首次需从商店装 BRAT,一次性,BRAT 本身是官方商店热门插件)
2. **(可选)[启用精确检索后端]** `curl …/init.sh | bash` → 点终端打印的 `obsidian://setup-cls?settings=…` 完成绑定
3. **[下载演示 vault]**(模板 vault 只做试玩,不做主路径)

插件装好后 first-run 向导:确认 → 铺 原白板//节点//检验白板/ + Dashboard + `.canvas-config.yaml`(生成 UUID vault_id)+ 写 `.claude/settings.json` skills 引用 → 开始学习。

### ④ 对北极星计划的最终修订
- A5 的 Tier 1 从"BRAT→商店两阶段"简化为 **"BRAT 单通道(商店留作未来可选)"**。
- A6(LICENSE)保留,优先级不降(理由见 ②)。
- 其余 Phase A/B/C 不受影响。
