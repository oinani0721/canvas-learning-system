## 一 裁定：**乙-2 的字面形态不可行**

三个独立设计方案（最小改动 / 口径统一 / 分层并陈）在对抗审查下**各得 3 条致命**，共 9 条。
三条最根本的：

### 1.1 读时重判会**新造**「假到期」——错误方向比现状更坏

- 生产器的判据是 `f(当刻 frontmatter 的 fsrs_due, 当刻墙钟)`（`daily_review_pick.py:561`）
- 乙-2 是 `f(generated_at 时刻拍下的 fsrs_due, 当前墙钟)`

这**不是**「同一条规则换个时钟」，而是**同一条规则跑在已经作废的操作数上** ——
产出唯一裁判从未做出、此刻也会反对的判决。

方向性判据（这是它比现状**更坏**的地方）：
- 现状的错恒是「某次生产器在 `generated_at` 说过的话」—— 滞后 / 多报；
- 乙-2 的错是「任何一次生产器运行都没说过、现在也不会说的话」—— **新增假阳性**，
  还带节点名 + `obsidian://` 深链，且用户点一下「刷新投影」就会被当场证伪。

⛔ 三个方案都把「单调只增 ⇒ 不引入漏报」写进合规论证，方案二还把它写成门 `G4(c)` ——
**那是把错误方向锁成不变量**。

### 1.2 本仓已有一条**相反口径**的现成裁判

`scripts/daily_review_run.py::ensure_payload`（:141-152）对「有排期节点到点了吗」的回答是
**整轮重扫 vault**，且带两道门：

```python
due_crossed = bool(st.get("next_due_utc")) and st["next_due_utc"] <= now_z
if not due_crossed and _nodes_max_mtime(VAULT) <= payload_path.stat().st_mtime:
    return json.loads(raw), "cached"
```

`_nodes_max_mtime` 的 docstring 明写「文件 mtime 抓原地更新（**quiz 写 fsrs_due 不动目录**）」，
来源是 Codex-A3 BLOCKER。乙-2 读到**同一个信号**（越过到期点），结论却是
「快照仍可用，直接下判决」，且**完全不看第二道门** —— 而那道门是系统里唯一能识别
「这张卡已经被答过」的信号。同一系统、同一问题、两套相反口径，新加的这套零守卫。

### 1.3 ⛔ 目标句不闭合（与实现无关，已由主 session 独立复现）

用户原话「**答错的**卡到点后自己出现」在乙-2 的**任何**形态下都不成立：
答题写入的新 `fsrs_due` **根本不在投影里**（复现 #2）。乙-2 的上限是
「**投影里已排期**的卡到点即显形」。

## 二 可行的形态：乙-2′（加性层 + 三处修补）

选方案一（加性层）当基座，因为它是唯一 **不推翻 `due_count` 权威计数**、
不与 `Dashboard.md` / `outputs/今日复习.md` 造帧分叉的形态 ——
A2「所有地方显示同一个数字」在 `due_count` 上逐字存活。

| 修补 | 治什么 | 要点 |
|---|---|---|
| 1 · 逐节点新鲜度前置门 | 幻影到期 | `stat(节点/X.md).st_mtime <= min(投影 mtime, generated_at)`；不通过就跳过（fail-closed，不猜） |
| 2 · 重判放在 stale 四态**之后** | 在过期投影上照跑 | `_summarize` 结构上拿不到「这份投影是不是今天的」；一份昨天的投影会让 `due_today` **整桶**被判「刚到点」 |
| 3 · 就地标注而非并列区块 | 同屏矛盾 | 「今天晚些 1」+「刚到点 1」是对**同一节点**的两句互斥陈述且无门可写；改为在该行上标 `⏰ 已到点` |

### ⛔ 修补 1 的直接后果——这是本文最重要的一句

> **用户一旦答题，被答的那张卡就永久退出重判候选（直到下次重建）。
> 所以在「答错 → 60 秒后重来」这个发起本次讨论的场景里，乙-2′ 输出恒为 0，
> 页面与今天一模一样。**

乙-2′ 的**实际**收益是：在**没有答题活动的时段**（夜间只看板、白天两档之间），
已排期的卡到点即显形，把 ≤1 小时（白天）/ ≤13 小时（20:05→09:05）的滞后
压到一个轮询周期（≤60s）。

## 三 与 Z1-C（CARD-G6-5）的顺序

**Z1-C 先，乙-2′ 后**（与三个方案的建议相反）。理由：修补 3 把依赖方向倒了过来——
乙-2′ 的正确 UI 形态是**在非到期层的节点行上就地标注**，而**节点级的非到期行只有 Z1-C 才会渲染**。
乙-2′ 先落，只能退回被判 fatal 的「并列第二区块」形态。

**Z1-C 的 `sum == counts == stats` 硬断言：一个字都不用改**（乙-2′ 不搬移节点、不改写 payload），
但卡文必须补一句参照系：

> 本断言的参照系是 `generated_at`，不是 `now`。读侧到点标记不并入本等式的任何一个被加数。

⚠ 反向提醒：若哪天有人把 (c) 改成 now 帧（真去搬移节点），那一刻起「答错的卡到点了」
会变成 `_gate_buckets` 抛 `ValueError` → **整库 corrupt 降级** → 页面直接坏掉，比现在的「看不见」更糟。

## 四 需要用户重新裁定的问题

**乙-2′ 兑现不了你最初提的那个场景。** 请在下面三条里选：

- **甲 · 改写目标句后仍做乙-2′** —— 目标改成「投影里已排期的卡到点即显形」，
  收益是消掉白天 ≤1h / 夜间 ≤13h 的滞后。代价：一张新卡，12 道门（含 1 道必须落在真实文件系统上的幻影门），排在 Z1-C 之后。
- **乙 · 不做乙-2′，改做「答题后触发重建」** —— 直接命中「答错的卡到点自己出现」。
  但自动轮询触发 POST 已被默认裁决② 禁掉（且刚被 G6-3 的第 ④ 条断言锁死），
  所以触发点必须在**写侧**（`fsrs_bridge` 写完后通知），那是另一张卡、另一条链路。
- **丙 · 都不做** —— 回到 G6-3 的甲案：承认清单是定时算的，想立刻看到就点「刷新投影」。

我的建议：**乙** 更贴近你的原意（你要的是「答错的卡自己出现」），
而且它绕开了乙-2 全部 9 条致命——因为它让投影里的 `fsrs_due` 变**新**，
而不是拿旧值配新钟。甲案是个独立的、较小的改善，可以之后再做。

## 五 这份设计**没有证明**什么

1. **逐节点新鲜度门从未实测**——`min(proj_mtime, generated_at)` 作 bound 这个组合本卡首次提出。
2. **没有证明 mtime 是充分信号**——保 mtime 的还原操作（rsync -a / Time Machine）未覆盖；
   「改了正文但没改 fsrs_due」会造成假阴性（方向安全，但功能静默失效）。
3. **没有量化收益**——「无答题活动时段」占实际使用多大比例、每天真正提前显形几张卡，零数据。
   live vault 当前 `due_today = future = 0`，**提升恒 0**，既不能当验收证据也不能当收益证据。
4. **没有走通 Z1-C 依赖**——修补 3 假设 Z1-C 会渲染节点级非到期行，而 Z1-C 尚未开工。
5. **没有解决另一半多报**——「答过了却还挂在到期数里」仍只能靠重建投影；乙-2′ 单向、不移除。
6. **乙案（写侧触发重建）本文完全没有设计**——只是指出它绕开了乙-2 的致命面。
