## 你问的第一个问题：生成考题用的是什么 AI？是 claude code 吗？

**答：不是 claude code。是 Google Gemini。**

- **claude code** = 我（写代码的这个工具/助手）。它只在"开发阶段"帮你改代码，跟你用产品时"出题"这件事**完全无关**。
- 你**用产品时**点"考察"，生成题目文字的是 **Google Gemini**（配置里写的 `gemini-3.1-flash-lite-preview`）。
- 顺带分清，这个系统里有三个不同的 AI 角色（你之前可能混在一起）：
  1. **出题/评分的 AI** → 现在是 Gemini ← 你问的就是这个
  2. **记忆抽取的 AI**（Graphiti 整理对话）→ 也是 Gemini
  3. **算向量的 AI**（embedding，做语义检索）→ 我上次已换成本地 bge-m3

### ⚠️ 但这里有个现在就卡住你的问题

我实测发现：**出题这个 Gemini 现在是坏的，你根本生成不出题**，两个原因叠加：
1. **地理封锁**：和上次 embedding 一样，Gemini 对你所在区域返回"User location is not supported"。
2. **配置本身写错了**：出题的模型名 `gemini-3.1-flash-lite-preview` 不是真实存在的模型，前缀也写错了。

所以你做 UAT 时点"考察"大概率是报错 / 出不来题 —— **这不是你操作问题，是出题 AI 没配对也没法连。**

### 解法：和换 embedder 一样，把出题 AI 一键切换

底层用的 litellm **本来就支持切换 AI**（改个配置就行，不用改代码）。可选：

| 选项 | 是否受地理封锁 | 出题质量 | 备注 |
|---|---|---|---|
| **Claude API（推荐）** | 否，能用 | 高 | 你本来就在 Claude 生态；和"claude code"不同，这是运行时调 Claude 的 API |
| OpenAI (gpt-4o-mini 等) | 否，能用 | 高 | 需要 OpenAI key |
| 本地大模型 (qwen 等) | 否，零成本 | 中（出题要结构化输出，本地模型偶尔不稳） | 出题比 embedding 难，本地模型这块不如云端稳 |

> **我的建议**：出题/评分切 **Claude API**（云端，稳，质量高）；embedding 保持本地 bge-m3。这样你既脱离 Gemini 地理封锁，出题质量也最好。

## 你提的第二件事：考题应优先"原白板层面"而不是"节点层面"

**答：你的直觉完全正确，而且这个能力代码里其实已经造好了一大半——只是没接到你点的那个按钮上。**

### 现在是什么样（节点层面）

你现在测的"快速考察"是这样：**你打开哪个节点的 md，它就只考那一个节点**。它只看那个节点上你打的批注，孤立出一道题。这就是你说的"节点层面"。

### 你想要的（白板层面）其实已经有了

后端有一个叫 `select_target_node` 的机制，它做的正是"白板层面优先"：
- 给它一个**原白板**（一组相关节点的集合），
- 它会**综合看整个白板下所有节点的学习状态**——哪个你掌握得最差、哪个快忘了、哪个在知识图谱里最关键，
- 然后**自动挑出最该考你的那个节点**出题，而不是你随便打开哪个就考哪个。

这套"从整个白板挑最该考的"+ 会话管理（记录已经考过哪些、避免重复）+"检验白板"考试系统，**后端已经建好了**。

### 那为什么你没感觉到？

因为**前端没把这套白板级系统接上**：
- 你现在点的"快速考察"走的是简单的单节点路径（没用 `select_target_node`）。
- 白板级的"检验白板"需要一个前端界面（选哪个原白板、显示考试进度），**这个界面还没做**。

所以：把考察升级成"白板层面优先"**不是从零开发**，是"把已经造好的白板级出题引擎，接到前端的考察入口上"。工作量集中在：
1. 前端：让你能"从一个原白板发起考察"（而不是只能打开单个节点），
2. 后端考察入口：改成调用已有的白板级出题（`generate_exam_question` + `select_target_node`），
3. （可选）前端显示考试进度（考了几个节点、还剩哪些）。

# 第二轮批注回复（你又追问的两点）

## 追问 1：为什么不能用 claude code 出题？

**答：能。而且这正是你之前自己定的「Mode D」架构——只是现在没接成。**

- 你的架构文档（`planning-artifacts/architecture.md:113-114`）白纸黑字写着 **Mode D**：用 Claude Code + **你的订阅额度**出题（"Tool-UI Bridge，用户订阅额度"）。所以"用 claude code 出题"不是不行，是**你本来就这么设计的**。
- 但现在**两条出题路都绕过了它**，都让后端用 Gemini API 出题：
  1. 一键快速考察 → 后端直接调 Gemini；
  2. 连给 Claude Code 用的 **MCP 出题工具**，点进去也是**后端自己调 Gemini** 把题目生成好，没把"出题"这件事交给 Claude Code。
- **根因**：后端那个出题函数把"调 Gemini"写死了，不管谁来调都先走它。
- **要真正用 claude code / 你的订阅出题（落地 Mode D）**：把 MCP 出题工具改成「**只返回出题需要的上下文（你的批注 + 学习状态），由 Claudian 侧栏里的 Claude Code 用你的订阅生成题目**」。这样：✅ 零 API 成本　✅ 不受 Gemini 地理封锁　✅ 符合你的架构决策。
- **代价**：交互方式从"按快捷键秒出一道题"变成"在 Claudian 侧栏让 Claude Code 给你出题"（对话式，不是一键）。这是你要权衡的 UX 取舍。

> 所以"出题 AI"的选择其实有**第 4 个、更符合你初衷的选项**：不花 API 钱、用你的 Claude 订阅（Mode D）。代价是出题入口从"一键"变"侧栏对话"。
