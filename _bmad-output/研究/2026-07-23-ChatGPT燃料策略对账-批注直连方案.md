| R3 | Canonicalization 前置（note_id/block_id/concept_id 锚点） | ✅ 采纳 | 我们的扁平节点池天然有稳定主键（文件名=node_id，批注有 id 字段）——成本极低收益直接 |

| R15 | Mem0「不是所有记忆都值得进显式图」作为反例镜子 | ✅ 采纳判据 | 支持 R1 的过滤哲学 |

**ChatGPT 自声明的证据边界**（诚实，记录在案）：它没能读取源码包，架构级审查基于任务书；监控阈值全部是经验值非上游硬指标。

## 二、修正与合成：批注 7 类的真实映射

ChatGPT 报告里的分类（error_candidate/definition_fix/derivation_reason/exam_event）混入了**非批注通道**（派生原因、考察事件已有独立入图通道，批次4' 刚修完）。落到我们真实的 7 类 callout：

| 我们的批注类型 | 分级 | 去向 |
|---|---|---|
| `question`（疑问） | **高价值** | 过滤直连 → json episode 分钟级入图 |
| `error`（错误） | **高价值** | 过滤直连 → 只生成**候选**（candidate_only 铁律），用户 accept 才成 Misconception |
| `tip` / `hint` / `note` / `warning` / `info` | 低价值 | raw lane（frontmatter tips[] + learning_events.jsonl，已有）——**一期不入图**；依旧经 SessionEnd 蒸馏间接可入 |

判据落地为一句话：**会改变下次出题/讲解行为的批注（疑问、错误）直连入图；只是「值得再看到」的批注（其余 5 类）留在文件层，图不背原文仓的锅。**

## 三、批次5' 方案草案 — 批注过滤直连管道（估 1.5-2 天）

> 对应 ChatGPT 路线图阶段一 + 我们「后续轨道 C1 管道修复」的具体化。

1. **①管道复活（过滤直连版）**：废除 tips.py 410 死代码，新端点只收 `question`/`error` 两类；`error` 强制走 write_error_dual(candidate_only)
2. **②json episode + 锚点**：受控 schema（callout_type / note_id / block_id / concept_anchor / text / 原始时间 / candidate_only），`EpisodeType.json` 入图（已实测 API 可用）
3. **③时间戳守卫**：reference_time 强制 = 批注原始时间（修 R5 抓到的 `datetime.now()` 默认陷阱）；缺原始时间 → 拒收进 DLQ，不补「现在」
4. **④背压与 DLQ**：复用 episode_worker 单 worker 串行 + 现有死信机制；新增 schema 失败免重试分类
5. **⑤plugin 侧触发**：Cmd+Shift+A 打完 question/error 批注 → 静默 POST 新端点（失败落本地待发队列，复用 SessionEnd hook 的 pending 模式）；不阻塞打批注手感
6. **⑥监控最小集**：schema 失败率 / 待处理最老年龄 / 近重实体率 3 项并入 memory-health.sh
7. **⑦验收**：G0 门禁跑三路对照（直连开 vs 关）——新增 `fresh_callout_hit_rate` 指标（刚打的批注 10 分钟内能否被检索引用）进 gold set 门禁

**回退方案**：任何结构写入故障不影响 raw lane（frontmatter/事件日志照常）；重复实体率超 5% → 冻结 question 直连只留 error 候选。
