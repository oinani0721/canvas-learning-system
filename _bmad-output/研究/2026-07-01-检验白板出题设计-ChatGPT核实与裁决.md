## 四、⛔ 最重要的一处纠正:校准偏差**不是"闲置"**

ChatGPT 全文的头号"缺口"是 **"`calibration_bias` 算了存了但没接入出题,本包里甚至没暴露它的代码位置"**。**这个事实前提是错的**:

- **它已经被算**:`signal_registry.py:192-229` 的 `CalibrationBiasSignal` + `calibration_tracker.py`(`CALIBRATION_BIAS_THRESHOLD = 0.15`)
- **它已经进了 5 信号融合**:`main.py:241` 注册 → `mastery_fusion.py:46-94` 加权融合,权重 0.10
- **它已经间接影响出题**:融合值 → `effective_proficiency` → `question_generator.py:517-525` 的难度档

**所以真正的缺口不是"闲置",而是措辞要精确成:**
> 校准偏差目前**只经 5 信号融合间接稀释进"难度档"(权重 0.10),没有作为独立信号去改变题型 / Bloom / 验证策略**(过度自信→反例/错误诊断题,不自信→降表面难度但保留生成)。

**好消息(比 ChatGPT 以为的省事):** 它建议的"过度自信→出反例题"设计**仍然完全成立且值得做**,而且**信号值现成、不用从零造**——只要把 `calibration_bias`(和现成的 `false_mastery_risk`)从融合黑箱里**单独拎出来**喂给出题逻辑即可。ChatGPT 因为没在打包文件里看到它,把接入点设计成"在出题层和 exam record 层从头建",这步可以省掉。

## 五、⛔ 落地点纠正:设计要搬进 **Skill**,不是后端 `question_generator.py`

ChatGPT 把所有落地建议(`compute_question_policy()` 插在 `_call_llm_for_question()` 前、改 `build_5_layer_prompt()`)都写在**后端 `question_generator.py`** 上。但:

- **后端 `question_generator.py` 走的是 Gemini 出题路径 —— 已地理封锁,且不是真检验白板的路径。**
- **真检验白板 = Mode D:Claude Code 订阅出题,读 frontmatter,根本不调 `question_generator.py`。**(见 `2026-07-01-检验白板Skill-草稿.md`)

**结论:ChatGPT 的设计"内容"(决策表 + ZPD 规则 + system prompt)可以搬,但"落点"是检验白板 Skill 的 markdown 指令,不是后端函数。** 这带出一个必须先定的架构决策:

> **数据暴露问题**:Skill 现在只从节点 frontmatter 读 `mastery_level` + `fsrs_next_review_at`。要落地 ChatGPT 的设计,Skill 还需要拿到 `calibration_bias`、`false_mastery_risk`、`fluent_count`、`retrievability`。两条路:
> - **路 A(轻)**:`/quiz-answer` 更新熟练度时,把这几个值一并写回节点 frontmatter,Skill 直接读。
> - **路 B(重)**:扩 `query_mastery` MCP 工具返回这几个字段,Skill 调 MCP 拿。
> → 建议先走**路 A**(零新 MCP、和现有 frontmatter 读取一致),MVP 够用。

## 六、可落地清单(按"能不能直接用"分三层)

### ✅ 强证据 + 真实代码 = 可直接落地

1. **把目标 Bloom 从"LLM 自决"改成"系统先算再约束"** —— 代码根据坐实(`target_bloom_level` 已是 LLM 返回字段),这是最高杠杆的一改。
2. **6 级熟练度→Bloom 决策表**(替换现有 4 档)—— 有证据(检索练习/生成效应/解释性提问),且用上了现成的 `fluent_count>=2` 门槛区分"真掌握 vs 看起来会"。
3. **校准偏差 → 题型转向**(过度自信→反例/错误诊断;不自信→降表面难度保留生成)—— 信号现成,只差拎出来用。
4. **Why/How 配比随熟练度上移**(低 30% → 高 80%)—— 有证据,且和 layer5 已偏开放题一致。
5. **延迟反馈 + 静默评分**(不即时暴露标准答案)—— 和现有"静默评分 + Dashboard 汇总"设计天然吻合,Bjork/Smith&Kimball 强支撑。

### ⚠️ 需调整后再用

6. **ZPD = 目标成功率带**(新手 0.75–0.85 / 中 0.65–0.75 / 高 0.50–0.65)—— 方向对(desirable difficulty),但**具体数值是 ChatGPT 的工程假设,非论文原值**,ChatGPT 自己也标了"假设"。→ 先按此上线,拿真实答题日志校准。
7. **proxy difficulty(先不用真 IRT)** —— 合理(我们没有经标定的题库),但"每题只加一个伸手因子"是它的设计约定,不是证据结论。

### ❓ 待验证的工程假设(别当定论,ChatGPT 已诚实标注)

- 校准偏差阈值 ±0.15、桶级重校准"30 次 ±0.10"、高自信错误线索复用窗 3–7 天 —— 全是可取但**未证实**的数值,上线后 A/B 校准。
