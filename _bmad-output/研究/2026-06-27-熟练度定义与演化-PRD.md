# 熟练度：怎么定义、怎么演化（回到你的 PRD）

> 你的要求：deep explore PRD 里熟练度如何定义和演化。3 并行 Explore agent 通读 PRD + 代码后，大量引用你的原话。
> 一句话：**熟练度 = 5 个信号揉成的一个 0-1 分数；它只在你答题后更新；更新的同时顺便算出"下次该考你的时机"（FSRS）。**

## 一、熟练度是什么（定义）

不是单一来源，是 **5 个信号融合成一个 0-1 的 `mastery_level`**。

你的锚定 PRD 原话（`14-scheme-a-implementation-prd.md`）：
> `query_mastery(node_id)` · 读 node_id → **返回 5 信号融合后的单维 mastery_level (0-1)**
> **5 个核心信号**: BKT 掌握概率 + FSRS 记忆稳定性 + 考察评分 + 校准偏差 + 自信度自评

5 个信号用人话讲：

| 信号 | 人话 | 范围 |
|---|---|---|
| **1. BKT 掌握概率** | 从你答对/答错的历史，反推"你到底掌握了没"。新节点默认 0.30 起步 | 0-1 |
| **2. FSRS（3 个）** | 难度（这点对你多难）+ 稳定性（记忆能撑几天）+ 可提取性（此刻还记得多少） | 难度1-10 / 稳定性天数 / 可提取0-1 |
| **3. 考察评分** | 近 5 次考察的 4 维分均值 | 1-4 |
| **4. 校准偏差** | 你自评 vs 实际表现的差。负=你高估自己，正=你低估自己 | -1~1 |
| **5. 自信度自评** | 你答前自评"我觉得我会吗" | 0-1 |

融合成最终 `mastery_level`，代码里的权重（Story 5.3）：BKT 0.30 / FSRS 0.25 / 错误史 0.20 / 校准 0.15 / 自评 0.10。

**档位（节点颜色）**：🔴 < 0.4 薄弱 / 🟡 0.4–0.7 学习中 / 🟢 ≥ 0.7 基本掌握（代码还细分了"Mastered ≥0.9 且流利答对≥2 次"，防止虚假掌握）。

**一条铁律（FR-MAST-06）**：熟练度**只由考察表现更新**，你自己手动调自评**不会**直接改熟练度——自评只是融合的一个输入。

## 二、熟练度怎么演化（答题后这条链）

你的原话（PRD 开篇）：**「最终的熟练度判定是在我答题后决定的，从而推断我下次答题检验的时机」**——PRD 把它落成 5 步（`14-…prd.md:651-656`）：

> 1. 答题后调 `score_answer` 拿 **4 维评分**
> 2. 调 `update_bkt` 用评分更新 BKT（掌握概率）
> 3. 调 `update_fsrs` 用评分更新 FSRS（**这里算出下次复习时机 next_review_at**）
> 4. 调 `query_mastery` 拿融合后的 mastery_level（**这是最终熟练度判定**）
> 5. 写回节点 frontmatter

**演化全链**：
```
你答题
  → AutoSCORE 4 维评分（概念准确 / 推理质量 / 知识覆盖 / 知识整合，各 1-4 分）
  → BKT 更新：答对→掌握概率升，答错→降（贝叶斯）。grade=4 流利时认定"非蒙对"，升得更多
  → FSRS 更新：答对(grade4)→稳定性增长→下次考得越来越远；答错(grade1)→稳定性重置→1-2 天内就考
  → 5 信号融合 → mastery_level（你的熟练度）
  → 写回节点 frontmatter mastery_level → Dashboard Dataview 表格反馈（非节点变色，你已废弃染色）
```

## 三、FSRS 怎么"推断下次检验时机"（你最强调的）

- **稳定性 stability** = 你这次答对后，记忆从 100% 衰减到 90% 需要的天数。
- 答得越好 → stability 越大 → `next_review_at` 越往后（不用频繁考）；答错 → stability 重置 → 很快再考。
- **可提取性 retrievability** 随时间衰减，到阈值就该复习了。
- **Dashboard 用 Dataview 查**（PRD 原文）：
  > `FROM "节点" WHERE mastery_level < 0.5 AND fsrs_next_review_at <= date(today)`
  > 列出"掌握度低 + 到复习期"的节点 —— **这些就是检验白板该考你的节点**。

你 round-15 的类比原话：
> Anki 的 FSRS 不就是根据你记不记得，推算掌握程度，再推算复习时间吗？我的检验白板一开始也是根据我对各节点的实际掌握，精确推算复习时间，然后生成精确的检验白板，最大限度回顾原白板内容。

**所以"熟练度 → 下次时机 → 生成检验白板"是一条链**：熟练度低 + FSRS 到期 → 该生成检验白板考这个节点。

## 五、这对检验白板（Mode D）意味着什么

**好消息**：熟练度系统已经 ready，检验白板评分后只要喂一个 grade，整条演化链（BKT→FSRS→融合→变色→算下次时机）就自动跑。

**Mode D 的接口点**（要注意的）：
- 现在熟练度更新的主入口是 `score_answer`，而它内部调 **Gemini** 评分（地理封锁，且我们要用 Claude Code 订阅评分）。
- 所以 Mode D 检验白板的正解：**Claude Code 用订阅算出 grade(1-4) → 调 `update_bkt` + `update_fsrs`（这俩纯数据、不碰 Gemini）喂回熟练度系统**。这恰好就是 PRD §1.5 第 2、3 步描述的流程，也"复活"了那两个半死的工具。
- 结果：检验白板评分 → 熟练度演化 → 写 mastery_level + 自动算出"下次该考这个节点的时机" → 下次 Dashboard（Dataview）就提示你复习它。**完整闭环。**

## 六、两个要你知道的留白（PRD 没拍死的）

1. **5 信号融合的精确公式 PRD 没给死**：PRD 只说"后端算法计算"，决策 D9 选了"FSRS 复习时机为主导"的方向；代码现在用 0.30/0.25/0.20/0.15/0.10 的加权平均。**这个权重是可调的**——以后你用着觉得某个信号该多算点，能改。
2. **BKT↔FSRS 的数学衔接**是自定义映射（grade 1-4 → BKT 的对错 + FSRS 的 Again/Hard/Good/Easy），社区无标准参考，代码用了 `难度 d = 1 - 掌握概率` 这类起点。能用，但属于"可调优"区。

## 七、连起来看（你的完整学习闭环）
```
原白板剖析（打批注/拉双链/对话）
  → 个人记忆（Graphiti 存批注/原因）          ← 我刚做的 P0-P5 把这段打通且脱离 Gemini
  → 检验白板：FSRS 挑到期+薄弱节点 → Claude Code 订阅出题(引用你批注) → 你手写答
  → Claude Code 订阅静默评分 → update_bkt/update_fsrs → 熟练度演化 → Dashboard 反馈 + 算下次时机
  → Dashboard 提示"该复习这些弱点" → 又去原白板剖析 / 再开检验白板
```
熟练度是这个闭环的"度量衡 + 节拍器"：度量你掌握到哪，定下次什么时候再考你。
