# 面 2「信息收集场景」— 需求澄清定案

> **⛔ 引用纪律**：本文档里带引号的都是用户 2026-08-15 的**逐字原话**，不得转述走样。
> 我方推导出的结论一律标「⇒ 推导」，与用户原话区分开。

---

## 一、用户逐字回答（4 问）

### A. 这是哪类收集任务？

> 「**一个是深度学习某一门学科，另外一个则是快速搜集信息调研，通过时不时的回顾，让我和 ai 都不会对研究内容过于偏移**」

⇒ 推导（三条，都会改变设计）：

1. **两类任务并存，不是二选一**。系统要同时承载「深度学习某学科」（= 现有 CLS）与「快速搜集信息调研」（= 新场景）。
2. **既不是纯决策型也不是纯学科探索型，是「调研型」** —— ChatGPT 给的二分（decision-research vs 学科探索）不完全适用。「快速」二字是关键定语：追求的是**在有限时间内把一个话题搞清楚**，不必然有 lock-in 日，也不追求学科级的覆盖完整性。
3. ⭐ **防偏离的对象是双向的：「让我和 ai 都不会」** —— 此前我方与 ChatGPT 的全部分析都默认「偏离」是用户在拆解时跑偏。**AI 也会偏，而且有铁证**：参照 vault 的 CLAUDE.md「第 0 步」正是因为 **AI 一天内连犯三个方向性错误**（把备选目标当主线 / 把已闭环问题当新盲点重开并派 agent 去查 / 给出与顶层目标反向的建议）才被事故驱动写进去的。

### B. 上次那份四层验收表，为什么填到一半就停？

> 「**填了也没帮到我**」

⇒ 推导（这一条否定了一个看似合理的方向）：

- 失败**不是**「字段太多、成本太高」 ⇒ **「减字段、换更轻的表」这条路是错的**。减到 5 行照样不填。
- 失败**是**「输出没价值」 ⇒ **新设计必须先证明回顾能产出可行动的东西，再谈要不要用户写字。**
- ⚠️ 对照 ChatGPT 的判断：它猜的四个原因里，「字段太多」「入口不自然」「忘了用」三个都被用户排除了。

### C. 回顾用什么形态？

> 「**我觉得搜集信息的时候，使用的不是我们原来的检验白板，而是设计了新的 skill，对抗性审查后给我生成了摘要，从而我自己评价我当前记得以及相关忘记的内容**」

拆成四段（用户原话的结构）：
1. **不用**原来的检验白板
2. 设计**新的 skill**
3. AI 做**对抗性审查** → **生成摘要**
4. 用户看摘要后**自己评价**「我当前记得以及相关忘记的内容」

### D. 对抗性审查具体审什么？（多选，用户选了 3 项）

| 选中 | 审查维度 |
|---|---|
| ✅ | **审有没有漏掉的** —— 这个话题应该搞清楚的事里，有哪几件根本还没碰过 |
| ✅ | **审我收集的内容本身靠不靠谱** —— 哪些是实测 / 哪些只是传言 / 哪些互相矛盾 / 哪些已过期 |
| ✅ | **审方向有没有偏** —— 我和 AI 这一阶段挖的东西，跟最初要搞清楚的事还是一回事吗 |
| ❌ **未选** | ~~审我的理解对不对~~（「你以为 X，但资料里写的是 Y」式反驳） |

⇒ 推导（这条排除是本次澄清最有价值的信息）：

**新 skill 审的是「材料」，不是「人」。**
- 现有检验白板：审**人**（Karpicke 主动回忆，把答案藏起来考用户）
- 新 skill：审**材料**（覆盖度 / 可信度 / 方向），把审查结果给用户看
- 自评那一步是用户**看完摘要后自己做的**，不是被考出来的

⇒ **断言 H 彻底不成立** —— 此前 ChatGPT 判「语义不可复用、壳可复用」，现在更进一步：**连审查对象都不同**。

## 二、由此确定的设计约束

### 必须满足

| # | 约束 | 来源 |
|---|---|---|
| R1 | 回顾产物**必须先产出可行动的东西**，在此之前不要求用户填任何字 | B「填了也没帮到我」 |
| R2 | 防偏离**同时管住用户与 AI 两端** | A「让我和 ai 都不会」 |
| R3 | 对抗审查覆盖三维：**缺口 / 可信度 / 方向** | D |
| R4 | ⛔ **不做**「你以为 X 但资料是 Y」式的反驳考察 | D 未选项 |
| R5 | 自评是用户看完摘要后的自主动作，**不是系统出题考出来的** | C「我自己评价」 |
| R6 | 新 skill，**不复用 start-exam-board** | C「不是我们原来的检验白板」 |
| R7 | 先在现有 vault 内试点，不动部署 | E |
| R8 | 「快速」是硬指标 —— 调研型不追求学科级覆盖完整性 | A「快速搜集信息调研」 |

### 已由历史证据确定（不必再问用户，见 22 问挖掘文档）

| 项 | 定案 |
|---|---|
| 回顾单位 | 我的问题 + 我的回答 + 进度（**不是来源清单**） |
| 来源证据字段 | 用户自定的强制 7 字段（`url_primary` / `url_wayback` / `accessed_date` / `info_type` / `sample_size` / `tier` / `fit_score`） |
| 可信度标注 | 三档【实测】/【文件】/【未确认】 |
| 矛盾处理 | 固定章节 + `甲方 \| 乙方 \| 后果差多少 \| 谁能裁` 表 + 跨轮次追踪状态 |
| archive 语义 | 移目录 + 改 status + 退出活跃队列 + **永不物理删除、永远可搜**；reopen 三步已成文 |
| 自动化边界 | AI 只提名，用户 accept 才入权威区；**可以**自动做时间驱动的过期归档（30 天） |
| 确认预算 | 队列式、异步、可批量、带超时默认。**不可**每事件同步阻塞确认 |
| 典型规模 | 1 个主项目 ≈ 500 md / 4 个月 / ~100 轮；同 vault 内并行 3-5 条子线 |
| 派生理由 | 已在做且用户最看重（Cmd+Shift+D 强制关系 modal + 自由文本理由，实测 7/8 有内容） |

## 三、与 ChatGPT 裁定的差异（它没料到的部分）

| ChatGPT 的判断 | 用户实际回答 | 差异 |

## 三·五、第 2 轮补充定义（2026-08-15 晚，用户逐字）

> 「这个 skill 的使用场景，主要是在 `/Users/Heishing/Desktop/转学规划` 这种**调研收集信息**的 vault，
> 这样我在把 Canvas learning system 部署到这个 vault 使用时候，我就使用**原白板把各个调研白板引入为节点**，
> 然后**不断打批注**，或者**引入新的材料作为节点**，然后我一旦原白板拆分时间长了，
> 我则需要**准确无误知道我在这个原白板做了什么事**，
> 如果用检验白板来进行考察的话**太耗时间**，
> 所以我需要你**结合社区成熟的设计**，
> 我是要**快速不遗漏**的回顾起我到底收集了什么信息，
> **检验白板是在深度做文章，而我这里则是考察了广度**，让我能**成熟的了解当局的情况**。」

### ⭐ 最锋利的一句：深度 vs 广度

这比前几轮所有分界线表述都更根本：

| | 检验白板 | 广度回顾 skill |
|---|---|---|
| 做什么文章 | **深度** | **广度** |
| 对象 | 少数节点，深入考察 | 全部内容，快速盘点 |
| 成本 | **太耗时间**（用户排除它的直接理由） | 快速 |
| 目的 | 检验学习能力 | 不遗漏地知道收集了什么 + 了解当局情况 |
| 理论锚 | Karpicke 主动回忆 d=1.50 | ⏳ 待调研（候选：MOC survey 层 / scoping review / Situational Awareness 三层模型） |

⇒ **不是「检验白板的简化版」，是同一套 vault 上的另一层视图** —— 深度层已有（Atlas/Notes），广度层缺失（Atlas/Maps 的 review 机制）。

### 两个用法（一个是新的，一个是我没查就说成新的）
**User：我自己把 相关材料收编到原白板作为节点来进行讨论和批注，我们有过把相关材料内容收编作为节点进行讨论的设计，然后这个节点也是可以作为进一步细分讨论的设计而使用**

> **[R2-Q1 → 已回复 · 2026-08-15]** 你是对的，我错了，下面这段「用法 B」原本写着「现有 skill 支不支持待实测」——**没查就写**。实测三条：
> **① 收编设计早就存在且用过 4 次**：`configure-whiteboard` 的**场景 B** 专门做这件事，带 move/copy 选择、节点池重名保护、反向引用检测，还支持**追加**种子到现有白板。真实记录：`递归与分治:111`(04-30 my-recursion-notes) · `特征值与特征向量:197-198`(05-01 Fundamentals，还是从 `wiki/canvases/math140/` **迁移**过来的) · `CS188 lecture 2:120`(05-09 lecture 2)。
> **② 「进一步细分」架构上支持**：`ai-linked-doc` 的引导范式是「active file 在 `节点/` 下 → 读 `source_board`」，即在节点里选中文本可以再派生。
> **③ 但二级细分从未被使用过**：全 vault 9 条 `derived-from` **全部指向种子节点**（`lecture 2`×7、`Fundamentals`×2），**零条派生自派生**。⇒ 现在的拆分形态是**扁平星形**（都挂在种子上），不是树。
> **④ 对广度回顾的影响**：如果你在调研 vault 里真的开始二级细分，拆分过程会从星形变成树 —— 「不遗漏地回顾」就要处理**层级**，而不只是列一张平表。这一条会进方案设计。
>
> ⚠️ 这是我今天**第三次**搞错现有系统能力（前两次：说 `derived_at` 缺失导致算不出时序、说不复用检验白板）。三次都是你纠正的。模式很清楚：**我对这个系统已有能力的了解不如你**，所以凡涉及「现有支不支持」的判断，我应当先查再写，而不是先写再标「待实测」。

**用法 A（确实是新的）：原白板把「各个调研白板」引入为节点 —— 出现了二级层次**

现有 CLS 的假设是「原白板 → 节点（概念）」。这里是：
```
原白板（索引层 / MOC of MOCs）
  └─ 节点 = 一整块调研白板
        └─ 该调研白板自己的节点 = 材料 / 概念
```
⇒ **节点可以指向另一块白板**，而不只是概念。现有 `source_board` 是单向「我属于哪块板」，没有「我代表哪块板」的语义。

**用法 B（⛔ 更正：不是新的，是已上线功能）：收编材料为节点**

~~现有 `Cmd+Shift+D` 只支持从选中文本派生，收编是新入口，待实测。~~ ← **这句是错的，已作废**

**实况**：`configure-whiteboard` **场景 B** 就是收编入口，已上线并真实使用 4 次。

| 能力 | 状态 | 出处 |
|---|---|---|
| 把任意位置的 md 收编为白板种子节点 | ✅ 已上线 | `configure-whiteboard/SKILL.md:91` 自动降级场景 B；Step 6 种子笔记归类 |
| move（原位删除）/ copy（保留副本）二选一 | ✅ 有 | SKILL.md:235-244 |
| 追加种子到**已有**白板（一板多材料） | ✅ 有 | SKILL.md:139「追加种子笔记到现有白板的 `## Concepts` section（仅场景 B）」、:204 选项 A |
| 节点池重名保护 | ✅ 有 | SKILL.md:237-239 |
| 反向引用检测（防重复建板） | ✅ 有 | SKILL.md:145，源于用户 2026-04-30 的实际踩坑批注 |
| 种子节点可再派生（一级细分） | ✅ 已上线且在用 | CS188：`lecture 2` → 7 个节点 |
| **派生节点再派生（二级细分）** | ⚠️ **架构支持，零使用记录** | `main.ts:603` 引导范式允许；但 9 条 `derived-from` 全指向种子 |

⇒ **用法 B 对广度回顾的真正意义不是「要新建能力」，而是「回顾时必须区分两类节点」**：
- **种子节点**（收编来的材料）—— 它代表一份外部输入，回顾时问的是「这份材料我消化了没有」
- **派生节点**（从材料里拆出来的）—— 回顾时问的是「这个点我搞懂了没有」

现有数据里两者混在同一个扁平池，靠 `derived-from` 有无来区分（种子无 `derived-from`）。实测：14 个节点里种子 5 个（`lecture 2`/`Fundamentals`/`my-recursion-notes`/`cs-61b-csm`/`csm-tutoring-unit-credit`）、派生 9 个。
