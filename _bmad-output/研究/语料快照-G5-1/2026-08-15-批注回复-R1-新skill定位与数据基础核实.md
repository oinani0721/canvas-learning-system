# R1-Q1 · 新 skill 的定位与数据基础核实

## 你的批注（逐字，未改动）

> **User：这个新 skill 应该是根据我的原白板的批注和拆分从而让我回顾，和检验白板强制让我输出检验学习能力不同的是，这个则是让我明确知道我今日原白板的拆分过程**

---

## 一、先承认：这条纠正了我的演示方向

我做的演示，素材选的是「**我们今天这次调研**」（全项目对抗审查）。
你要的是「**我今日在原白板上的拆分过程**」。

两者**方向对、素材错**：
- ✅ 方向对 —— 都是「日度回顾」，都是「AI 审材料 → 给摘要 → 我自评」
- ❌ 素材错 —— 我审的是我俩的对话产物，你要审的是**你在 Obsidian 里的派生活动**

讽刺的是：这正是你要防的那种偏移，而且是**我这一侧**的（你要求「让我和 ai 都不会偏移」）。演示本身证明了这个需求真实存在。

---

## 二、你这句话定死了四件事

| # | 定死的内容 | 逐字依据 |
|---|---|---|
| 1 | **数据源 = 原白板的批注 + 拆分** | 「根据我的**原白板的批注和拆分**」 |
| 2 | **时间粒度 = 今日** | 「我**今日**原白板的拆分过程」 |
| 3 | **产出对象 = 拆分过程**（我干了什么），不是知识点 | 「让我明确知道…**拆分过程**」 |
| 4 | **与检验白板的分界线 = 强制输出 vs 明确知道** | 「和检验白板**强制让我输出**检验学习能力**不同的是**，这个则是**让我明确知道**」 |

第 4 条是最锋利的一条。它比我之前总结的「审材料 vs 审人」更准确：

| | 检验白板 | 新 skill |
|---|---|---|
| 动词 | **强制让我输出** | **让我明确知道** |
| 我处于 | 被考的一方（要产出答案） | 被告知的一方（接收结论） |
| 检验的是 | 我的**学习能力** | 我的**拆分过程** |
| 我的负担 | 必须写出东西 | 读完即可 |

⇒ 这也解释了为什么上次那份四层表你「填了也没帮到我」—— **它是「强制让我输出」的形态，但用在了不该考我的场景上**。

## 三、⛔ 实测：你要的这个功能，目前缺时间基础

我去 live vault（`canvas-learning-system/canvas-vault`）逐个节点核实了 frontmatter：

### 核实结果

| 字段 | 覆盖率 | 说明 |
|---|---|---|
| `source_board`（属于哪块原白板） | **14 / 14** ✅ | 完整，可用 |
| `relationships[]`（关系 + 派生理由） | 8 / 14 有关系，7 条带理由 | 可用但稀疏 |
| `created`（创建时间） | **9 / 14** ⚠️ | 且**最新一条停在 2026-07-23**，今天是 08-15 |
| **`derived_at`（派生时间）** | **0 / 14** ⛔ | **一个都没有** |

⚠️ 顺带更正我自己：我在现状核实文档里写「全 vault 仅 2 个节点带 `derived_at`」—— **也是错的，实测是 0 个**。

### 为什么这是硬障碍

「**今日**的拆分过程」需要一个可靠的「这个节点是什么时候派生的」。目前三条路都不通：

| 路径 | 为什么不通 |
|---|---|
| `derived_at` 字段 | **不存在**。插件源码里 grep 不到任何写 `derived_at` 的地方（只写 `source_board` / `relationships` / `source_note`） |
| 文件 mtime | **会被污染**。例：`Characteristic-Equation` 的 `created` 是 04-30，但 mtime 是 **08-11** —— 后续任何一次编辑都会刷新它，分不清「今天派生的」和「今天顺手改了一下的」 |
| git 历史 | **覆盖不到**。`git ls-files canvas-vault/节点/` = **3**，14 个节点里只有 3 个入了 git |

⇒ **今天在原白板上拆了什么，系统目前答不出来。**

## 四、解决路径（成本从低到高）

### 路径 A · 插件派生时补写 `derived_at`（推荐先做）

在 `Cmd+Shift+D` 派生节点的那段逻辑里，往 frontmatter 多写一个 ISO 时间戳。

- 成本：一行字段 + 一处写入
- 收益：**从明天起，「今日拆分过程」就能精确算出来**
- 局限：**救不了历史的 14 个节点**

### 路径 B · 历史节点的时间用 `created` 兜底 + 明确标注

对已有的 9 个有 `created` 的节点用它；剩下 5 个标「时间未知」。

- 成本：纯读取逻辑
- 局限：`created` 与 `derived_at` 语义不完全等价（一个是文件建立，一个是派生动作），且最新只到 07-23

### 路径 C · 批注侧的时间戳

「今日的**批注**」同样需要时间。当前 `Cmd+Shift+A` 写的 callout 是否带时间戳，我还没核实 —— 这是下一步要查的。

## 六、我需要你再确认一点

「**今日**」这个粒度，是指：

- (a) **自然日** —— 每天固定一份「今天你拆了什么」
- (b) **一次学习会话** —— 我坐下来学一段，结束时回顾这一段（可能一天多次，也可能跨天）
- (c) **按白板** —— 我在某块原白板上工作告一段落时，回顾这块板的拆分

这决定了触发方式（每日定时推送 / 会话结束触发 / 手动对某块板调用），也决定了要不要 `derived_at` 之外再记一个「会话 ID」。
