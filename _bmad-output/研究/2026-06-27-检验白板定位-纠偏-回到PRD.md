### 2. 它和原白板是对称的一对 —— 一个"信息可见/剖析"，一个"信息隐形/回忆"

你的审查任务书（`审查/2026-05-27-原白板检验白板-设计审查-任务书.md:20-26`）：

所以检验白板**不是**"快速考察那种打开节点就考一道题"。它是一个**独立的、信息全隐形的白板**。

## 三、降级版架构：Obsidian + Claudian（确认我理解对了）

你强调降级版用 Obsidian + Claudian。三方分工（`planning-artifacts/architecture.md`）：
- **Obsidian** = 本地笔记编辑器（你打批注、写答案、看节点颜色的地方）
- **Claudian** = Claude Code 侧栏（**用你的订阅额度**跑 AI：对话、出题、评分，经 MCP 调后端工具）
- **FastAPI 后端** = 算法权威（BKT/FSRS 选题、AutoSCORE 评分、Neo4j/Graphiti 记忆）

检验白板在这个架构里**本该这样跑**（锚定 PRD §2 的 10 步）：
> Claudian 的 Skill（如 /start_exam_board）→ MCP `generate_question`（后端按你的记忆选薄弱节点 + 组装出题上下文）→ Claudian 把题目 callout 写进 `检验白板/*.md` → 你在 Obsidian 编辑器"答："下手写 → Cmd+Option+S 触发 /quiz_answer → MCP `score_answer` 静默评分 → 节点颜色变。

这正好接上你前面问的「为什么不能用 claude code」：**检验白板的出题本来就该由 Claudian（Claude Code，你的订阅）承担**——这是 Mode D。现在那个"快速考察"绕过了 Claudian、让后端直接调 Gemini，既不是检验白板、也没用你的订阅。
