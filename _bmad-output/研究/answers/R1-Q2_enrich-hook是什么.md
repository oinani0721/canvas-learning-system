# R1-Q2 · enrich-hook auto-RAG 功能解释

## 批注位置

`_bmad-output/研究/2026-07-12-全景状态报告-PRD对照-Graphiti实证-对抗审查.md:195`（§9-Q2）

## 批注原文

> **User：** enrich-hook auto-RAG 请你解释一下这个是什么功能设计出来是干什么的，

## 一句话核心结论

它是**你自己在 2026-05-09 提出的需求**：「对话过程中天然有很多次相关知识点返回，**不要每次按快捷键**」——于是做了一个自动机关：你在 Claudian 里每发一条消息，系统就自动去你的笔记库里搜相关片段、悄悄塞给 Claude，让它回答时能引用你的真实笔记（带可点击的 `[[wikilink]]`）而不是凭训练数据编。

## 深度解释

### 它解决什么问题（设计初衷）

在它出现之前，想让 Claude「看到你的笔记」只有两条路：按快捷键手动触发检索，或者 Claude 自己决定调 MCP 搜索工具。你当时的反馈是对话里相关知识点出现得太频繁，每次手动触发太麻烦。所以 Story 2.2 Phase A（2026-05-09）用了 Claude Code 官方的 **UserPromptSubmit hook** 机制（Anthropic 钦定模式）做成全自动。

### 它是怎么工作的（4 步，全程你无感知）

1. **你在 Claudian 发任何消息**（比如「eigenvalue 是什么」）
2. vault 的 `.claude/settings.json` 里注册的 hook 拦截这条消息，把它 curl 给后端 `/api/v1/chat/rag/enrich-hook`（带鉴权 key）
3. 后端拿你的问题去 **LanceDB 笔记索引**（bge-m3 语义 + 中文分词全文两路混合）搜出最相关的笔记片段
4. 搜到的片段包装成 `<supplementary_materials>` 块**注入到 Claude 的上下文最前面**，并附一条指令：「回答前必须真的去 Read 这几个文件核实、正文必须带 `[[文件#标题]]` 精确跳转链接、禁止凭训练数据回答 vault 里有的内容」

理想效果：你问「特征值怎么求」，Claude 的回答里自然出现 `[[节点/Characteristic-Equation-for-Eigenvalues#...]]`，点一下直接跳到你自己的笔记。

### 为什么它现在成了问题（本次对抗审查的两个发现）

**问题一（R1·CRITICAL）——"相关"的过滤器坏了。** 设计上有个分数门槛（不够相关的片段不注入，"0 命中就不打扰"）。但检索分数经过三层数学变换后被压缩到 0.45~0.51 的极窄区间——**任何东西都能过门槛**。真机实验：问「怎么烤酸面包」（和你笔记零相关）照样注入 10 条材料。也就是说它现在是「每条消息无差别塞 5KB 笔记片段」，你之前看到的「递归笔记 0.508 分」其实是这个坏掉的体系里的**最高分**。

**问题二（R2·HIGH）——它不分场合。** 它拦截**一切**消息，包括 `/start-exam-board` 出题指令。于是出题的那一轮，Claude 的上下文被塞进了**被考节点的定义原文** + 一条「必须去 Read 完整文件」的指令——和检验白板「出题绝不读定义正文」的信息隔离铁律（d=1.50 的命脉）正面打架。等于监考老师进考场前被人往兜里塞了答案册。

### §9-Q2 三个方案的通俗含义

| 方案 | 做什么 | 效果 |
|---|---|---|
| A | 修好分数过滤 + 出题指令跳过注入，**保留自动机关** | 保住"不用按快捷键"的初衷，修复成本中等（分数归一化要动检索链） |
| B | 降级成"只有**全文精确命中**你笔记关键词才注入"（语义弱匹配不再触发） | 注入次数大减但每次都真相关；实现简单；牺牲一些语义联想能力 |
| C | 暂时**关掉**自动机关，需要时让 Claude 自己调 MCP 搜索 | 立刻止血两个问题；但回到"看 Claude 自觉"，你的原始痛点（太频繁手动）回来一半 |

**我的推荐**: 短期 **A 的止血半份 + B 的思路**——先做两个一行修复（出题指令跳过注入 = 救回隔离铁律；分数门槛临时提高/FTS 强命中才注入 = 止住垃圾注入），保留机关本身。等基本功能收敛后再回头做完整的分数归一化。这样你的初衷（自动、免快捷键）不丢，两个破口先堵上。
