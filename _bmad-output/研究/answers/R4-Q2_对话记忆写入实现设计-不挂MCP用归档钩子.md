# R4-Q2 · 对话记忆写入实现设计

## 批注原文

> **User：那么关于这一点你打算怎么实现，你这个相当于挂了一个 Graphiti MCP 来随时的进行写入吗？**

## 一句话核心结论

**不是**。官方 Graphiti MCP 确实存在（13 个工具很齐全），但把它挂给 Claudian「随时写入」有两个机制级缺陷——写入时机靠 Claude 自觉（聊得越投入越容易忘记调工具，违反「记忆写入要确定性」铁律），且它的分组参数每次调用可被任意覆盖（源码实证），我们精心设计的影子图隔离在它面前锁不住。真正的实现是「**下课铃一响教室自动录音归档**」：一个会话收尾钩子（机器自动触发，Claude 想忘都忘不掉）把对话记录送进后端确定性管道——蒸馏、写进哪个图全由服务端代码写死。

## 一 · 三种做法的对比（打比方版）

| 做法 | 比方 | 判定 |
|---|---|---|
| A · 挂官方 Graphiti MCP 随时写 | **指望学生自觉交作业，且交到哪个班的作业筐还归学生自己挑** — 时机靠 LLM 自觉必漏记；group 参数可被覆盖 → 影子图隔离失守、主图污染无防护；还会在同一个 Neo4j 上多出第二套互不知情的写入栈，绕过后端全部防护（注入扫描/失败重放/统一分组） | ⛔ 不用于学习记忆 |
| **B · 归档钩子 + 后端管道** ⭐ | **下课铃一响教室自动录音归档** — 铃是机器打的（钩子），归档蒸馏入哪个图由后端代码决定，Claude 无权也无需插手 | ✅ 主干 |
| C · 自家 MCP 显式记忆工具 | **课堂上老师随手记下学生的精彩瞬间** — 写入管道确定性（走后端），但触发靠 Claude 判断，只适合捕捉高光时刻（如当场发现你一个误解），扛不起全量归档 | ✅ 补充（已存在，需修缮） |

## 二 · 推荐实现（B 主干 + C 补充）的完整设计

**一个惊喜发现**：后端的「归档→蒸馏→入图」流水线**大半已经建好**——三层归档（热=30 天全文 / 温=蒸馏出摘要+知识点+错误 / 冷=只留结构化）、本地模型三级降级蒸馏、24 小时定时调度、手动触发端点全都在。**唯一断点**：Claudian 的对话记录到不了后端（它只会搜后端自己的记忆库）。
**User：我们把 claudian 改为 claude code 来使用会不会更好，更成熟，我们改为 Canvas learning systeam 用于 obsidian 加 claude code** 

> **[A5 2026-07-13 → round5]** ✅ 会更好，你的判断被三路调研实锤支持：你的全部资产（skill/钩子/配置）本来就是标准 Claude Code 格式，Claudian 只是第三方壳——切换必做工作仅一个配置文件搬家（5 分钟）。关键实锤：会话归档钩子在 Claudian 里结构性不可靠（源码取证 SessionEnd 零支持 + 关会话 3 秒强杀），原生官方保证每会话恰好触发一次——所以「换 Claude Code」实质是 Phase 2 记忆管道的前置条件，两个决定互相成全。Claudian 不必卸载（降级可选侧栏）。四步落地 ~1 小时 + 两周试用。详见 [[R5-Q1_Claudian换ClaudeCode原生-调研裁决与迁移设计|📚 R5-Q1]]

**补断点的关键件 · 会话收尾钩子**：你的 vault 里已经有一个成功先例（每次发消息自动触发检索注入的那个钩子）——照同样模式加一个**会话结束钩子**：触发时自带完整对话记录路径 → POST 到新的后端归档端点（带鉴权）→ 后端排队蒸馏 → 产物由**服务端代码固定写入影子图**（`vault:canvas_vault:semantic`）。

**三层触发保险**：
1. 钩子自动归档（主干——每次对话结束，机器触发，确定性）
2. 现有 24 小时调度（兜底——钩子万一没打到，第二天补上）
3. 手动触发命令（应急）

**双图隔离的落点（回应你对"随时写入"的隐忧）**：任何经过 LLM 抽取的内容，分组由后端代码**写死**为影子图；MCP 工具和钩子端点都**不暴露分组参数**给调用方。即使 Claude 出错、提示词被污染，也没有任何通路能让 LLM 抽取物碰到你的记忆主图——这是机制保证，不是靠 AI 听话。

**C 的修缮**：已存在的两个显式工具（对话中记误解、交对话摘要）保留作补充，但要修一个 bug——它们目前把分组硬编码到公共桶（越 vault，与 B2 修复同族问题）。

## 三 · 改动清单与工作量

6 处文件（5 后端 + 1 vault 配置），全部沿现有模式扩展、零新组件，**约 1 人天**——与 R3-Q1 路线图 Phase 2 完全吻合，不增加总工作量。开工前唯一要实测的（半小时）：会话结束钩子在 Claudian 内嵌环境是否触发；若不触发，退路是插件侧会话关闭时调同一端点（端点设计不变）。
