# R1-Q4 · 三机制运作解释

> **User：请你给我解释一下以上你所设置的3. 提交评分；5. 错误候选处理；6. Quick Exam 旁路及其后端 LLM 出题是怎么运作的，请你给我解释一下**

## 一句话核心结论

三个机制分别是：**正式考试的静默阅卷员**（/quiz-answer，你的 Claude 订阅当评分引擎，分数悄悄记账不当场亮分）、**错题本的守门员**（AI 只能提名错误、你亲自批准才算数）、**课间小测验**（Quick Exam，后端 Gemini 出题+即时反馈，只练手不记账）。

## 机制一 · 提交评分 `/quiz-answer` — 正式考试的静默阅卷员

**评分引擎是谁**：你的 Claude 订阅（Claudian 里的 Claude 本身），**不调后端、不花 API 钱**。这是你拍板的「本地 EMA 主轨」（R1-Q3 决策）。

**你输入 `/quiz-answer` 后，它按五步走**：

1. **防重复守卫** — 先看这张检验白板的状态标记：已评过分就整体跳过（防止重复评分把掌握度重复演化）；上次中断的能从断点续跑
2. **提取你的答案** — 只取答题区标记之间你手写的内容；如果你考试中途用 Cmd+Shift+D 拉过疑问节点，那些系统生成的文字会被剥掉，不混进评分
3. **静默 4 维评分** — Claude 按固定量表打分（准确性/完整性/深度/清晰度四个维度），分数**只写进检验白板文件的属性区，绝不在对话里告诉你**——这是 HARD-SILENT 铁律：延迟反馈比即时反馈更利于长期记忆（测试效应研究的结论）
4. **掌握度记账** — 一段固定的小程序（不是 AI，是确定性代码，昨天刚修了三个数据缺陷）把分数按「新旧加权平均」公式更新到被考节点的 `mastery_score`：新掌握度 = 旧值 + 0.5 ×（本次得分 − 旧值）。这就是 Dashboard 上掌握度变化的唯一正式来源
5. **疑问归纳** — 你答题时暴露的新疑问被写回原节点，变成一条带跳转链接的批注，下次考察会带上它

**你唯一看到的**：一条"已静默评分并落定"的回执。想看分数去 Dashboard（延迟反馈是有意设计）。

## 机制二 · 错误候选处理 — 错题本的守门员（D15 用户主权设计）

**设计哲学**：AI 无权直接给你定错误。它只能把"我怀疑你搞混了 X 和 Y"写进**草稿区**（节点属性里的 error_candidates 列表），必须**你亲自批准**才进正式错题本。

**完整流水线三段**：

1. **生产（AI 提名）** — 设计上：你和 AI 对话后，系统自动分析对话、提取疑似误解写进草稿区。⚠️ **这一段的自动管道当前断裂**（全景报告 B4，触发时机待设计）——所以你现在测试时草稿区里只有一条我们手造的测试候选
2. **确认（你拍板）** — Cmd+P →「接受错误候选」：列出当前文件的待处理候选 → 你选一条 → 它被移入正式错题本（errors[]）**并同步进 Graphiti 图谱**，未来考察这个概念或相邻概念时，出题会引用"你曾在这里犯过 X 错"。选「异议错误候选」则相反：你写一句理由，它被标为"AI 判错了"，永不进错题本（你的理由会留着改进 AI 的判断）
3. **过期清理** — 30 天不处理的候选自动标过期，不会永远堆着等你

**为什么这样设计**：错题记录直接影响出题方向（针对性考察的燃料）。如果 AI 自说自话记错误，一次误判会让系统反复考你根本没搞错的东西——所以守门权在你手里。

## 机制三 · Quick Exam 旁路 + 后端 LLM 出题 — 课间小测验

**和检验白板的分工**：检验白板 = 正式测试（静默评分、写掌握度、进考察历史）；Quick Exam = **快速练手**（即时反馈、**不写掌握度**、不进正式记录）。想快速自测一个概念时用它，不想走完整考试流程。

**出题半环**（Cmd+P →「Quick Exam」触发）：

1. 插件把当前节点名发给后端
2. 后端**只读**这个节点的批注和错误记录（信息隔离：不读你的定义正文，防止出送分题）
3. 后端通过 litellm 调 **Gemini** 模型，围绕你的批注生成 1 道针对题——⚠️ 这条链在 7-12 之前一直是坏的（配置错误导致永远退化成"请用自己的话解释"模板题），修复后你会看到真正针对你批注的问题（例如上次真机测试它出了"构造一个二维矩阵使特征值为负"这种题）
   **User: 我们现在全职不是都没有用 Gemini 吗？我们考察的时候都是用 claude code ，那么至于我们 Graphiti 本身需要使用配布的模型，是否可以使用 claude code ，还是我们使用本地模型来执行**

   > **[A2 2026-07-13 → round2]** ✅ 你的直觉基本对：考察主链 100% 走你的订阅；全栈真正花 Gemini 钱的只有这个手动触发的 Quick Exam 角落（实测总花费 $0.0007，免费额度内）；Graphiti 的 Gemini 是零调用的挂名依赖。⛔ 换 Claude Code **订阅**不可行（官方封禁后端代持，铁律 5）；换本地模型可行且检索向量早已本地化（你的 Ollama bge-m3），但两个场景 3-agent 调研后都推荐保持现状、退路已备好（详见文档内三方案对比）。详见 [[R2-Q1_全栈模型使用现状与Graphiti换模型可行性|📚 R2-Q1]]

4. 
5. 题目写进 `节点/考察-{概念}-{日期}.md` 并自动打开

**评分半环**（你答完 **Cmd+S 保存**即触发，无需任何命令）：

1. 插件监听到考察文件被保存 → 提取"## 你的回答"下你写的内容（占位符没改就不触发）
2. 发给后端 → Gemini 按量表评 1-5 分 + 写针对性反馈
3. 分数和反馈**直接追加在文件底部**——这里是**即时显示**的，和检验白板的静默评分相反，因为练习题的目标是快速纠错，正式测试的目标是准确测量

⚠️ 已知缺陷提醒：评分监听只在内存里——如果你出题后**重启了 Obsidian** 再答题，保存不会触发评分（手册 §四已标注，遇到别当 bug，重新出一题即可）。
