## 3. 务实推荐：A+ 中间路线

### 核心洞察（为什么不必上纯 E）
边 uuid 已经是**确定性 content-hash**（`graphiti_structured_writer.py:35-41` `uuid5(类型:节点:group:内容hash)`）。这意味着**不需要稳定 block-id，也能做"create-or-preserve"**：同内容重跑 → 同 uuid → 可检测"边已存在"→ 保留其 `created_at/valid_at` 不覆写。A4 因此可用一个**小改动**解决，不需要 E 的稳定身份基础设施。

更深一层张力（必须让 ChatGPT 评判）：content-hash uuid 天然给出"每个不同内容 = 一条持久边" — 这**正是**用户想要的累积/时光机模型（旧版本带旧时间戳持久存在）。而我之前的 F10 去重（首行身份→合并版本）是为了"不给出题 LLM 喂重复噪声"。**两者方向相反**：累积要"版本都留"，去重要"只留最新干净版"。务实裁决取决于出题到底要"最新干净版"还是"完整演化史"。

### A+ 的四件事
1. **X1 派生实时化（治 X1）**: 前端 `runHybridDerivation`(main.ts:1313 Notice前) 加 POST → 后端 `record_knowledge_entity` 加 relation 分支 → `write_relation_reason`（Graphiti-native，保 reason，**不走** sync.py 那个写 CANVAS_EDGE 的 G-FAKE endpoint）。复用批注已验证的实时路由对称结构。
2. **A4 create-or-preserve（治 A4，小改动）**: 回填/写入前查边是否已存在（uuid 确定性），存在则**保留** `created_at/valid_at`，只在缺失时按真实时间插入。派生时间用 frontmatter `created_at`（已有，实测 `代理函数` 节点带 `2026-06-11T21:28:04.351Z`）；批注暂用 file mtime 兜底（callout 模板无逐条时间）。
3. **A7 诚实失败（治 A7，横切）**: `record_knowledge_entity` 检查 enqueue/write 返回值，失败落 outbox（复用 `FAILED_WRITES_FILE`，需扩展 `recover_failed_writes` 认 callout/relation 格式）+ 前端轻提示非静默。
4. **A2 删除 + 稳定 block-id = 延后**: 用户累积模型几乎不删；删除失效原语已存在（`belief_service.py:179-185` 可复用），等真有需求再做周期性 GC 对账，不做实时。稳定 block-id 同理延后。

## 4. 务实分阶段
- **阶段0（先，横切，低风险）**: A7 诚实失败 + outbox。
- **阶段1（治当前最痛）**: X1 派生实时化 + A4 create-or-preserve。
- **阶段2（按需）**: 若实测出题需要"完整演化史"或用户开始频繁改删 → 再上稳定 block-id + 删除对账（升级到纯 E）。

## 5. 验证方法（针对"读回有边"盲区 — 之前栽过）
1. **实时性**: 打新批注/拉新节点 → **不重启** → 读回有 = 真实时。
2. **时间戳**: 改批注 → 重启 → `created_at` **不变** = A4 真治。
3. **失败**: worker 未就绪时打批注 → 返回非 ok + outbox 有记录 = A7 真治。
4. **删除（若做阶段2）**: 删 callout → 对账 → 边 `invalid_at` 被置。
