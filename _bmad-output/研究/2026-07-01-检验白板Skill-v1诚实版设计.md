## 批注回复(2026-07-01 · 第二轮)

### ① EMA 是什么、有什么用(你 Line 129 的问)

**EMA = 指数移动平均**(Exponential Moving Average),大白话:**每次考完,新的掌握度 = 旧掌握度朝这次的表现"挪一步"**。

- 公式 `new = old + 0.5×(这次表现 - old)`:如果这次比旧值好,掌握度往上挪;差,往下挪;**挪的幅度是差距的一半**(α=0.5)。
- `α=0.5` = 挪多快的旋钮:**越大越信最新一次(反应快但抖)**,越小越平滑(记得久但迟钝)。0.5 是折中。
- `grade 归一化` = 把 4 档分(1/2/3/4)换算成 0-1(1→0,4→1),这样能和 `mastery_score`(0-1)用**同一把尺子**比。
- **作用**:让掌握度**平滑演化**,不会因为一次考砸就清零、一次考好就满分——像"滚动平均分",比"只看最后一次"或"全部平均"都合理。
- **为什么叫"临时"**:真正该用 BKT(贝叶斯掌握概率)+ FSRS(遗忘曲线)演化,但那条管道现在 4 处断裂(§二 B1-B4)。v1 先用 EMA 这个简单规则**占位**,管道修好后 v2 换成真 BKT/FSRS。

### ② HARD-SILENT 裁决是什么(你 Line 131 的问)

**HARD-SILENT = 静默铁律**:检验白板评分后,**分数只写进文件里(frontmatter),不显示给你、不弹通知、md 正文不追加"评分"段**。

- **为什么静默**:检验白板命脉是主动回忆(d=1.50)。答完立刻看到"你 2/4 分"= 即时反馈,会削弱下一次回忆的强度(Bjork 延迟反馈证据)。
- **但审查发现"永久静默 = 零反馈"也不对**(证据说延迟反馈才最利于长期记住)。所以 v1 裁决 = **静默 ≠ 零反馈,是延迟反馈**:
  - 即时分**不显**(保护回忆强度);
  - 反馈**延后给**:v1 只在 Dashboard 显掌握度变化 + 复习建议;"哪里错/为什么"的解释性反馈留 v2(下次开检验白板先回放上次错因)。
- **一句话**:考完不当场对答案,但事后从 Dashboard / 下次回放拿反馈——这更利于长期掌握。

### ② Graphiti "90 天图清理"是什么、会不会清掉重要内容(你 Line 175,已 deep explore 社区)

**结论:你不用担心,重要内容不会被清掉。** 两路核查(我们代码 + Graphiti 官方/社区)都指向同一答案:

**(a) "90 天清理"在我们代码里根本没实现**——只在旧 PRD 提过一句(`prd-annotations-2ae5897.md:111` + tauri 原始 PRD 的"Graph Temporal Compaction"设想),v1 设计里已标 v2 待办。代码里唯一的"90"是 **LLM 成本日志轮转**(`cost_tracker.py:37` `LOG_RETENTION_DAYS=90`),清的是 SQLite 成本表,**跟你的知识图谱毫无关系**。全仓无任何图清理 cron/scheduler 在跑。

**(b) Graphiti 本身不删数据,只打"已过期"标签**(bitemporal 双时间轴)——我们的 belief 服务改批注/关系时,旧边不删,只设 `invalid_at`/`expired_at`/`status=superseded` 后 `save`(`graphiti_belief_service.py:213-227` 是 SET 更新非 DELETE);读取默认 active-only 过滤(`graphiti_memory_reader.py:50`),旧的物理还在图里、可 `get_belief_history` 回溯。官方证实:源码 `edges.py` 四时间戳、论文 arxiv 2501.13956、Zep 博客"invalidated — not deleted"、Neo4j 合作博客。

**(c) 社区证据:你的担忧方向其实反了**——找不到任何"Graphiti 清掉重要内容"的翻车案例;社区反而**嫌它删太少**(数据只增、孤儿节点残留),GitHub issue #864 / #1300 都是在**请求**增加清理能力。而且"90 天"既不是 Graphiti 库默认、也不是 Zep 云默认(Zep 云是"你自己设策略"),**极可能是我们 PRD 自己拍的数**。

**(d) 真删除只有一种**:有人主动写代码调 `remove_episode()` / `delete_by_group_id()`。你不开自动清理、不手动删,它一个字都不动。

**给 v2 的修正**:既然 Graphiti 不删、噪音是"只增",v2 防噪音**不该靠"90 天删除"**(会误删你的历史批注/疑问),而应靠 **active-only 读取 + 相关性排序 + `group_id` 精确限定 vault**,再加 **Neo4j 定期备份**兜底(社区公认唯一真实副作用是图会慢慢变大,备份即可)。

**一句话**:你的批注、疑问、节点历史都是"留档不删"的;Graphiti 天生最自豪的就是"不丢历史"。那个"90 天"是纸面设想,没在跑,将来也建议改成"只标记不物理删"。

**证据**:代码 `cost_tracker.py:37`(唯一的90=成本日志)· `graphiti_belief_service.py:213-227`(invalidate 非 delete)· `graphiti_memory_reader.py:50`(active-only)。社区/官方:源码 edges.py · arxiv.org/html/2501.13956v1 · blog.getzep.com/beyond-static-knowledge-graphs · github.com/getzep/graphiti/issues/864、#1300。
