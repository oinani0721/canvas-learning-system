### 证据 1 · 当前栈是"三源拼接的弗兰肯斯坦"(docker inspect 实测)

| 组件 | 实际来源 |
|---|---|
| backend 代码 | ✅ 本 worktree(feature-obsidian-hybrid-dev) |

→ 同一个栈的代码、笔记、图数据来自三个不同的历史时期目录。这就是"过时设计未收敛"的物理形态,任何"一键部署"都无从谈起。

### 证据 2 · 隔离契约在数据层 0% 兑现(cypher 实测,补审计缺口)

学习数据图(7691)全部 88 个节点的 group_id 分布:
```

```
最近真实 Episodic 写入:**2026-06-10**(审计里"07-07 还在写"是事务文件 mtime,实为引擎内部活动)。

→ **结论**:写侧管道代码虽通,但 vault 身份从未被正确传入——所有 vault 的数据都会塌进同一个 `vault__default` 桶。你的"数据不冲突"目标当前不是 partial,是 **未兑现**;好消息是数据量极小(88 节点),**现在收敛成本最低,推倒重来毫不可惜**。

## 一 · 北极星拆解为 3 个工程不变量

1. **INV-1 一键部署**:`/deploy-vault <课程名>` 一条命令把 CLS 的全部 vault 侧资产(8 skills + plugin + Dashboard + hooks + .canvas-config.yaml)落到任意新 vault,零手工步骤。
2. **INV-2 隔离不变量**:任何写入(Graphiti episode / LanceDB 行 / frontmatter)必须携带真实 `vault_id`;任何读取必须按 vault_id 过滤。违反即测试失败。
3. **INV-3 学习主流程**:原白板剖析(批注/派生/精确检索)+ 检验白板考察(出题/评分/疑问回流)两条 UX 在单 vault 内完整、在多 vault 间互不可见。

**依赖关系:INV-2 是 INV-1 的前提**(隔离不成立,部署越多污染越大);**INV-3 的检索环节依赖 INV-2 的索引修复**。所以计划顺序 = 收敛清理 → 隔离闭环 → 主流程打磨。
