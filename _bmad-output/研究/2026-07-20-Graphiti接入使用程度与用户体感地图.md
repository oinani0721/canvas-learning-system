# Graphiti 接入使用程度 + 用户体感地图（2026-07-20）

> [!info]+ 这份报告怎么读
> 你问「Graphiti 接入用了多少、我用产品时体感能感受到哪些」。三路调查（写侧 / 读侧 / 直接查生产 Neo4j 真数据）交叉合成。核心结论一句话：**管道接入度约 40%，但用户体感接入度只有约 10%——写侧很勤快（你打批注/派生/结束会话都在写图），读侧几乎全断（写进去的东西无处被看见）。** 第二节是你现在就能照做复现的「体感时刻」。

# Graphiti 接入使用程度 + 用户体感地图（最终分析，2026-07-20 实况）

## 一、接入度总判

**写侧：11 条已盘点通道中 8 条实活、2 条半活、1 条空转；另有 8 簇断裂。**
- 实活：A1 批注即时上报（main.ts:1559→tips.py:274→graphiti_structured_writer.py:145）、A2 停笔 3s 回填（main.ts:225-260→tips.py:446）、A3 派生关系原因（main.ts:1428→tips.py:362）、A4 错误候选 accept（candidate_service.py:217→error_writer.py:522）、A5/A6 SessionEnd 双通道归档（memory.py:749 / episode_worker.py:539-590）、A8 启动 vault_backfill（main.py:377）、A9 启动投影同步（main.py:347-352）。
- 半活：A7 语义 fallback（outbox 只进不出，recover_failed_writes 已 deprecated，memory_service.py:2122-2128）、A10 MCP 写工具（通路活但 8 个 vault skill allowed-tools 全只读，无固定触发）。
- 空转：A11 定时归档（数据源 per-node 对话在 Obsidian 部署不存在，conversation_archive.py:496-530）。
- 断裂：B1 蒸馏错误写侧（classify 返回值被丢弃，conversation_distiller.py:~412）、B2 候选生产端点零调用方（chat.py:650）、B3 belief 版本链（EpisodeTask 不传 metadata，memory_service.py:363）、B4 calibration、B6 mastery 事件链、B7 Tauri 遗留簇、B8 JSON fallback 回灌。

**读侧：14 路盘点中仅 2 路活。** ①MCP search_memories（memory_tools.py:164→memory_service.py:1582 双图检索，实测返回 10 条真实 fact）；⑤targeting-material（exam_sessions.py:201→targeting_material_service.py:83-148，实测 200）。1 路活但零 Graphiti 成分（enrich-hook 纯 LanceDB）。其余 11 路：Story 2.3 历史错误提醒双死（方法不存在实测 500 BUG-C7B6C53A + 无调用方）、6-source RAG Graphiti 通道静默恒空（group 格式错配 + 200ms 超时）、profile label 错配恒空（:EntityNode=0 vs :Entity=87）、memory_reader 3/4 零消费、mastery / /memory REST / GET tips / agents-dialog 全悬空。

**库内数据：小，且近半是测试。** 全库 118 节点 / 主图 40 RELATES_TO + 影子图 58 RELATES_TO + 101 MENTIONS。按内容实查，E2E/UAT/开发会话驱动约 55 节点（~47%）；真实用户学习数据约 50-60 节点 = 07-10 种入的 15 个课程概念 + 31 条 SelfAnnotation 批注边 + 07-20 凌晨 1 个完整 CS188 CSP 学习会话链。管道端到端已证实活着（当天归档内容当天可被 search_memories 召回），但真实使用量只有一次完整学习会话的规模。

**诚实的完成度感：管道接入度约 40%（写 8/20 活、读 2/14 活），用户体感接入度约 10%——全系统只有 2 条路径能让用户真实"看到"图谱，其中确定性触发的只有 1 条。** 写侧明显强于读侧：用户日常动作（批注/派生/accept/结束会话）基本都在写图，但写进去的东西几乎无处被看见。

## 二、你现在就能体感到的 Graphiti 时刻（按体感强度排序）

**1. 检验白板引用邻居节点的错误原话（强体感，唯一确定性触发）**
- 操作：Claudian 输入 `/start-exam-board <原白板名>`。
- 看到：检验白板题目中出现 `[NEIGHBOR_ERROR source=<邻居节点名> reason=<增殖原因>]`——"你之前在 A 节点犯过 X 错"。
- Graphiti 给的部分：**投影图**（CanvasNode-[CANVAS_EDGE{label=派生原因}]-，9 节点/7 边实测，A9 启动时从 frontmatter relationships[] MERGE 写入）做邻接遍历，选出邻居后取其 frontmatter errors[]（misconception 优先，P5 泄题防御，targeting_material_service.py:111-121 双侧组过滤）。
- 怎么验证不是普通检索：题目引用的是与当前节点**文本上无关**的邻居节点错误——选一个与目标节点无共享关键词的邻居即可证明是图遍历而非相似度检索；`cypher-shell -a bolt://localhost:7691` 跑 `MATCH (a:CanvasNode)-[e:CANVAS_EDGE]->(b) RETURN a.name,e.label,b.name` 可对上题目里的 source 和 reason。
- 诚实标注：严格说这条走的是 Neo4j 投影图，不经 graphiti_core 语义层——是"图谱体感"而非"graphiti_core 体感"。且弹药有限（7 条边），假节点优雅空回 `{"materials":[],"degraded":false}`。

**2. Claudian 对话召回历史学习事实（可体感，但触发靠 Claude 自觉）**
- 操作：Claudian 里问"回忆一下我上次学了什么 / 我在 CSP 上卡在哪"。
- 看到：MCP 工具调用卡片 search_memories + 回答引用历史 fact 原话。确定性验证：`curl -s -X POST http://localhost:8011/mcp/tools/search_memories -H 'Content-Type: application/json' -d '{"query":"特征值 eigenvalue 在 PCA 中的作用"}'` 实测返回 10 条。
- Graphiti 给的部分：主图（批注/结构化实体）+ 影子图（本地 LLM 抽取的三元组关系）双组同查（memory_service.py:1640-1642）。
- 怎么验证不是普通检索：①返回的是三元组式命题（"0 是 A 的特征值 implies A 的零空间非平凡"），措辞是 LLM 抽取产物，grep vault 全文零命中；②能召回 07-20 CSP 会话内容（forward checking / AC-3），这些只存在于已归档对话、不在任何 vault 笔记里——只能来自图。
- 诚实标注：vault CLAUDE.md（36 行）和所有 skill 均未强制触发，全靠模型自觉；且返回有近重复（同一 PCA 事实 4 种表述）、无 group_id/score 字段。

**3. SessionEnd 归档的延迟体感（隔日经路径 2 兑现）**
- 操作：canvas-vault 里 claude 会话聊满 4 条消息后退出。hook（.claude/settings.json:14-24）触发归档，实测 add_episode 2.9-78s/条；次日问"回忆上次"能召回。当前无任何即时回执，体感完全后置。

## 三、接了但你感受不到的（静默生效类）

1. **A1-A4 写侧本体**：打批注/派生/accept 有 md 层反馈（modal、frontmatter、卡片），但 Graphiti 写入是 fire-and-forget 零回执，且专用读器几乎全断——写了 40 条主图边，只有 search_memories 泛化检索兜着。可见化价值：中。plugin 状态栏加"本 session 入图 N 条"计数成本低，能建立信任；但优先级低于修读侧。
2. **A6 影子图抽取**：本地 Qwen 默默抽出 ~30 种谓词（PrerequisiteRelation、IMPLIES、HAS_EIGENVALUE…），全靠 search_memories 才可见。可见化价值：高且便宜——session-end hook 已存在，归档完成后 stdout 打印"归档完成：抽取 N 实体 M 关系"是几行改动。
3. **A8/A9 启动同步**：幂等重放保证图与 frontmatter 一致，重启无感。不值得可见化，log 足够。
4. **反向错觉（enrich-hook auto-RAG）**：用户每次提问看到的 supplementary 注入是纯 LanceDB（supplementary_search_service.py 中 "graphiti" 出现 0 次），容易把它误记成"记忆系统在工作"。值得在列表里标注来源类型，把 LanceDB 的功劳和 Graphiti 分开。

## 四、看起来接了其实在空转的

**写了没人读**：主图 canonical 结构化数据（31 条 SelfAnnotation + relation reason 边）的专用读器 graphiti_memory_reader 3/4 零消费方——P1 A+-prime 裁决后 ACP 改读 frontmatter，question_generator.py:1021-1042 注释明说"Graphiti 降为历史流"；唯一活口 read_node_conversation_summary 只有 MCP exam_tools 可达，而 skill 明令不调（quiz-answer SKILL.md:242）。
**读了没数据**：profile.py:215/281/344 查 :EntityNode（库内=0，真实 label :Entity=87）恒空；A11 定时归档数据源为空；/memory REST、GET /tips、mastery Neo4j 链无调用方；review.py:117 ImportError → schedule 恒空。
**断裂（最伤的四条）**：①Story 2.3 历史错误提醒——search_error_memories 方法全 backend 不存在，实测 500，双死；②6-source RAG Graphiti 通道——传 legacy `subject:canvas`（nodes.py:198）永不命中物理 `vault__` 组 + 200ms 超时（graphiti_client.py:222）对上实际 >1s，静默 fallback []，日志佐证 fuse_results graphiti 通道健康 0/5——skill 文档对用户宣称的 Graphiti 成分实际为零；③候选生产链——P14 classify 返回值丢弃 + B2 端点零调用，A4 accept 只能消费存量候选，**体感最强路径的弹药只出不进**；④belief 版本链——metadata 永不传入，write_belief_version 零调用（S2-2 GAP-D）。
附带 bug 证据：episode_worker.py:507 QueueShutDown（Py<3.13 API）；outbox 只进不出（memory_service.py:1466 落盘后无人重放）。

## 五、要让体感翻倍，最划算的 3 个接线

1. **【小时级】把 search_memories 变确定性触发**：chat-with-context / study-question 两个 SKILL.md 的 allowed-tools 加入 search_memories（当前仅 search_notes/get_neighbors/read_note）+ vault CLAUDE.md 加一条"回答学习类问题前先调 search_memories"。零后端代码。效果：确定性体感路径从 1 条变 2 条，是全表性价比最高的一根线。
2. **【半天-1 天】修 6-source RAG 的 Graphiti 通道**：nodes.py:198 的 group 构造改走 to_physical_group_id（对齐 vault__ 双下划线物理格式）+ graphiti_client.py:222 超时 200ms→3s（与 memory_service._search_graphiti:1647 的 3s 对齐）。效果：每次 /chat-with-context 和 /study-question 真实多一路主图+影子图召回，让 skill 已宣称的"含 Graphiti"从假变真；配合在 supplementary 列表标注 [Graphiti] 来源即可体感化。
3. **【1-2 天】接通 P14 候选生产**：conversation_distiller.py:~412 把 classifier.classify 的返回值落进 error_candidates[]（复用 error_writer.py write_error_dual candidate_only 既有路径）。效果：每次 SessionEnd 自动生产错误候选 → accept（A4 已活）→ misconception 入主图 → targeting-material 持续有新弹药。不修这条，第二节第 1 名的最强体感路径会随存量候选耗尽而枯竭。
（次优候选：重实现 search_error_memories 救活 Story 2.3——但需补方法 + 找调用方 + plugin 不调 enrich-context，成本中等，排第 4。）

**底线诚实**：即便三线全接，短期体感上限仍受库容制约——真实数据只有 ~50-60 节点、1 次完整学习会话。但写侧管道已被证实端到端活着（当天写当天可召回），接线的意义是让每天的批注和会话"看得见"，形成使用→可见→更多使用的飞轮；数据小的问题会随真实使用自然消解，读侧断裂不会。
