### 0.2 域的划分（剥完豁免后，按所在段落判）

| 域 | 位置（结构锚点） | 要求 |
|---|---|---|
| **D1 强绑定域** | frontmatter 的绑定键；`> [!info]+ 规模自陈` callout 整块；`## 台账（种子/派生）` 的模板行；`## AI 侧对账` 的统计行；四类信号行 | 域内每个数字**必须能在 scan JSON 找到同值来源**，且绑定到**具体对象**（哪个节点的哪个字段），不是「形状对就行」 |

## 二、问题的精确形态（已实读代码，非转述）

**文件**: `canvas-vault/.claude/skills/board-recap/scripts/recap_scan.py`（1714 行）
**函数**: `_verify_numbers(fm, text, report_path, problems)`（:1116）

现有绑定是**枚举式闭世界**——只对下列具名量做 scan JSON 全等校验：

| 绑定项 | 锚点 | 绑定方式 |
|---|---|---|
| `board_sha256` / `data_mode` / `recap_date` | frontmatter | 正则取值 + 与 scan JSON 全等 |
| 规模自陈五元组（成员/种子/派生/占位/批注） | 正文 | `scale_pat` 全文逐条校验，且必须**恰好一条**（round-6 修的诱饵行漏洞） |
| AI 侧对账 tips 两数 | `## AI 侧对账` 段 | 前缀定位 + 绑定 |

**漏拦面 = 上述枚举之外的任何数字。**
报告正文里写一句"这块板有 99 个子节点"，99 不匹配 `scale_pat`、不在 frontmatter、不在 tips 段，
于是既没有被绑定、也没有被禁止 → `--verify` exit 0。这不是实现 bug，是**设计边界**：
`_verify_numbers` 的 docstring 自述范围就是"报告核心计数"，从未声称覆盖全文数字。

## 三、为什么收紧很难（做卡时必须先解决的设计问题）

把"未绑定的裸数字一律 FAIL"直接落地，会打到大量合法语料。至少下列几类必须放行：

1. **日期与时间戳**——`2026-08-28`、`06:10`，且 `recap_date` 本身就是日期。
2. **节点/板标题里自带的数字**——CS 61B 的 `Lecture 14`、`§12.3`、`Project 2` 都是原文，
   report 是链接回原节点的，标题必然出现。
3. **Markdown 结构性数字**——有序列表 `1.` `2.`、标题层级、表格里的列编号。
4. **白名单动作句里的按键**——SKILL HARD-CONSTRAINTS #3 的 `Cmd+Shift+D`（含数字形态的组合键同理）。
5. **无据行固定文案**——`_NODATA_REASONS`（:861）五条常量本身若含数字则必须豁免。

同时"多禁一点"的每一步都要有反向锁，否则重演 round-5：
误伤不会让测试变红（报告是人写的，测试用的是 fixture），只会在**真实用板时**炸——
这正是最难被发现、也最伤用户信任的一类回归。
