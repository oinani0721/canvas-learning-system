#### G2-1 Cypher 读写契约拆分审计（6h · wave 1 · 防暗坑）
- **计划书锚点**: 计划书 L261（G2 条目1）；L43 进度矩阵'读侧 Phase 2 不在闭环'
- **做什么**: 全量枚举 cypher_with_group_filter() 的调用点并按 MATCH/MERGE/CREATE/DELETE 分类，把'读查询过滤契约'与'写身份契约'拆成两份显式规则；在规则/测试明确支持前禁止机械套 helper。产出调用点清单（file:line）+ 规则文档 + 新增真实 Neo4j 语法门与双 vault 行为门测试。只审计和立规立门，不在本卡改业务写路径（那是 G2-3）。
- **依赖**: 无 · **需勘探**: 是
- **完成判据方向**: 调用点清单 100% 分类且每处标注读/写契约归属；规则文档合入 .claude/rules 或 known-gotchas；新增真实 Neo4j 双 vault 行为测试（同名写删互不影响）全绿；Codex 审查 BLOCKER/HIGH 清零

#### G2-2 唯一 VaultScope resolver + 409 fail-closed（8h · wave 1 · 防暗坑）
- **计划书锚点**: 计划书 L262（G2 条目2）；L209 硬边界3'每请求只解析一次 VaultScope'；L114 memory 双真相源；L394 D1-A
- **做什么**: 把现有 _vault_id_resolver.py（11 endpoint 共享）、config.get_current_vault_id() 进程级 active vault、memory_service 写组三者收敛为唯一 VaultScope 对象：请求边界单点解析，request vault 与单 active 进程不一致时返回 409，禁止静默改写作用域；memory 写组改从 VaultScope 取（根治 C6 docstring 记录的'进程级单 active vault'双真相源）。边界：跨 vault 总览页（D3-B）读的是文件投影不经数据存储路径，不受 409 约束；Lance 表/Neo4j group/Graphiti group/journal namespace 的实际消费改造分别归 G2-4/G2-3/G4/G2-5。
- **依赖**: 无 · **需勘探**: 是
- **完成判据方向**: grep 请求路径无旁路直读 DEFAULT_GROUP_ID/直调 get_current_vault_id；不一致请求返回 409 的 API 测试全绿；C6 重写的 test_memory_service_contextvar_leak.py 契约断言更新为经 VaultScope 且全绿；全量收集无回归

#### G2-3 Neo4j 概念/LEARNED 身份加 group（6h · wave 2 · 防暗坑）
- **计划书锚点**: 计划书 L263（G2 条目3）；L112 create_learning_relationship 按概念名 MERGE 再 SET group 的搬家 bug
