## 三、更新协议

1. **复核第 N 批收尾**：把本批不合的卡追加进 §一，附「为什么没合」与「整改要点」（要点必须能直接粘进下一批 goal）。
2. **排第 N+1 批开头**：§一 每一行必须出现在手册里（整改车道 / 显式推迟并写理由 / 用户裁定放弃），不允许静默消失。
3. **卡合并后**：从 §一 移到 §二，写 squash commit SHA，并给原分支 tip 打 tag `merged-squash/<branch>`；**部分抽取**（只合分支里某几个 commit）用 `merged-squash/<branch>-<卡号>-only` 指向抽取点而非 tip——机械核对时带 `-only` 后缀的分支**仍算未合**（如 `card/w8-scope` 的 G4-4/OBS 仍在 §一）。
4. **终审字样如实抄录**：§二 登记时同时写终审自己的裁决词（如 G3-6b-R1 round-3 自判「FAIL」、G8-2 round-12 自判「PARTIAL」），合并依据是 B/H 计数而非该字样，两者并列以免误读。
5. 相关待用户裁决点在 `_bmad-output/审查/<日期>-第N批复核裁定与待裁决登记.md`（第八/九批为 `2026-09-04-第八九批合并僵局诊断与开发清单.md` §五），本文件只追踪「卡进没进主干」。
