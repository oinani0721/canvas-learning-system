## 1. 判定纪律

- **原子判据三态**：每维拆为原子判据，每条判据 `outcome ∈ {pass, fail, not_yet}` —— `pass` = 该判据在候选 SHA 上有完整证据；`fail` = 有机械反例在案（未闭合）；`not_yet` = 过门动作未发生或证据不完整。另记 `coverage ∈ {none, partial, complete}`（表列与 YAML 键名统一为 `coverage`）。**缺 outcome 或存在未闭合反例时 fail-closed**。登记完备性（证据/owner/缺口三者至少其一非空）是格式纪律，不替代 outcome。
- **owner 只引用未完成的正式卡**：owner 数组只填总账 v2 中存在 `#### <id>` 档案节的卡；已收官卡（在总账 §五 DONE 台账、无档案节，如 G2-1）不作 owner，其产物只作 evidence 引用。
- **source_criterion 逐字纪律**：每维「必过标准」逐字保留计划书 §8 原文；任何解释、裁定、范围调整放 `note` 字段并注明依据，不得覆盖原判据。
- **CI 单 SHA 规则**：「CI 全绿」只能对**单一 candidate SHA** 宣称——该 SHA 上全部 required workflow `triggered + success` 才算；异 SHA 绿灯只是历史 provenance，禁止拼绿。记录格式 = `SHA + workflow + run id + 日期` 三件套（对齐 V8 锚点纪律 1b7485b9：run id 是时点证据非现势声明；现势以 `gh run list` 实查为准）。
- **CI 白名单诚实声明**：当前 Test Suite 门 = 15 文件白名单套件（`.github/workflows/test.yml`），不是全量 tests/；全量门扩面 owner = DEBT-1 → DEBT-4。
- **未合并分支证据**：第三批 D 卡（m1/m2/m3 分支）证据标 `[分支未合并]`——其 Codex 审查为 **BLOCKER/HIGH 清零（MEDIUM/LOW 残留见各审查存档）**，未合并不构成过门。
- **YAML 定位（诚实声明）**：§3 的 YAML 是 §2 表的**结构化索引**，不是无损同源镜像——它承载 dim/criterion/outcome/coverage/owners/evidence-key/note 摘要，**不含逐维 `source_criterion` 全文与全部 note 正文**（人读正文以 §2 为准）。evidence 值目前是**未定 schema 的短别名**（如 `d5-shasum-30of30@c823a35f`），别名→路径/命令的 registry 属残余（§5）；在 registry 落地前，机读消费方只能把 evidence 当标签而非可解引用的证据指针。
