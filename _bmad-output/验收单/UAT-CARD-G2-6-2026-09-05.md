## 4-B 用户可感（先看这段）

> **一句话**：无变化（给「一键新建课程 vault」列了一张正式清单，并能只读检查一个 vault
> 缺了什么、多了什么）。

**展开说，这次改了什么、对你意味着什么：**

1. **你的日常没有任何变化。** 「一键新建课程 vault」这个命令跑起来和以前一模一样，
   复制过去的东西一件不多、一件不少。这一点是专门验证过的：新建 vault 用的那个仓库
   位置，在你不额外设置任何东西时，取到的值和改动前**一个字都不差**。

2. **多了一张正式清单。** 以前「新 vault 该有哪些东西」这件事，只写在那个安装脚本
   内部的五行里，别的程序读不到、也没法拿它去检查。现在它是一份独立的清单文件，
   每一项都写明了：它是**照搬过去的**、**只建个空文件夹**、**按新 vault 重新生成的**，
   还是**故意不带过去的**。

3. **多了一个只读检查工具。** 给它指一个 vault，它会告诉你：该有的东西缺了哪些、
   清单外多出了哪些、（如果你同时指个参照 vault）哪些文件的内容跟参照对不上。
   它**只看不改**——这一点不是靠承诺，是靠两道检查盯着：一道逐行数它有没有写操作，
   一道在真实目录上跑之前跑之后各拍一次快照比对。对你现在这个 vault 跑了一次，
   结论是「该有的 28 项一件不缺，另外有 5 样东西是清单里没写的」——那 5 样是
   两个额外插件、Obsidian 自己生成的两个文件、和一个缓存目录，都不是问题。

4. **有一件事要告诉你（已转交下一张卡）：** 现在新建 vault 时，会把旧 vault 的两个
   **本机私有文件**一起复制过去（一个是后端的通行凭证，一个是本机专属设置）。
   这次**没有改这个行为**，只是把它写进清单并标了记号。要不要改成「新 vault 重新
   生成一份」，是下一张卡的事。

5. **这个检查工具被反复挑毛病，都已修好，其中几个挺要紧。** 我请了三轮外部复核，
   又让一批互相独立的审查者从五个不同角度找茬。要紧的那几个都是同一类：
   **这个号称「只看不改」的工具，在某些情况下真的会改到你的文件。**
   比如你让它把检查报告存到某个位置，而那个位置恰好是你 vault 里某个文件的「另一个名字」
   ——它就会把报告内容盖到你的文件上。最离谱的一种是：你老老实实写
   「报告存到 vault 里的某某位置」，它**本该拒绝**（工具的规矩就是不许往被检查的地方写），
   结果它没拒绝，还真写进去了。

   现在改成了另一种写法：报告永远先写一个新文件，再把名字换过去。
   （我一度以为「换个写法就够了」，**第三轮复核把这个想法否掉了**——换写法保护不了
   「同一个文件的另一个名字」那种情况。所以现在是三道一起把关，不是一道。）

6. **还有一个反过来的毛病：它会把「我读不到」当成「一切正常」。** 如果某个文件夹因为权限
   读不进去，它以前会当作那里什么都没有，然后报告「一切正常」。现在它会明确告诉你
   「这里读不进去」，并且**不再报一切正常**——看不见和没问题是两回事。

7. **第三轮复核又找出三个「会动你文件」的毛病，也都修了。** 一个特别值得说：
   Mac 的文件夹名**不分大小写**（`Vault` 和 `vault` 是同一个文件夹），而这个工具
   之前是按名字的字面拼写来判断「这个位置在不在你的 vault 里」——于是换个大小写写法，
   它就以为在外面，报告直接写进了你的 vault。现在改成按**文件本身的身份**判断，
   跟怎么拼写无关。另外两个：它清理自己的临时文件时，**可能误删别人的同名文件**；
   以及某些文件夹它扫不进去时会假装「都检查过了」——现在扫不完就直接拒绝，不再蒙混。

8. **一句实话**：三轮外部复核分别挑出 **4 条、7 条、10 条**，那批独立审查者另挑出 15 条——
   **每一轮都还能找出新的**，而且第二轮的修复自己又带进了一个「会删你文件」的新毛病。
   其中**五个**是「只看不改的工具真的会改（或删）你的东西」。
   最后一轮的修复**没有再送去复核**（复核次数用完了），所以我不敢说它现在一定干净——
   只能说每一条挑出来的都当场复现过、修完又当场验过、也都补了检查盯着。

### 三 (b) 只读校验器 `scripts/verify_vault_install.py`

- **CLI**：`--vault <dir> [--source <dir>] [--manifest <path>] [--report <path>]`，`--report` 缺省写 stdout。
- **六种分类**：`match` / `missing` / `extra` / `content-drift` / `intentionally-excluded` / `unreadable`
  （`unreadable` 是 round-2 加的：读不进去的条目必须单独记，且**计入阻断**——
  「我看不见」不等于「一致」，把它算成 match 是漏报）。
  - `content-drift` **只在给了 `--source` 时**评估；否则报告里写 `not evaluated (无 --source)`，
    由 `test_content_drift_not_evaluated_without_source` 钉死（同时断言 `drift_evaluated is False`）。
  - `extra` 的覆盖面**写在 manifest 里**（`extra_scan` 字段：`.claude/*`、`.obsidian/*.json`、
    `.obsidian/plugins/*`），根级文档不在覆盖面内——与卡文 (b) 的定义一致，且「改边界只改清单」。
  - `intentionally-excluded` **只报告，不进退出码**：`test_intentionally_excluded_is_detected_alone`
    断言这一类单独出现时 `rc == 0`。
- **退出码**：`0` 全 match / `1` 有 missing·extra·content-drift·unreadable / `2` 用法错。
  rc=2 的入口每个都有测试：清单含绝对路径 / 非字符串 action / 非法 kind / 非法 extra_scan（7 种取值）/
  非 UTF-8 或坏 JSON 清单 / `--manifest` 指向目录 / `--vault` 不存在 /
  `--report` 落在 `--vault` 或 `--source` 内 / 落在树内软链的目标下 / 指向 `/dev/fd/N` 别名
  （凡涉及落点的都另断言那个文件**确实没被创建或修改**）。
- **零写，两道独立判据**：
  1. **结构判据**（`test_verifier_exposes_only_readonly_switches` +
     `test_verifier_write_calls_are_confined_to_write_report`）：
     CLI 参数面是**白名单**（必须恰好是 `-h/--help/--vault/--source/--manifest/--report`，多一个就红），
     并断言**没有位置参数或子命令**（它们的 option_strings 是空的，会从白名单里漏过去）；
     AST 遍历全部调用节点，26 类写操作**必须全部落在 `_write_report()` 这一个函数内**，
     别处一个都不许有，另断言 `shutil` / `rmtree` 不以任何 import 形式进来。
     精确豁免 `sys.stdout.write` / `sys.stderr.write` 两个字面形态（写标准输出不碰文件系统），
     而 `f.write(...)` 那种对文件对象的写照样被抓。
     > 这条最初写成「文件文本里不得出现 `--fix`」，跑出来是红的——docstring 里说明「没有 --fix」
     > 就被自己的 grep 抓到了（判据自指）。文本判据同时有假红和假绿两面（换个名字叫 `--repair-now` 就漏），
     > 换成白名单 + AST 后强度反而上升。
  2. **行为判据**（`test_verifier_writes_nothing_into_vault_or_source` + 裁判 9 手工一次）：
     先在目标里制造全部四类差异让校验器走遍所有分支，跑前跑后对 `--vault` 与 `--source`
     各取一次全树摘要（文件 sha256 + 目录条目，**目录也计入**，这样新建空目录也抓得到），逐字相同。
     手工那次用真实目录（车道 `canvas-vault/` 的一份拷贝，66 文件 / 104 条目）：
     `FILES-IDENTICAL` + `ENTRIES-IDENTICAL`，模板源 `git status` 0 变更。

**补充实测**（`stdout-default-and-rc2-20260905T173042.txt` + 更正件
`stdout-default-rc-corrected-20260905T173104.txt`）：

### round-2 整改本身带来的新边界（如实登记）

14. **报告落点的守卫是「防误伤」，不是「防对抗」**：检查与写入之间存在 TOCTOU 窗口；
    `_forbidden_roots` 扫描**之后**新建的软链别名不在覆盖范围内；本脚本不是特权程序，
    调用者本来就有权写那些文件。承诺收窄为：不会因为「路径看起来在树外」而误伤树内内容。
15. **`_forbidden_roots` 只在给了 `--report` 时才全树扫软链**，但那一次是整棵树遍历。
    live vault 上实测可接受，更大的树上是线性成本，未做上限或缓存。
16. **不支持字符类模式**：`GLOB_CHARS` 收窄为 `*?` 之后，清单里写 `[abc]*.json` 匹配的是
    **字面的** `[abc]`。这是为了让 `_has_glob` 与 `_pattern_to_regex` 两处口径一致而付的代价，
    现行清单没有字符类模式，但将来要用就得先扩 `_pattern_to_regex`。
17. **两侧都读不进去时摘要相同**：`_digest` 对不可读条目写同样的标记，所以源与目标都不可读
