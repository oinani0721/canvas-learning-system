## 一、你需要做什么（用户产品体验）

**没有任何要你操作的**。这张卡修的是一个你看不见但一直在坑你的账本 bug：

- **坑是什么**：系统每天会记一笔"今天推荐过哪个白板"（用来做轮转——明天并列时优先推没推过的板）。但如果某天早上第一次扫描时恰好没有到期卡（休息日、或库还是空的），这一天的记账机会就被白白烧掉了——下午到期卡出现、推送也正常发了，账本却一整天记不上。
- **后果**：账本长期空白 → 系统以为所有板都"从未推荐过" → 起步阶段几个板并列时，同一个板天天霸榜，轮转失效（恰是当初 CARD-A3 要防的事）。
- **修复后**：每天第一个真正上榜的白板会被记上账，不管它出现在早上首扫还是下午重扫；一天最多记一笔。你手机上的推送行为**零变化**，变的只是后续几天推荐轮转更公平。

### 改动语义（核心约 10 行）

`scripts/daily_review_run.py` 落账门从 `if ranked and first_gen_today:` 改为按日判定：

```
credited_today = (marker == today) or (today 已出现在 board_last_recommended 的值里)
if ranked and not credited_today: 落账 + 写 marker(last_recommend_credit_date)=today
```

- **语义** = 每天只给第一个**非空**榜首落账一次（原来是"只在当天第一次生成时落账"——首扫为空就永远欠账）。
- **兼容** = state 加性新增字段：旧 state 缺 marker 时 `.get()` 返回 None → 若当天从未落账则照常落账；若是**升级当天**旧版已落过账（值=today、无 marker），`values()` 检查识别为已落账，不给第二个板补账（Codex H1）。
- **tie-break 防线保留** = 当日已落账后重扫换榜，门挡住补写——"第二个板被标成今天推荐过"的污染路径与 CARD-A3 时代同样封死。

### 新增测试（3 条，均先红后绿）

1. `test_rest_day_first_nonempty_top_gets_credit` — 休息日形态：首扫全员未来到期（榜空）不落账 → 跨过到期点重扫，首个非空榜首落账（含磁盘持久化断言，Codex L1）→ 磁盘重载后同日换榜重扫不补账。
2. `test_empty_vault_first_scan_then_new_node_gets_credit` — 纯空形态：空库首扫（无通知）不落账 → 同日新增真板节点重扫，榜首落账。
3. `test_legacy_state_credited_today_without_marker_not_double_credited` — 升级当天：旧版已落账、state 无 marker → 同日换榜不得二次落账（Codex H1 回归锁）。
