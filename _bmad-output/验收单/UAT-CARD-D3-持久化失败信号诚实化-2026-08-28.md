### 语义设计（三分法，全部如实）

| 场景 | card_state_persisted | degraded_reason / reason |
|---|---|---|
| 评分写盘成功 | `true` | `null` |
| 评分写盘失败 | `false` | `card_state_write_failed` |
| 评分 concept_id 为空（算了没存） | `false` | `empty_concept_id_not_persisted` |
| Ebbinghaus fallback（无卡状态可存） | `null`（不适用） | `null` |
| 查询 auto-create 写盘失败 | `persisted=false` | `auto_created_not_persisted`（found 仍 true） |
| 查询命中既有卡（干净） | `persisted=true` | — |
| 查询命中缓存但此前写失败（内存孤儿） | `persisted=false` | `cached_state_not_persisted`（Codex H1 修复） |

**向后兼容**：全部新字段 Optional + 默认 None（沿用 SubmitAnswerResponse degraded 字段先例），200/404 语义不变；`reason` 仅在失败时写入 dict，防 None 值破坏既有 `result.get("reason", "")` 消费方。

### Codex 对抗审查

- 一轮（gpt-5.6-sol ultra）：`_bmad-output/审查/codex-review-CARD-D3.md` — **0 BLOCKER + 3 HIGH + 2 MEDIUM + 2 LOW**
- HIGH 处置（全部先红后绿）：
  - **H1 缓存命中洗白失败** → 新增 `_unpersisted_concepts` dirty 集合：写失败 add、成功全量快照 clear（治愈全部历史失败）；缓存命中锁内读集合决定 persisted，False 时 `reason="cached_state_not_persisted"`。反例测试：失败后同实例二次查询不得报 True
  - **H2 bool 不绑定本次 card_data** → `_save_card_states` 加 `pending` 参数，mutation 移入锁内、快照前应用；三个调用点全部改传 pending，不再锁外 mutate
  - **H3 UnicodeEncodeError 逃逸** → except 扩 `(OSError, TypeError, ValueError)`，持久化边界归一 False；lone surrogate 测试锁定 algorithm 仍 fsrs-4.5 + 如实 False
- MEDIUM 处置（reasoned rejection，二轮复核裁定）：
  - **M1 wire key set**：维持不改代码，但修正理由（二轮裁定原 rejection 不成立）——`exclude_none` 之外确有定向方案（`response_model_exclude_unset` + 全部构造点显式传参审计），但该方案需改造两端点全部 4 个构造点并改变 route 级序列化语义，对无 live 消费方的端点风险收益不成比例。旧响应将新增 `persisted:null` 等 3 个 null keys 的技术事实如实入档，列入下方待确认节由你裁决
  - **M2 openapi.json**：tracked spec 全面陈旧（实测重导出 10519 行 diff 全为存量债），本卡重导出会混入巨量无关变更；提议独立收债卡
- LOW 处置：断言强化 `"reason" not in result`（2 处）；`fallback_service` fixture 保存/恢复全局 `FSRS_RUNTIME_OK`
- 二轮复核（high）：H1/H2/LOW-1/LOW-2 全部 **RESOLVED**（H2 含 Codex 自跑并发线性化实测）；H3 裁定"部分"——**残留 HIGH：毒 key 无回滚隔离，拖垮后续正常 concept 持久化**（Codex 实测 normal-after-surrogate 也失败）
