## 三 (e) `expect_msg`：判据从「门」收紧到「那一条断言」

判据由 `rc != 0 and _hit(nodeid, failed)` 收紧为

```python
killed = rc != 0 and _hit(nodeid, failed) and (expect_msg is None or expect_msg in _error_lines(out))
```

⛔ **`_error_lines(out)` 只取 pytest 回溯里以 `E ` 开头的行**（真正抛出来的异常文本），
**不是**整份 stdout——pytest 的 long traceback 会把**整个测试函数的源码**打出来，函数里
每一条断言的消息串都在里面；拿 `msg in stdout` 当判据等于恒真，那是「判据被自己要找的
东西喂饱」的又一种形态（本仓一天内栽过三次的粗判据，换了个壳）。

取值规则：`expect_msg` 必须是门文件里**那一条断言**的消息字面量片段。

**18 条全部填了实值，没有一条留 `None`。** 取值不是照抄断言的整句，而是取该断言消息里
在门文件内 `grep -c` **恰为 1** 的片段（逐条实测，**18 条各一个字面量、两两互不相同**，在门文件里各命中 1 次；这条判据已升成 harness 的常驻门 `_check_expect_msg_unique()`）。

### 三.1 为 M3 的目标断言补了消息

`test_append_event_refuses_when_ledger_locked` 里

### 三.1b 「唯一」这个前提被我自己当场破掉了一次 —— 已升成常驻门

### 三.2 加性断言的期望值换成了独立快照

## 四 (f)(g) 两条恢复路径的 CAS 门

### 4.1 为什么必须单列

`_cas_guard` 在 `quiz-answer/SKILL.md` 有 4 处：`:353 def`、`:2678` A2 foreign 重放后的恢复发布、
`:2746` dup 恢复路径发布、`:2959` 正常路径发布。此前**只有 `:2959` 有门承重**（M2 绑
`test_cas_conflict_refuses_and_rerun_converges`），另外两个是「已实现但没有任何门测它」——
拆掉它们整份测试照样全绿。恢复动作与正常路径一样是**整份覆盖** frontmatter+正文，
少一道 CAS 就是**恢复动作自己**把用户的并发编辑吃掉。

### 4.2 双段结构（对照段不可省）

只跑「注入竞态 → 失败」的话，失败也可能是因为 seed 根本没走到恢复发布（被采用时刻门
`:2501` / attempt 序数门 `:2649` 先拦下），那样门是空的。所以每条门先跑**对照段**证明
同一个 seed 真的走完了恢复并把结果落了盘，再注入竞态。

seed 形态逐字照抄生产写侧真实产出的行（顶层 6 键 + payload 11 键），只改 `event_id` /
`exam_board`——自造形态过不了写点侧的 `validate_record_full`。只放**一条**：若本次事件也在
账本里，会先撞 `:2675-2676`「本次事件与别人的事件同处待恢复队列」fail-closed。

**「对照段真的把那两道门走完了吗」不靠论证，靠能翻转结论的对照输入**（实测，tmp vault）：

| 对照输入 | rc | 被哪一道拦下 | 拒因（节选） |
|---|---|---|---|
| **门里用的那个 seed（基线）** | 1 | **没被拦，走到了恢复发布** | stdout `A2 已恢复 1 个未完成事件…` |
| 只把 `attempt_count` 1 → 5 | 1 | **序数门 `:2649`** | `attempt_count=5 不等于期望值 1 (重放前笔记里是 0, 该事件未应用过)` |
| 只把 `review_time` 改成 11:00（`effective_at` 仍 10:00） | 1 | 更早的**校验器 §6.1 同瞬间门** | `扩展键 review_time … 与顶层 effective_at … 不是同一瞬间 (§6.1)` |
| `review_time` = `effective_at` = 11:00 而 `scored_at` = 10:00 | 1 | **采用时刻门 `:2501`** | `没有校准记录, 于是由 scored_at=… 与当时的水位线复算采用时刻 = …, 但账本记的是 review_time=…` |

⇒ 两道门都**确实在这条 seed 的路径上**（各有一条能把它们打红的对照输入），而基线 seed 从
它们中间**穿过去**了。第三行还顺带说明：单改 `review_time` 命中的是更早的校验器门，
不是 `:2501`——如果只用那一种对照输入，会误以为 `:2501` 被走过了。

### 4.3 ⚠️ 与卡文 (f) 的一处**如实偏差**

卡文 (f) 写「对照 rc=0 且恢复发布落盘」。**实测：A2 foreign 恢复路径按设计以非零码收尾**——
`SKILL.md:2705` 是 `raise SystemExit("[quiz-answer] 恢复已落定, 本次评分未写入 — 请重跑
/quiz-answer 续跑 …")`，rc=1。这是两阶段收敛语义（恢复先落定、本次评分要求重跑续写），
不是缺陷。所以对照段的判据按实况写成「**恢复结果落了盘 + 拒因是续跑要求**」，而不是 rc==0：

| 门 | 对照段 rc | 对照段判据 |
|---|---|---|
| `test_a2_foreign_recovery_publish_respects_cas` | **1**（设计如此） | stdout 含「A2 已恢复 1 个未完成事件」+ `fsrs_last_review == TS1` + 节点里有被恢复事件的校准条目 + stderr 含「恢复已落定, 本次评分未写入」+ validator rc=0 |
| `test_dup_recovery_publish_respects_cas` | **0** | stdout 含「A2 恢复(崩溃窗口①)」+ `fsrs_last_review == TS1` + 账本仍 1 行 + validator rc=0 |

### 4.4 竞态段：状态不变量排在 rc 之前

⛔ foreign 这条路径**拆掉 CAS 后 rc 仍是非零**（恢复照样以「请重跑」收尾）——拿 `rc != 0`
当第一判据会被那个非零码喂饱，与门① 当年栽的是同一个坑（「带层变异 + 假杀」）。所以两条门
都先问**状态**：

1. `RACE_MARK.strip() in text` —— 外部写者那段正文还在吗（拆掉 CAS ⇒ 被内存里的旧 body 整份覆盖掉）；
2. `"fsrs_last_review:" not in text` —— 恢复结果没被发布到节点（零写）；
3. 然后才是 `rc != 0`；
4. 拒因绑**这一个发布点**：`"冲突点: A2 foreign 重放后的恢复发布"` / `"冲突点: dup 恢复路径发布"`
   （只断言「CAS 冲突」不够——正常路径的门已经在断言它了，那样两条新门与 M2 分不开）；
5. 无 `.quiz-tmp` 残留。

### 五.1 顺着 R1-05 挖出来的一件更要紧的事：判据的结论取决于 PATH

整改 R1-05 时给残留扫描加了「返回码三态 + 两个方向」，**新输出立刻报了 `rc=1`**，残留是
`backend/scripts/__pycache__/g33_mutation_gates.cpython-314.pyc`——那是我自己那条对照探针用
`importlib` 导入 harness 时留下的字节码（CPython 把 `"MUT" + "ANT"` **常量折叠**成了一个真正的
MARK 字面量）。判据没判错，是派生物。但顺着它查下去发现了一件**更要紧**的事：

| 跑法 | 解析到的程序 | 对同一个 `.pyc` 的结论 |
|---|---|---|
| 交互 shell 的 `grep`（是个 shell **函数**包装） | `ugrep 7.8.4` | `rc=1` —— **看不见**（二进制默认静默跳过） |
| Python `subprocess.run(["grep", ...])` | `/usr/bin/grep`（BSD） | `rc=0`，报出文件名 |

字节层实测：该 `.pyc` 第 29686 字节处确实有 `MUTANT`；`grep -c` rc=1，`grep -a -c` = 1。

⇒ **同一条判据的结论取决于 PATH 上是哪个 `grep`**。换台机器、或某天 PATH 顺序变了，这道残留门
就会对二进制**静默失明**——那正是负控最不能有的东西。而且我此前所有用 shell 做的「复扫 5 项」
本身就比 harness 的判据弱，**我的验证命令比被验证的门还弱**。

处置（**加强**，不是放宽）：`_mark_files()` 改成在 Python 里**逐字节扫描**（分块 + 重叠尾巴），
不再 shell out；扫描面 1166 文件 / 19.6 MB，代价可忽略。同时新增 `_source_of()`：把
`X/__pycache__/name.cpython-*.pyc` 归到源文件 `X/name.py` 再判「自身 / 基线」——归属判的仍然是
「这个 MARK 属于**哪个源文件**」，**生产文件**的 `.pyc` 若含 MARK 照样落进 `leftovers`。

扫描器自己的验伪锚（实测）：在 `backend/tests/` 下埋一个含 MARK 的**二进制**探针文件，
新扫描器把它报了出来（旧的 shell 路径在本机看不见它）；同一次运行里 harness 自身的 `.pyc`
正确归到自身、不进 `leftovers`；`基线缺失: 无`。探针跑完即删。

   §九.3 的对照输入证明这一类现在会被正确判 SURVIVED，但**归因要按门分开写，不能一句带过**：
   - **M2 / M15**：红在**本卡新加的前提断言**上（`竞态注入没有触发` / `账本里一行都没有`）——
     这两条是前提断言真正承重的证据；
   - **M16 / M17**：红在**对照段**的断言上（`对照段没走到 foreign 恢复发布` / `对照段未收敛`），
     那两条断言在 `a795741f` 之前就存在；把它们翻转成 SURVIVED 的是 `expect_msg` 不命中。
     新加的 `_race_fired` 凭据挡的是**另一支**——「对照段过了、只有 race 那份副本死了」——
     本次对照输入没有触发到那一支，因此那一支**仍未被实测证明**；
   - **M13**：其门用的是自己那份内联注入（锚点是 `cas_token`，不是 `main`），本次对照输入的
     探针打在主写点块上，**没覆盖到它**；它的前提断言只有「门本身仍绿」这一个证据。
   - **M1**：没有任何能翻转结论的对照输入（它的前提断言 `len(rows) == 2` 未被实测打红过）。
   总之这不是一道通用防线，是**逐门加断言**换来的：新写的门若不带前提断言，这一类会复发。
10. **本卡新加的 5 条断言里有 5 条没有任何变异指向它们**（内部对抗审查逐条核出，是本卡
    「加了门但没证明它承重」的残余面，如实列）：
    - 4 处 `assert _race_fired(...)`（M2 / M13 / 两条新恢复门）：它们是**夹具前提**断言，
      失效形态在测试文件里而不在生产代码里，所以 `MUTATIONS`（只变异生产代码）**结构上
      够不到**它们。§九.3 的对照输入让其中 **2 处**（M2 / M15 那条）真的红过；M16/M17 的
      `_race_fired` 挡的那一支（「对照段过了、只有 race 副本死了」）**没有被实测触发过**。
    - `caller_payload == caller_snapshot`（R1-04 补的那条）：现有 18 条变异没有一条会单独
      打红它（M4a 先被「就地污染」那条抓住，M4b 先被「不是加性的」那条抓住）。
    ⚠️ **不为它编变异**：内部审查的两个反驳者独立指出，照「补一条变异」的建议做会同时引入
    两个新缺陷——① 那条 `expect_msg` 在门文件里出现 2 次，会被 `_check_expect_msg_unique()`
    在跑任何变异之前 `return 2`，把一道能跑的门变成跑不了的门；② 建议的变异方向是反的
    （先改再复制会落进账本行、被别的断言抓住），照做会造出一个**假 SURVIVED**。
    所以这里选择**如实登记**而不是凑覆盖率。

    本卡沿用既有机制，**没有**扩大这条声明的证据面。
