## 4-B 用户可感（先看这段）

**这次改了什么，对你意味着什么：无变化（提交前那道「有没有把实验残片留在代码里」的检查，
之前对一种极端文件名会放过去，现在会拦下；正常提交不受影响）。**

系统里有一道"交作业前的自检"：每次提交代码时，它会翻一遍这次新加的每一行，
看有没有把做实验时留下的临时记号忘在里面。忘了没清干净是很麻烦的事——那意味着
交上去的代码里混着实验残片，所以这道检查的规矩是"宁可错拦，不可放过"。

问题是：它自己有个放过去的口子。文件名里如果**带了换行**（一个文件名占了两行的那种），
这道检查会把这个名字当成两个不同的文件去找，两个都找不到，于是什么也没检查，
最后还是打印"通过"。也就是说——**一个自称"宁可错拦"的检查，对这一类文件名反而是"一定放过"**。

这次把这个口子堵上了。堵完之后：

- 名字带换行的文件，如果里面有实验记号，现在会被拦下，并且会在报告里点名说是哪个文件；
- 名字正常的文件、以及完全正常的一次提交，行为**和以前一模一样**，不会多拦你；
- 顺带修好了一件本来看不见的事：以前就算侥幸检查到了带特殊符号的文件名，
  报告里印出来的路径也可能是**假的**（比如名字里的反斜杠会被悄悄改写成别的字符）。现在印出来的就是真名字。

**一个诚实的补充**：为了保证"堵住了就是真堵住了"，这次给检查加了一小段自检——
它开工前先验一下自己会不会读文件名。如果哪天换到一台不支持这种读法的电脑上，
这道检查会**直接把提交全部拦下并说明原因**，而不是假装通过。这在你现在这台 Mac 上不会发生
（已实测），但如果以后有别人在 Linux 上开发这个项目，他们会撞上——这一条已登记，见文末。

### (a) 解释器判定 — 有实测，不靠推断

scratch worktree 里临时加一条 `shell-probe:` 命令跑真 hook（该命令**不进 commit**）：

```
PROBE-0=sh              PROBE-comm=sh          PROBE-args=sh -c …
PROBE-BASH_VERSION=3.2.57(1)-release
PROBE-rec1=[a\nb]  PROBE-rec2=[c]  PROBE-nul-records=2
```

- lefthook 2.1.6 用 **`sh -c`** 起 `run:` 块；本机 `/bin/sh` 是 bash 3.2.57 的 posix 模式。
- 最后三行是**正控**：`while IFS= read -r -d '' f` 在真 hook 环境里读出 2 条记录、
  且第 1 条把内嵌换行原样保住了。`BASH_VERSION` 非空只证明"有个 bash 在附近"，
  证明不了"lefthook 调的这个 sh 接受 `read -d`"——所以判据取记录数与记录内容，不取版本号。
- 据此选卡文 §一(a) 的 **bash 分支**写法：`while IFS= read -r -d '' f … done < "$TMPD/names"`。
  本机 `/bin/dash` 也存在，`read -d` 在它下面报 `Illegal option -d` 且整体 rc=0——这是新引入的
  假绿面，故加自证块（见 (d)）。

**残孔链（实测复核）**：文件名含 `\n` → `tr '\000' '\n'` 拆成两段 → 两段都非空、都进循环 →
`git diff --cached -- "<不存在的半个路径>"` **rc=0 且无输出** → `FAILED` 不置位、awk 无输入 →
打印 OK 退出 0。

**中间态存证（`b3x`）**：只补 NUL 消费、还没改 awk 时，b3 拿到的是 rc=1 **但走的是
`FAILED: 解析失败` 分支**、hits 为空。原因是 macOS awk 20200816 拒收 `-v` 赋值里的裸换行
（`awk: newline in string`, rc=2）。这条缺陷**修前走不到**——换行名根本到不了 awk——
是被本卡的上游修复"打开"的。顺带查出 `-v` 对赋值做转义处理：`-v F='a\tb.txt'` 会印出一个**真 TAB**，
即门报出的路径不是真路径。两者一并由 `BEGIN { F = ENVIRON["F"] }` 解决（env 值可含 NUL 以外任意字节）。

### (d) 新增的 NUL 读法自证块（承重矩阵）

自证块在开扫之前，用一份**已知答案**的载荷验证本 shell 真能逐字节取回 NUL 记录：

- 载荷字节 `a \ \n b \0 SP c \0`——同时含**反斜线**、**换行**、**前导空格**；
- 判据是把两条记录用 `|` 拼起来与一个**独立字面量** `$(printf '|a\\\nb| c')` 整串比对，
  不是数条数（期望值不由被测量派生，故不会跟着变异一起退化）。

矩阵（`d-selftest-mutation-matrix-…`）：

| 变体 | 自证块判定 | 说明 |
|---|---|---|
| 正控 `IFS= read -r -d ''` | **PASS**（放行） | 不是死门 / 不误拦 |
| 去掉 `-r` | **FAIL**（拦下） | acc 变 `\|ab\| c`——反斜线被吃 |
| 去掉 `IFS=` | **FAIL**（拦下） | acc 变 `…\|c`——前导空格被剥 |
| 去掉 `-d ''` | **FAIL**（拦下） | acc 变 `\|a\`——退回按行 |
| 解释器换 `/bin/dash` | **FAIL**（拦下） | acc 为空——`read -d` 不支持 |

对照组同样落盘：**旧的计数式载荷 `a\0b\0` 在带 `-r` 与不带 `-r` 时条数都是 2**，
即计数判据对 `-r` 完全失明。而 `-r` 一旦丢失，含反斜线的文件名会被改写 →
`git diff` 查不到 → rc=0 无输出 → **正是本卡要修的那条链原样复发**。
这条是内部复核（`selftest` 镜头）指出的，第一版自证块确实只数条数，已改。
