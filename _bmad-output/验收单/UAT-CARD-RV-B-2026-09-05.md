**机制**：冻结之后一次 walk 内不再有资格传播，每轮只学一层，总预算 =
外层 `range(4)`（`:429`）× 内层 `range(2)`（`:736`）= 8。旧版 add-only 能在单次 walk 内

**深度预算是独立参数，不是修法的必付代价**（本卡实测，内层 `range(k)` 逐档扫）：

| 内层 k | 预算 4×k | callee 首个误拒 | caller 首个误拒 | 负控 MISSED / 误拒 |
|---:|---:|---:|---:|---|
| 2（现状） | 8 | 8 | 8 | 0 / 0 |
| 3 | 12 | 12 | 12 | 0 / 0 |
| 4 | 16 | 16 | 16 | 0 / 0 |
| 8 | 32 | 32 | 32 | 0 / 0 |
| 16 | 64 | 64 | 64 | 0 / 0 |

首个误拒 hops **恒等于 外层×内层**，且**每一档负控都保持 0 MISSED / 0 误拒**
⇒ 加大预算不会把 HIGH-1 的漏检放回来。docstring `:720` 那句「把内外循环上限加到 20/40
仍然漏检」对 **add-only 版**为真，对**冻结版**已不再是「加轮数没用」的理由。

### 4-A.7 本卡新发现（均非阻断级）

**R-1（LOW，本卡新增）— `raw_proc.returncode` 未检查**
位置 `git show 004e08cc:…guard_probes.py:1057-1060`。`raw_proc` 只在 `:1057` 赋值、`:1058`
读 `.stdout`，**全文再无引用**（`grep -n 'raw_proc'` 仅两行）。若该命令失败（`bash` 不在
PATH、超时、权限），`raw` = `[]` ⇒ `sorted([]) == expected` 为假 ⇒ `premise_ok` 假 ⇒ 判 FAIL，
reason 却写成「乱序前提不成立：原始 compgen 展开为 []……本环境下去掉 sort 也会通过，
本探针无鉴别力」——把**命令失败**误报成**前提不成立**。方向仍是 fail-closed（判 FAIL 不判 PASS），
故非阻断级；属诊断误导。另两条同源边界（Codex 独立提出、本卡已核实）：`:1057` 用绝对路径
`/bin/bash`、`:1063` 用 PATH 里的 `bash`，代码不保证二者相同；`_sh`（`:505-509`）
`os.environ.copy()` 继承环境并再套一层 `bash -c`。

**补强（第二源实测，§4-A.10 #3）**：把解释器换成不存在的路径复现 → `raw_proc.returncode=127`、
`raw_proc.stderr='bash: … No such file or directory'`、`raw=[]`、`premise_ok=False`，
reason 原样打印那句关于 sort 的**结论**。更糟的一层是：返回的 `stderr_tail`（`:1092`）取的是
**门那次** `proc.stderr`（此时为空），而 `main()`（`:1160-1162`）是 `if r["stderr_tail"]: print(...)`
⇒ 该分支**根本不触发**，`raw_proc` 的 127 报错完全不可见，操作者只剩 reason 里一个 `[]` 作线索。
修法一行：先断言 `raw_proc.returncode == 0 and raw`，给它自己的 reason 并回传 `raw_proc.stderr`。
