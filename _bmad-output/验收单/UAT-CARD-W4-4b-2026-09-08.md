## 二 「旧断言为什么是把缺陷钉成规格」

**旧断言原文**（存档 `evidence-w44b/d-old-contract-verbatim.txt`，逐字节取自 `HEAD:` 那一版）：

```python
def test_final_accounting_is_registered_after_the_precheck(self):
    """相对顺序不变：预检抛出时就该拒绝装门，不留一个会 os._exit 的 atexit。"""
    ...
    assert precheck_at < register_at
```

**新断言**：

```python
def test_final_accounting_is_registered_before_the_precheck(self):
    ...
    assert register_at < precheck_at   # + assert hook_at < register_at（防反向窗口）
```

旧断言的目标是「预检抛出时不留下一个会 `os._exit` 的 atexit 处理器」。这个目标**本身是错的**：

1. `_install_audit_hook()` 调 `sys.addaudithook()`，CPython **没有** `removeaudithook` —— 装上就摘不掉；
2. 所以预检抛出的那一刻，门**已经在位**：受拦端口的连接照常被拦、照常进 `STATE` 的账；
3. 旧顺序下 `register_final_accounting()` 还没跑 ⇒ 这些账**没有人在退出时交**；
4. 于是进程带着 `unaccounted=1` 以 **rc=0** 收场 —— 「任何未结账尝试都令测试失败」这句承诺不成立。

`atexit` 处理器不是负担而是**责任**：装了会记账的 hook，就必须有人结账。零账时最终总账
本来也不改退出码（`_final_accounting` 的判据只看 `unaccounted` / `blocked` / `reported_status`，
与 `installed` 无关），所以「留下它」没有代价。旧断言把「不留 atexit」这个错误目标写成了
契约，等于把缺陷钉成了规格——它会让任何试图修复的人先撞上一条红。
