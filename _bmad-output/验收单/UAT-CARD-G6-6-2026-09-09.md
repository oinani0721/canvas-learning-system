## 一 本卡做了什么

### (b) state 加性 `snoozed`，`STATE_SCHEMA_VERSION` 2 → 3

- 形态 `snoozed: {<board>: "<aware ISO-8601 带 offset, 秒精度>"}`。
- `_fresh_state` / `_normalize_state`（`setdefault`）/ `_parse_state_file`（非 dict → 隔离重建）三处与既有 `board_done` **逐条同型追加**，原行不动。
- **不删过期键**：值 ≤ now 即非活跃。没有清理器，也不需要有——「还活着吗」是每次现算的。
- U6-B 的三方合并律**不需要改**：它按「我改没改」判，不写死键名（`_merge_state_with_disk` 一字未动）。

### (c) pick 让位（不删行、不改桶、不改分）

- 新增 `parse_snooze_until` / `active_snoozed` —— 后者是**「谁还活着」的唯一定义点**。
- `build_payload(..., snoozed=None)` 加性关键字；分区块紧跟 board_done 分区之后，稳定分区，全部活跃时退化恒等。
- `main()` 从 `--state` 与 `board_done` **同一次解析**取出 `snoozed`（不开第二个撕裂窗）。
- **payload 顶层零新键**——两条金样门是证明。

### (d) runner 缓存门同律唤醒

- `snoozed_sig`：与 `board_done_sig` 逐条同形，含「签名缺席 ≠ 变化」那条收紧。
  ⛔ **另立一个键**而不是把 `snoozed` 掺进 `done_sig`：后者会让升级当天所有既有 v2 state 的签名一次性对不上，每个库白重扫一轮。
- `snooze_wake_utc`：与 `next_due_utc` 同形、紧随其后落键；`wake_crossed` 与 `due_crossed` 同律。
  ⇒ **until 一过，下一档 runner 必重扫**，被推迟的板回榜首、Bark 标题跟随。
- `active_snoozed`（runner 侧薄封装）转调生产器那**一个**判定——Web 读侧也走它，三处不可能对「到没到点」给出不同答案。

### (e) 写端点 `POST /overview/board-snooze`

- 两档枚举，其余 422 `snooze_until_invalid`；`until <= now` → 422 `snooze_until_in_past`，**state 字节不变**。
  ⛔ 不静默夹到下一档：用户点的是「今晚」，悄悄改成「明天」等于替他做了一个他没做的决定。
- 「明天」用 `datetime.combine(date + 1天, 00:00, tzinfo)` 而非 `now + timedelta(hours=24)`——DST 切换日那一天不是 24 小时。
- 三道写侧门（同源 / 容纳 / 板名）与 board-done 是**同一个函数**，不是各写一份。
- `_write_board_snooze` 复用 U6-B 的锁 + `save_state`，写面不新增任何一项。

### (f) GET 投影 + 「已推迟」区

- `_read_snoozed`（只读，不隔离不写盘）+ `_snoozed_active`（只留活跃）→ `_vault_entry` 加性 `snoozed`，与 `board_done` 共用**同一次 now 读数**。
- 零 JS 页与交互壳各加第三区 `<details>`，**条件渲染**：活跃集为空时一个字节都不输出。
  ⛔ 理由：`test_review_overview.py:2012`（`count("<details") == 2`）与 `:2115`（`== 1`）是「恰好等于」断言，本卡**零改动**它们，只让代码不输出空区。
- 同板既完成又被推迟 → **只进已完成区**（done 优先），一行不会渲染两次。

### (g) 20:00 只在服务端判一次

- `_collect()` 顶层加性布尔 `tonight_available = now.hour < _SNOOZE_TONIGHT_HOUR`，与端点那侧同一个常量、同一次时钟读数。
- JS 直接用它渲染，**不做任何小时数比较**。
  ⛔ 理由：`display_tz` 若在某宿主形态下为 `null`（三档都取不到 IANA 名），JS 会退回浏览器本地——异地访问的用户看到「今晚」钮，而服务端按自己的本地时间必以 422 打回。JS 门的夹具把 node 进程本地钟钉在 **10:00** 来证明它用的是布尔不是自己的钟。

### (h) 取回 `POST /overview/board-unsnooze`（BASE 上 `board-undone` 存在 ⇒ 落地，非降级）

- 与 board-undone 逐条同形：幂等 200 + `already_unsnoozed`，不 404；本来就没有时**不改写 state**（一次无事可做的撤销不该跟 runner 的 :05 档抢发布）。

### 单一时钟入口 `_display_now()`（本卡新抽）

页面 / 端点原先各写 `datetime.now(_display_tz())`。本卡收成一个模块级函数，两个理由：
① 「读了几次时钟」在源码里数得出来；② 门可以把钟点钉死——没有可钉的入口就只能去打 `datetime` 这个**解释器全局**，那会连累同进程里任何别的调用方。
时区仍是每次现调 `_display_tz()`，本函数不持有状态；`review_overview.py` 里 `_DISPLAY_TZ` 出现次数**仍为 0**。
