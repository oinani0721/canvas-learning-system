## 1. 🎯 一句话目标

总览页升级出一个「交互版」：**到点的复习卡自己冒出来、页面自己刷新**，后端没开时明确告诉你「不可用」而不是白屏。

## 2. 📖 你的视角

作为学习者，我想把总览页一直开着当复习驾驶舱，**以便**不用手动刷新就知道「现在该复习哪块板、哪个节点」；后端偶尔没起来时，我也想知道是「没数据」还是「页面坏了」。

## 3. 🖥️ 交互流程（你的屏幕变化）

1. 打开总览「交互版」页面 → 顶栏出现绿色「已连接」徽标 + 上次更新时间 + 下次自动刷新倒计时。
2. 页面放着不动 → **到点的卡自己出现**：某块板的到期数字变了、节点明细自己多出来，顶栏「上次更新」时间在走。
3. 点某块库卡片上的「刷新投影」按钮 → 按钮旁出现一行反馈（已重建 / 刚刷过在等冷却 / 失败原因）。
4. 后端临时没开 → 页面顶部出现红色横幅「后端离线/不可用…自动重试中」，**之前的数据还在屏幕上**；后端恢复后横幅自己消失。
5. 某个库今天没有任何到期 → 那张卡片显示「✅ 今日无到期节点，休息一天」+ 最近到期提示。

## 本卡未证明什么（必填段，如实）

1. **未在 live 容器验证**：部署不在本卡。走查是在本车道本地起的临时服务上做的（数据是真实 live 库投影）。
2. **浏览器里没有真的点过「刷新投影」**：走查为满足写侧零取证全程未点（卡文允许二选一）。按钮点击后的 POST 行为，服务端由第七批 G6-1 测试覆盖，前端展示分支由 node 断言 + demo 截图覆盖——但「真实浏览器点下去」这个动作没有发生过。
3. **「保留最后一次成功数据」的横幅态没有截图**：走查截的是「从未成功过」的分支（横幅 + 尚未获取过数据）；「有旧数据垫底」的分支只有 node 断言。
4. **页面隐藏暂停只验了纯函数与事件分派逻辑**，没有在真实浏览器里做「切走再切回」的人工走查（headless 一次性进程做不了）。
5. **轮询的真实时钟行为未长跑**：clamp 边界由固定时钟断言，页面挂一整天会不会内存泄漏/定时器漂移，未验证。
6. **netlog 是进程级证据**：里面出现的谷歌组件更新域名是 Chrome 浏览器自己的后台流量（开任何页面都有），与页面无关；页面级判据是「页面发起的请求 4/4 全同源」。已写进分析文件，别被域名列表吓到。
7. **今日走查看到的是 08-31 的过期投影**（走查在 09-01 凌晨、当天 09:05 推送未发生），「今日投影」绿徽标的实时态在走查里没有自然出现（由 fixture 断言覆盖）。
8. **stale 库的深链可点性、obsidian:// 唤起**未验证（需要 Obsidian 真机环境）。
