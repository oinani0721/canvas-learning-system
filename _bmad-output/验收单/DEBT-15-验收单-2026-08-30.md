## 这一轮被外部审查抓到了什么（如实写）

Codex 第一轮给了 **5 个 BLOCKER + 2 个 HIGH，判 FAIL，明确说"不能据此关闭"**。
它不是纸面挑刺——每条都自己搭沙箱注入了变异命令，实测我的脚本**照样 exit 0**（也就是漏了）。

被抓到的核心问题是同一个：我用**逐行正则**去认 git 命令，而正则认不出这些写法——

```bash
git add -A                              # 和 git add openapi.json 共用一个签名 → 蹭到"允许"的登记
git commit -am auto && git push origin  # 一行两条命令，只报了 push，commit 消失
echo ready && git push rogue HEAD       # 首字是 echo，整行被丢掉
"git" push rogue HEAD                   # 命令名带引号
git -C "$REPO" push rogue HEAD          # git 和 push 中间插了参数
bash B.sh                               # B.sh 里的 git push 完全看不到
{"command":"git","args":["push",...]}   # 只读了 command 字段，没读 args
```

修法是把这一步换成**真正的命令解析**（词法分析 + 按 `&&`/`;`/`|` 拆命令 + 递归追进被调用的脚本）。
现在上面每一条都会变红，并且都固化成了负验证用例（N11–N16），以后改坏了会立刻报出来。

**同时如实说明**：我自己在这轮里也踩了三次同一个错误——把"我没看见"当成"它不存在"：

1. 路径展开时引号留在中间，导致最该抓的那个脚本**一条都没扫到，却报全绿**；
2. 负验证脚本自己崩了没输出，`grep` 匹配不到就判成"没有误报"，**假通过**；
3. 沙箱少复制了几个文件，基线判红。

这也是为什么脚本里专门加了"来源不可达 / 配置解析失败 / 命令看不懂 → 一律判 FAIL"这三道门：
**看不见，不等于没有。**
