## ⛔ 一句话把话说准：这个脚本不是防线，那把锁才是

外部审查（Codex）连查两轮，**两轮都判 FAIL**，理由是同一句话，我接受：

> 它只能证明「**被这个扫描器看到的**、又没登记在案的 git 写会报警」，
> **不能**证明「所有偷偷自动提交推送的行为都会被看到」。

所以本卡的真实结论是：

- 脚本的用处是**把已知的 10 条自动 git 写链登记在案、可机械复核**，以及把"读不懂的地方"显式标红（而不是假装没事）。
- 它**替代不了** U1——把那 4 条危险写链真正拆掉。
- **在 U1 落地之前，安全性依然押在 `~/.claude/auto-sync.lock.d` 这把锁上。**

脚本现在跑出来的状态叫 `KNOWN_UNSAFE`（不是"通过"）：意思是"账对得上，但危险的东西还在"。

**还有几类它看不到的**（如实列，不遮掩）：公司/MDM 下发的 hook、命令行 `--settings` 临时传入的 hook、
skill/agent 文件头里写的 hook（你本机就有 5 个这样的 skill 文件）。

## 这两轮被外部审查抓到了什么（如实写）

Codex 第一轮给了 **5 个 BLOCKER + 2 个 HIGH，判 FAIL，明确说"不能据此关闭"**。
它不是纸面挑刺——每条都自己搭沙箱注入了变异命令，实测我的脚本**照样 exit 0**（也就是漏了）。

被抓到的核心问题是同一个：我用**逐行正则**去认 git 命令，而正则认不出这些写法——

```bash
git add -A                              # 和 git add openapi.json 共用一个签名 → 蹭到"允许"的登记
git commit -am auto && git push origin  # 一行两条命令，只报了 push，commit 消失
echo ready && git push rogue HEAD       # 首字是 echo，整行被丢掉
"git" push rogue HEAD                   # 命令名带引号
git -C "$REPO" push rogue HEAD          # git 和 push 中间插了参数
bash B.sh                               # B.sh 里的 git push 完全看不到
{"command":"git","args":["push",...]}   # 只读了 command 字段，没读 args
```

修法是把这一步换成**真正的命令解析**（词法分析 + 按 `&&`/`;`/`|` 拆命令 + 递归追进被调用的脚本）。

**第二轮它又抓到 10 条**，也都改了并固化成用例（N17–N24）：递归深度超限被静默丢弃、
直接执行脚本（不带 `bash` 前缀）、`sh -c "…"` 内联、编译成二进制的 hook、
`lefthook-local.yaml`（后缀是 `.yaml` 不是 `.yml`）、`extends` 引进来的外部配置、
LaunchAgent 的另一种写法，外加两类**误报**（heredoc 里的文档、纯数据列表被当成命令）。

其中最值得记的一条：`extends` 引进来的 rogue 配置，**被我自己写的"已核查"标记放行了**——
那个标记本来只是认领"某个动态路径看不懂"，结果把性质完全不同的"外部配置合并"一起盖过去了。
这正是 U6 要收紧的问题，它真的咬了一次。

现在上面每一条都会变红，改坏了会立刻报出来。

**同时如实说明**：我自己在这轮里也踩了三次同一个错误——把"我没看见"当成"它不存在"：

1. 路径展开时引号留在中间，导致最该抓的那个脚本**一条都没扫到，却报全绿**；
2. 负验证脚本自己崩了没输出，`grep` 匹配不到就判成"没有误报"，**假通过**；
3. 沙箱少复制了几个文件，基线判红。

这也是为什么脚本里专门加了"来源不可达 / 配置解析失败 / 命令看不懂 → 一律判 FAIL"这三道门：
**看不见，不等于没有。**
