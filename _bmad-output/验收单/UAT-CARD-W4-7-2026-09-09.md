## 五 本卡未证明什么

1. **不证明所有协议族 / 地址形态的分类正确**。Codex p1 §4 表里标「未验证」的项仍未验证；
   本卡只补了「普通 tuple + 真实主机 + 受拦端口」这一类负例。
2. **(f) M-4 不证明「起了事件循环之后」的 uvloop 行为**，也**不证明非本机 CPython 版本**的
   audit `import` 事件语义 —— 实测只在本树 **CPython 3.14.4** 上做过。若某个版本让
   `importlib.import_module` 也为顶层名抛事件，本卡的判据只是变得更宽松（不会误拦）；
   若某个版本让子模块也不抛事件，这条路会重新打开 —— **那种情况本卡测不到**。
3. **(e) M-3 的行为探针只证明「这一种最小会话形态里预检跑到了」**，不证明所有 pytest 入口
   形态（例如 `-p` 之外的插件加载方式、带 `-c` 指定 ini、xdist 子进程）。
4. **H-1a 的修法不证明 `__index__` 抛 `BaseException` 子类（如 `KeyboardInterrupt`）时的行为**
   —— `except Exception` 捕不到它，那条路径仍会让异常逸出、越过记账。如实登记：
   与 U7-B 的 `_safe_repr` 用 `BaseException` 的取舍**不一致**，本卡按卡文写的
   `except Exception` 执行，一致性问题登记交下一卡。
5. **不做真连 7691/7687 的活性验证**（M-3 探针只做 URI 字符串判定，M-4 探针只做 import）。
6. **不复审 U8 面**（`negative_control.py` / 四 harness / `lefthook.yml`）。
7. **契约与探针的数字（136 / 59）是本树快照，不是代码不变量**。
8. **L-2 只删了「同输入同期望」的那一条**；`UNSUPPORTED_SCHEME_URIS` 的 ftp/http/https

### 9.2 ⛔ 验收单混入字面 NUL 字节 —— git 判 binary，主 session 无法 diff 审阅

**现象**：本验收单 `:89` 的命令串内含 **1 个字面 NUL**，`git diff --numstat` 对该文件显示 `-` / `-`（binary），
`grep` 报 `binary file matches`。契约 / 守卫 / 探针等**代码文件本身零 NUL**，污染只在这一份文档。

**根因（当场复现，非推断）——「任何会解释转义的中间层」，不是某个工具专属**：
文档要写 U+0000 的**转义拼写** `\u0000` 时，只要落盘路径上有一层会解释它，拼写就变成真正的 NUL 字节。
本卡在**同一个坑上连踩三次**，三次分属三个不同的层：

| # | 中间层 | 实测 |
|---|---|---|
| 1 | 原验收单 `:89` 写入时（本节之前，已污染入库） | 文件含 1 个字面 NUL，git 判 binary |
| 2 | **zsh 内建 `echo`**（默认解释反斜杠转义；bash 内建 `echo` 需 `-e`） | `zsh -c 'echo "X\u0000Y"'` 输出 `b'X\x00Y\n'`（NUL=1）；同一命令 bash 输出 `b'X\\u0000Y\n'`（NUL=0） |
| 3 | **Edit 工具的 JSON 字符串解码**（写本节 §9.2 时） | JSON 里的 `\u0000` 被解码成真 NUL，一次写进 2 个 |

⚠️ **第 2、3 次都发生在「修这个坑」的操作本身里** —— 知道坑在哪并不能避开它，
因为每次换一个写入通道就换了一层解释器。**收尾时把这条坑写进工程记忆，写记忆的那次 Write 又触发了第 4 次**（同为工具 JSON 层，2 个 NUL，已修）。
⇒ 台账 §六.13 建议的 lefthook 检查不该只盯 `_bmad-output/**`，凡是本仓写出的文档都该过一遍。

**可靠写法（本卡最终采用）**：由 Python 直接写文件，且脚本内**用拼接构造**该拼写
（`"\\\\" + "u0000"`，避免源码里出现可被任何层解释的完整形态），落盘前 `assert` 全文件无 NUL。
第一版重测证据文件（zsh `echo` 写的，实测 NUL=1）已删除不入库。

**处置**：`:89` 那行的原命令串已被 NUL 破坏、**不可复现** ⇒ **不复原猜测值**，改为在最终 HEAD 重测并记录确切命令与输出
（`grep -c 'assert "\\x00" in host'` = **1**；`grep -c 'x00'` = **2**，`:580` docstring + `:595` 断言；
`grep -c '_is_selftest_address(('` = **7** ≥ 5）。证据 `evidence-w47/nul-root-cause-and-remeasure-*.txt`。

改后全文件 NUL = 0、`file(1)` 判 `UTF-8 text`。**如实说明**：本次修复**这一次的 diff** 仍会显示为 binary
（对比的旧侧是库里那份含 NUL 的 blob），**从本提交起**该文件在树上即为文本，后续版本可正常逐行 diff。
