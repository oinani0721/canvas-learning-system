### 1. `split-preview-CS188 lecture 2.md` —— 建议清单（多了一列）

还是你上次验收过的那份 27 条建议，只是候选表格多了一列 **稳定 ID**（`bsa1-` 开头的一串）。
你不需要看懂那串字符，它的作用是：**同一段讲义内容，不管你在文件开头加多少行、
不管你怎么改这一节的正文、不管你在**同一个上级标题底下**把它上下调序，它的这串 ID 都不变。**

⚠ 这句话有边界，不能听成「怎么动都不变」（这处措辞被审查连着两轮点名，第一次改得还不够准）：
把这一节**搬到另一份笔记**、**挪到另一个上级标题底下**（哪怕还在同一份笔记里）、
**改它或它上级的标题**、或者笔记里**有两个标题一模一样的小节**时，ID 会变。完整清单（会变 10 条 / 不变 10 条，每条都有测试钉着）在
`docs/design/split-stable-id-contract.md` §4。

### 2. `split-diff-CS188 lecture 2.md` —— 「什么都没变」长什么样

同一块板连跑两次的对账结果：新增 0 / 内容变更 0 / 移动 0 / 移除 0 / **未变 27**。
这是稳定 ID 生效的最直接证据——如果 ID 不稳，同一份内容跑两次就会满屏"变化"。

### 3. `split-diff-CS188 lecture 2-四态演示.md` —— **重点看这份**

我把你的 CS188 讲义**复制了一份到临时目录**（你的原件一个字节没动，见 §二），
在副本上故意做了四种改动，然后让它对账。你会看到：

| 我做了什么 | 它报出来的 |
|---|---|
| 在文件开头塞了 3 行 → 后面所有内容行号整体位移 | **不算变化**（未变 24 条里就有它们） |
| 给「课程概述与理性代理」补了一句正文 | **内容变更** 1 条，并且 ID 没变——还是同一段 |
| 把「反射代理」整块挪到「吃豆人示例」前面 | **移动** 1 条，ID 也没变 |
| 把「规划代理」的标题改成「规划代理（修订版）」 | **移除** 1 条 + **新增** 1 条 |

最后那条要特别说清楚，因为它是**有意的取舍不是 bug**：**改标题会让这条建议换一个新身份**，
所以它报成「旧的没了 + 来了个新的」，而不是「同一条改了名」。
为什么不做得更聪明（比如猜「这两条其实是同一个」）——因为一猜就有猜错的可能，
而这个引擎的硬要求是「同样的输入跑两次结果必须一模一样」，容不下猜测。
真要把改名前后接上，将来在 G5-10 由**你点一下确认**来接，不由机器猜。

还有一个你可能会疑惑的地方：演示里**新增是 2 条不是 1 条**。多出来的那条
`理性代理 (Rational Agents)` 不是 ID 不稳——是我补的那句正文正好落在它下面，
把它从「正文太短、不够格拆」推过了门槛，于是它**第一次成为候选**。
这属于"建议清单本身变长了"，和身份稳不稳定是两回事。
