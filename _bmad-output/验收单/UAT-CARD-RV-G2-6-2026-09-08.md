## 六 (c) `extra_allow`

- `Manifest` 加 `extra_allow: tuple[str, ...] = ()`；`load_manifest` 读顶层 `extra_allow`，
  缺省 `[]`，非 list → `ManifestError`。
- 每项走 `_check_relative_segment`（`_check_path_field` 的同一个底层函数）：相对 / 无 `..` /
  非空 / 无 NUL / 可编码 UTF-8；规范化后**重复 → `ManifestError`**；支持 `*?` glob。
- 与 `declared_paths` 或任一 exclude 模式**重叠 → `ManifestError`**（`_overlapping_declaration`）。
- 命中 → `report.allowed_extra`，render 新段 `## allowed-extra`，**不计 rc**；未列 → 仍 `extra`。
- 仓内清单初值 **`"extra_allow": []`**，`description` 加一句说明（门
  `test_manifest_ships_empty_extra_allow` 同时钉住这两点）。`test_extra_scan_surface_is_pinned` 未动。

#### 最重的一条：我自己造的假绿

round-3 为了让摘要阶段不抛 `UnicodeEncodeError`，我把 `.encode("utf-8")` 改成
`errors="backslashreplace"`，并在注释里写下理由：**「摘要只需确定性，转义不影响可比性」**。

**那句自我说服的理由就是缺陷本体。** 确定性是**必要**条件，不是充分条件 ——
摘要还必须**单射**。本机实测：

```
os.fsdecode(b"bad\xff-target")  →  'bad\udcff-target'  →  backslashreplace  →  b'bad\\udcff-target'
字面串 'bad\\udcff-target'（纯 ASCII）                  →  backslashreplace  →  b'bad\\udcff-target'
⇒ 编码后逐字节相同、sha 相同 ⇒ 两个**不同**的软链目标判等 ⇒ 内容差异被吃掉 = 假绿
对照 surrogatepass: b'bad\xed\xb3\xbf-target' vs b'bad\\udcff-target' ⇒ 不同 ✅
```

改用 `surrogatepass`（单射且不抛）。两道门：**AST 判据**（摘要函数里的 `encode` 不得用
`backslashreplace`，带「至少见到 3 处 encode」的验伪锚）+ **行为判据**（两个不同软链目标必须给出不同摘要）。
