## 一、你会看到什么变化（用户产品体验）

`/board-recap` 生成的回顾报告里，**用中文数字写的规模自陈会被拦下**，提示你改用
阿拉伯数字。具体：

- ✅ 仍然放行：`本板共有五个子节点`（单字数词，值 = 五 = 5，能在 scan 里找到出处）
- ⛔ 现在拦下：`本板共有一零个子节点` / `共有五四个` / `共有九十八万个` / `共有十个`
  —— 报告会写「中文数字计数 X 无法解析（报告请用阿拉伯数字写计数）」

还有一类更隐蔽的、这次一并拦下的：

- ⛔ `本板共有九十八万**五**个子节点` —— 在 Obsidian 里**渲染出来就是**
  「本板共有九十八万五个子节点」（五是粗体），而验证器原先只看到尾巴上的
  `五`，`五 = 5` 有出处，于是**整句虚构的 980005 静默通过**。
- ⛔ 同理：`980 005个`（空格当千分位）、`98765**4**个`、`1 000个`、
  数字中间夹 `&nbsp;` / 零宽字符 / 空 HTML 标签 —— 现在都按**读者看到的那个数**
  去核对出处。

**为什么值得拦**：`一零` 这种写法，旧实现会算成 **0**，而 0 恒在「有出处」的数值池
里（池含任意两数之差，`a−a=0`），于是**一句完全虚构的规模自陈整域免检**。
R3 开工在标准 tmp fixture 上实测过这条：开工 HEAD 上它 **exit 0 放行**。

### 一个字都不能误伤（放行门与拦截门同权重）

`说明十分清楚` / `统计口径尚未一致` 这类含「十」「一」的正常中文**不受影响**
（中文数字只有紧跟量词、且出现在规模自陈句式里才算计数）——这是 round-5 那次
翻车的原始误伤输入，全套件里有专门的放行门守着。

## 三、技术判据（Claude 已代跑，输出全文见 §四-A 与存档）

### R3 的整改（三条，一体）

1. **多位解析器整体退役** —— 删 `_cjk_to_int`，代之以
   `_cjk_single_to_int(s) = _CJK_NUM.get(s) if len(s) == 1 else None`。
   值 = 单字映射（绝对确定）；多字 / 单字量词（十百千万亿，**不在** `_CJK_NUM`）/
   集合外一律 `None` → 调用方 fail-closed。
2. **两个消费面共用同一判据** —— D2 叙述段与 fallback 允许式都调它，不再分叉。
3. **提取面机械派生** —— `_CJK_NUM_CHARS = "".join(sorted(set(_CJK_NUM) | set(_CJK_UNIT)))`，
   `_CJK_NUM_RE`（D2）与 `_CJK_NUM_RUN_RE`（fallback）都由它构造。
   口径：**抓得到才拒得掉**——提取面漏字，该串会落到检查面**之外** = 漏拦，
   而不是 fail-closed。此前两侧各手抄一份字面量，正是它们分叉的成因。

### 第二刀的整改（提取面，三条一体）

4. **数串跨连接字符整体抓取** —— `_D2_NOISE_ONE`(:1355) 拆出单元，
   `_INVISIBLE_ONE`(:1366) 补零宽/双向控制字符，合成 `_D2_JOIN_ONE`(:1367)。
   `_CJK_NUM_RUN_PAT`(:1508) 与 `_D2_COUNT_RE`(:1388) 都按「数字字 (连接字符\* 数字字)\*」
   构造，CJK 与 ASCII **同一口径**。
5. **剥连接字符后再交判据** —— `_join_free()`(:1371) 还原读者**看到**的那个数；
   诊断里打印的也是还原后的完整数串（`九十八万五` / `980005`），
   而不是尾片（原先报 `五` / `005`，连诊断都在骗人）。
6. **前导零归一化下沉到 token** —— 行级剥零与整体抓取相冲（见 §二），已删除。

`*+` possessive 量词：连接字符集与数字字集**不相交**，贪婪吞完即可、无需回溯，
同时杜绝嵌套量词的病态回溯。

### 一处**删掉**的防线（如实记，因为它正是本卡在审的那种病）

第一版还写了个"左边界守卫"（匹配左侧跳过连接字符若仍有同类数字字则判无法确定）。
**实测它永不触发**：能被它命中的形态都先被 run 模式吞掉了，而连接集表外字符
（`九十八万x五个`）又不满足它的条件。一个永不执行的分支 = round-5 判过的
「死代码冒充防线」，故**删除而非保留**。

### 代价（如实记，不粉饰）

合法的**多字**中文数词计数（真写「本板共有一百二十个节点」且属实）现在也会被拒，
诊断提示改用阿拉伯数字。报告是机器渲染的，模板与合成语料里没有多字合法用例，
全套件 253 门实测**零误伤**——但这是「当前语料零误伤」，不是「不可能误伤」。

### 新增的四道门（每道写清「证明什么 / 不证明什么」）

| 门 | 层 | 证明什么 | **不**证明什么 |
|---|---|---|---|
| `test_domain_r5_cjk_single_char_only_unit_contract` | 单元 | 判据逐形态取值；提取字符类由 `_CJK_NUM ∪ _CJK_UNIT` **机械派生**；`_cjk_to_int` 确已退役且不得复活 | 不证明调用方正确使用了它 |

| `test_domain_r5_noise_split_number_run_cli`（round-2 新增） | 真实 CLI | 排版噪声/不可见字符**不得**成为数串断点：CJK 6 形态 + ASCII 3 形态（含 SI 千分位与前导零交互）+ fallback 2 形态全部 exit 1，**且诊断里出现还原后的完整数串**；同时 5 条放行面（含 round-5 原始误伤输入）不被反噬 | 连接集是**封闭表**；表外字符（`x` / 顿号 / `[[目标\|]]` 残留 `\|]]`）仍能切断——那些断点渲染后**可见**；表外**不可见**载体（>22 字符的 HTML 注释）是真残余，见 §五之三 |
| `test_domain_r5_prose_single_char_value_enters_pool`（round-2 新增） | 单元（合成 scan） | D2 侧单字**带自身值**进池（九→`九(9) 找不到同值来源` / 二→放行）——该分支此前**零门覆盖**（摘掉它 253 用例仍全绿） | 不证明段切分、豁免跨度剥离与句式门 |

**为什么第二道门要用合成 scan（这是本卡最容易写成假门的地方）**：标准 fixture 的
数值池是 `[0..16, 22]`，**覆盖了 `_CJK_NUM` 的全部值（0-9）** —— CLI 层根本构造不出
「单字且值不在池」的用例。只写「`五` 放行」会退化成**空洞证明**：没查池也会 rc=0。
合成 scan 把池收窄到 `[0,1,2]`，`九` 才能证明 9 **确实**带值进了池比对。
合成语料非 live 正文，不触碰 live vault。
