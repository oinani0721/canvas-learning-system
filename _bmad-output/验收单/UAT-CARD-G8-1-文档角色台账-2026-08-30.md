## 📌 你需要过目的三个结论

1. **发现了一处"两套门禁不一致"，并且我没有去修它。**
   你的笔记要进系统有两道门：一道决定「进不进搜索库」，一道决定「进不进记忆图」。
   实测全 vault 324 个文件逐个过这两道门，**恰好有 1 个文件两道门给出了相反答案** ——
   vault 根目录下那份 `chatgpt-adversarial-review-Q1Q2Q3-2026-05-12.md`：
   它**能被搜索到，但不会进记忆图**。
   两边的代码各自都写明了这是有意为之（搜索侧认为"根目录下的用户笔记应该能搜到"，
   记忆侧认为"根目录下的散文件不是学习节点"）。
   卡片明令这是**登记对象不是修复对象**，所以我把它写进台账并说明依据，**没有动任何一边的代码**。
   → 如果你觉得根目录笔记**应该**进记忆图（或者反过来**不该**被搜到），
   这是一个需要你拍板的产品决策，不是 bug。

2. **台账现在是"文档类型白名单"的唯一真相源，但我如实写了它还没关门。**
   G4-16 那张卡查完 `doc_type` 标签后，把"该收哪些值"的裁定权移交给了本卡。
   六个取值已逐一登记。但**值域仍然没有关门** —— frontmatter 里 `type:` 写什么就入库什么，
   没有白名单校验。我**没有**顺手去加这道校验（那是 G4-16 FU-3 的地盘），
   只是把"门还开着"这件事连同三个具体的敞口写进了台账。

3. **抄到两个"户口本上没有的类型"，也照实登记了。**
   live vault 里有 `type: recap`（4 份板级回顾报告）和 `type: mockup`（1 份 UX 样稿）
   —— 这两个值都不在 doc_type 六取值里。它们现在没事，因为所在目录（outputs/ 和 .trash/）
   都在黑名单上、进不了搜索库。但**万一哪天 outputs/ 被移出黑名单，`recap` 就会直接变成第 7 种值**。
   这条风险已登记，归属 G4-16 FU-3。

## 🔍 本卡实测坐实的事实（不是推断）

用**真实的两个准入函数**（不是重新实现）对 live vault 全量 324 文件逐路径求值：

| 指标 | 实测值 |
|---|---|
| 总文件数 | 324 |
| `should_index` 放行（进 RAG 索引面） | 64 |
| `check_vault_path` 放行（进记忆写入面） | 63 |
| **两面分歧** | **1**（`chatgpt-adversarial-review-Q1Q2Q3-2026-05-12.md`，root_level） |

分歧只有 1 条的原因：其余 9 个根级 md 都命中了文件名黑名单（CLAUDE.md / Dashboard.md /
excalibrain.md / UAT-* / Untitled* / 未命名* / 2111.md），被两面同时拒，因此不构成分歧。

另登记了第二类分歧 **DIV-2（后缀大小写）**：`should_index` 用 `endswith(".md")`（大小写敏感），
`check_vault_path` 用 `suffix.lower()`（不敏感）→ `节点/FOO.MD` 会被检索面拒、被记忆面收。
live vault 当前 **0 实例**，但**登记的是类不是实例** —— 依据是两函数后缀判定行的源码差异，不是推断。
该类的 pattern 刻意写成 `["**/*.M[Dd]", "**/*.[Mm]D"]` 而非 `[Mm][Dd]`，
就是为了**不吃掉全小写 `.md`** —— 否则将来真出现同向的新分歧类会被误判成"已登记"而漏报。

### round-4 再抓 1 BLOCKER + 3 HIGH + 1 LOW（全部整改）

最重的一条是**越界读取**：指向 vault 外的 symlink，checker 会在准入判断**之前**
把外部文件的正文读进来——一个只读的 vault 审计器跨出了 vault 边界。
连同 `rglob` 静默吞掉的四类盲区（不可读子树 / 不可读文件 / dangling·self symlink /
超长路径），"0 finding"又一次可能是"没看见"。
→ 枚举改用带错误回收的 walker（新增 **G10** 报盲区），containment 检查前移
（新增 **G11** 判红并**拒读**）。live vault 计数与旧实现完全一致，无回归。

另三条 HIGH：台账里还残留一行与新结论矛盾的"事件账可重放 frontmatter"（我上一轮只改了一处）；
`known_instances` 可写成标量从而让成员判定退化成**子串匹配**、G9 整条失效；
跨行拆分仍能形成 catch-all → 改为要求**每条 glob 指名道姓**（而不是去检查全体行的并集
——一份完整台账的并集本来就该覆盖一切，拿它当判据是错的）。

### round-5 ~ round-7：又三轮，重点转向「契约是否真的强于台账自己的文字声明」

- **round-5**（两次被安全过滤拦掉，只从推理轨迹里捞回两条）：G11 的判定**顺序**有缺口
  （放在"无法归属则跳过"之后 → 未登记目录里的外逃链接永不判红）；以及我写的"拒读"断言
  **杀不掉 mutation**（fixture 里外部目标的 type 恰好在允许集内，去掉拒读它照样绿）。两条都已修。
- **round-6**（8 条窄声明全部属实、0 BLOCKER）：台账对 `节点/**` 一刀切声明"检索可见"，
  但**无 `type` 且含 `exam_question_id`** 的考察文件会被写侧推断为 exam_board 而被排除；
  以及**契约弱于台账自己的文字声明**（头部写了"id 唯一 / match 必填"，裁判却不查）。
- **round-7**：同类问题的更深一层 —— 那五个"允许无 type 且进索引"的条目同样在一刀切；
  id 唯一性没覆盖 repo_docs；普通行自报 `surface: store` 就能绕过 match 必填；
  `str(v).strip()` 的真值缺口**第三次**被抓到（这次是 `rag_retrieval_note`）。
  新加的契约规则上线后**当场把我自己的台账逼红**（`dir-raw`），这是它有效的最强证据。

一个值得记的教训：`str(value).strip()` 这个写法在三轮里被抓了三次。
前两次我修的都是"这几个字段"，直到第三次才抽出统一的 `_nonempty_str()`。
**正确的修法从第一次就该是换掉这个写法，而不是补上这个字段。**
