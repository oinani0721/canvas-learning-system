> [!info]+ 你不需要跑任何命令

### 变严的六处（每一处都先复现过、看见它确实能糊弄过去，才动手修）

## 二、这张卡的方法：先划域，再收紧

完成条件 (a) 要求**开工前书面裁定「数字治理域」，且按位置/结构划分、不按字符**。
裁定写在卡文 `§零`（Codex 按它审），并在复核后按实测**修订过一次**（见下）。

```
判定顺序：先剥豁免跨度（E1-E8，全部按结构判定）→ 再按所在段落判域
  E1 围栏代码块（CommonMark 全判据）   E5 Markdown 结构性数字（有序列表序号等）
  E2 行内代码跨度                     E6  无据行固定文案
  E3 wikilink 内部                    E6b SKILL 模板逐字常量（「最老 3 条原话」）
  E4 时间形态                         E7  范围表达（2~3 个）   E8 HTML 注释

  D1 强绑定域：frontmatter 绑定键 / 规模自陈 / 台账种子行绑 tips_count /
              AI 侧对账 tips 两数 / 四类信号行 → 绑到**具体对象**
  D2 有据叙述域：⛔ **默认全域**——报告的每一段都在域内，包括首个 `##` 之前的
              规模自陈 callout、以及任何新增/自造段落
              → 计数必须能在 scan JSON 的数值池找到同值
  D3 域外：**仅**「数据来源与新鲜度」一段（显式例外表）+ frontmatter 非绑定键
```

### ⛔ 域的定义被复核**推翻过一次**，这是本卡最重要的一次修正

初版 D2 写成 `("你现在可以做的", "三维审查")` ——**点名两段的允许式**。
Codex 判 HIGH，并逐条实测给出 exit 0：规模 callout 的「1 次调用」、台账派生行、
AI 侧对账段其余数字、`## 本段新增`、乃至**新开一个 `## 附录`**——全都在域外。

> **加一个标题就能逃出治理，那不是「域」，是几个段名 + 几条正则。**

⇒ 倒转成 **default-deny**：默认全域，例外**显式列表**（改动例外表要过一道专门的测试）。
这才是治理域裁定「按位置划分」的本意。

**为什么不按字符**：`_has_numeric` 维护「哪些汉字算数值」的字符表，两头都失守——
「仨/皕/零」绕过去，「一/十」误伤进来。改由**位置**承担后，生僻写法不需要被逐个枚举。

### 负验证的三条铁律（都来自踩过的坑）

1. **串行**——脚本原地改被测文件再还原，并发会让 B 的还原把 A 的 mutation 写回而测试照样全绿。脚本自带原子互斥锁，重入直接拒绝。
2. **变体禁掉该性质的全部防线**——只退化一层时纵深防御会让测试仍绿，从而误判「门非承重」去改本来正确的测试。
3. **还原后逐字节自检**——这道自检本身抓出过"还原不干净"。

### ⛔ 最后一处、也是最深的一处修正：D2 的判据换了

对抗审查第二路（误伤面）交出 **14 条、2 条 BLOCKER**，最要害的一条我复现后确认成立：

> **同一句合法叙述，在四块板上判决不同。**
> `你说「我做了 5 个练习」` / `第 4 条动作建议` / `有 5 处值得注意` ——
> 在 CS 61B、特征值、CS188 上放行，在「递归与分治」上 FAIL。

根因不是覆盖面，是**判据本身不可用**：「值落在 scan 数值池里 = 有出处」是个
**碰撞判据**。池里有 0/1/2/3 时，报告里几乎任何小计数都"碰巧有出处"；
而「递归与分治」的池只有 `[0,1]`，于是正常中文全被拒。
反过来它也解释了拦截力为何弱——能拦住的只有**大到不可能碰撞**的数，
而那恰恰是最不会被写出来的数。

⇒ **D2 从「查所有计数」收窄为「只查明确自称全板规模的句式」**
（`本板共有 N 个…` / `全板总共 N 条…` 这类），判据从**碰撞**换成**句式 + 值绑定**。
普通叙述（引用原话 / 序数 / 自指 / 同义量词 / 链接文本）不再被牵连。

**宁可少管，不可乱判**——一个会因为"另一块板恰好有没有那个数字"而改变结论的门，
比没有门更糟：它会在用户真实用板时随机炸。

验证：14 条构造 × 4 份 live 真报告，**判决全部一致且符合期望**
（6 条合法叙述全放行、8 条越界全拦下），并固化成
`test_audit_verdict_is_board_independent` / `test_audit_scale_claims_blocked_on_every_board`。

⚠️ 代价如实记：D2 的**覆盖面因此进一步收窄**——不自称全板规模的伪计数
（如「另有 987654 个隐藏节点」）现在不由 D2 管。这类位置归 D1 的逐字段绑定，
D1 未覆盖到的则留给人工判读。这是**有意的取舍**，写在这里供你裁定。
