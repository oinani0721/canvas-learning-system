## 一、你会看到什么变化（用户产品体验）

> [!info]+ 你不需要跑任何命令
> 下面说的都是你用 `/board-recap` 对多块板做阶段回顾时、**生成的那张检验白板上**的变化。
> 全部技术判据（测试、格式、回归）我已代跑，见 §二。

### 1. 「总批注」不再重复计数（M11）

`节点/` 是**一 vault 一学科的扁平共享池**——同一个概念节点被两块板同时列进 `## Concepts`
是正常形态（比如「递归」既属《排序》板也属《树》板）。对这样的多板做阶段回顾时：

| | 修复前 | 修复后 |
|---|---|---|
| 两块板共用 1 个节点，该节点有 1 条批注 | 覆盖 2 板 / 总成员 1（按节点去重）/ **总批注 2 条** | 覆盖 2 板 / 总成员 1（按节点去重）/ **总批注 1 条（同口径去重）** |

修复前那一行是**自相矛盾**的：成员只有 1 个，批注却有 2 条——同一个节点的同一条批注被数了两遍。
产物正文与 preview 回执两处都会错（它们原本各算各的，所以同一个错误出现了两遍）。

> 括号里新增的「同口径去重」四个字是有意加的：数字改对之后，你还需要知道它跟成员是**同一套
> 去重规则**算出来的，否则会以为总批注仍是各板相加。

**不受影响的**：每块板自己那一行的「批注 N 条」照旧（板内节点本就唯一，不存在重复）；
两块板各用各的节点时，总批注仍然是相加（有专门的反向测试钉着，防止「去重」被写成错误的聚合）。

**顺带加固的一个罕见情形**（Codex 复核当场用注入实验逼出来的）：如果你**正好在它取数的那几秒里
改了某个节点的批注**，两块板会读到不同的值。现在它会**直接拒绝**，不给你任何数字：

```text
取数期间下列节点的批注数发生变化 (各板读到不同值), 本次数字不可信: NodeShared (共 1 个; 请重跑 preview)
```

这里的取舍被复核连推了三步，如实记下来：先是「取先读到的值 + 产物多一行警告」，
实测发现那个总数**依赖你在 `--boards` 里写板的顺序**（`A B` 得 1、`B A` 得 2）⇒ 改成拒绝；
拒绝之后各板明细里的数字仍在发，而它们同样随顺序变（240 块板实测有 125 块的
「种子/派生」会交换）⇒ 最终收成一句干净的规则：**这次取数不可信，就一个数字都不给你**，
只告诉你是哪块板、哪个节点出的问题。重跑一次即可。

（正常情况下你永远不会看到这句话；一致态、单板、空板、幽灵链接、板内重复各有反向测试钉着，
产物字节与加固前完全一致。）

### 2. 怪板名不再产出坏掉的检验白板（M7）

有些字符肉眼完全看不见，但会从别处复制粘贴带进板名（`U+007F` DEL、`U+0085` 下一行符等）。
本卡开工前**实测复现**了它们的后果：

| 板名里混进 | 修复前的后果 | 修复后 |
|---|---|---|
| `U+007F` | 生成的检验白板 YAML 解析失败 → 整张板从 Dashboard/统计里**消失**（记 `file_parse_failed`） | preview 直接拒绝，`检验白板/` 零新增 |
| `U+0085` | 板归属断裂 → 统计里这张板的「属于哪块原白板」变成**空白**，而且**不报错**（静默错更难发现） | 同上 |

拒绝时你会看到具体是哪个字符，例如：

```text
以下板不存在或板名非法: ['板\x85乙'] (create 将拒绝) — 板名含不可用于 YAML/行级解析的字符 U+0085
```

点名码位这一点是必要的：这些字符在编辑器里看不见，只说「板名非法」你无从知道改哪里。

**不受影响的**（有专门的放行测试钉着，各一条）：中文板名、带空格和数字的
`CS 61B 第 3 周`、带连字符的 `线性代数-复习`、全角括号 `Lecture 14（补）`、
下划线与点 `板_一.v2`、带圈数字 `第①章`，以及 emoji、重音字母、不换行空格（NBSP）——
全部照常可用。这一半和拦截同等重要：round-5 在同一个文件上翻过一次车，
教训是「多禁一点」的每一步都会同时抬高误伤面，而误伤在测试里不会自己变红，只会在你真实用板时炸。

## 三、改了什么（实现要点）

### M11 — 把两份拷贝收成一个口径

同型错误出现两遍（产物正文 + preview 回执），根因是**聚合算法有两份拷贝**。
所以修法不是各改一处，而是新增 `_cross_board_totals()` 作为跨板聚合的**唯一口径**，
两个消费点都改走它。

- 只上抛 `{node_id: 批注数}` 纯计数映射，**不上抛 ledger 行**——ledger 含正文派生字段，
  扩大它的传播面会顶到本脚本「产物零正文」的核心约束。
- 同 node_id 在不同板上的批注数正常必然相同（同一个节点文件读出来的），唯一例外是**取数期间
  文件被改**。这一档走 `_tips_conflict_refusal()` **fail-closed**：preview 与 create 各自
  独立检查、各自拒绝，不发布任何总数、不产出 content。
  ⚠ 这里改过一次方向：最初是「取首现值 + 产物警告行」，复核者实测该总数**顺序相关**
  （`--boards A B` 得 1、`B A` 得 2）⇒ 不该发布。`max`/`min`/`sum` 都不是正确替代——
  正确语义是「这次的数不可信」。create 侧**独立再查一次**而非只信 preview：两者是两次
  独立扫描，且 direct create 根本不经过 preview。

### M7 — 一处判定 + 一处诊断

- 判定：`recap_scan.unsafe_name_chars()`（新增），拒绝集 = C0 + DEL + C1 + U+2028/U+2029；
  `_contained_md` 用它（承重防线，节点名与板名共用）。
- 诊断：`recap_exam_build._scan_board` 用同一份判据生成**点名码位**的拒绝原因，
  并把逐板原因带到**顶层** `refusal_reason`（skill 转告的就是那一句）。
- ⚠ 两类字符的证据等级**如实分列**，没有混称「均已实证」：U+007F / U+0085 / C1 是实测症状驱动；
  U+2028 / U+2029 **无实测症状**（当前 PyYAML 容忍），列入是因为 Python `str.splitlines()`
  会在它们处分行而本脚本全是行级解析，属**预防性**拒绝、误伤面为零。

### 不越界的声明

- Unicode 归一化（NFC/NFD）属 **CARD-G5-3** 的稳定 ID 面，本卡**未触碰**。两者互不覆盖：
  归一化解决「同一板名的两种编码形式」，本卡解决「这个字符根本不能进 YAML/行级解析」。
- `recap_scan.py` 的 **verifier**（`_verify_numbers` 及其正则族）是**维护卡 B** 的地盘，
  本卡**未碰**——本卡在 `recap_scan.py` 只改了 `_contained_md` 的字符判据（containment 面）。
  可由 `git diff` 逐 hunk 核验。

### 三轮的共同形态（值得记下来）

三轮都不是发现「算错了」，而是发现**声明的范围超过了实际做到的范围**：
docstring 说会「在产物与回执里显式声明」而实际是拒绝、测试注释说「一个都不许发布」
而断言只查顶层、代码注释说「结构信息不随取数顺序变」而它只在文件不变时成立。
修复本身每次都只有几行，**找出边界在哪**才是三轮审查真正的产出。

### ⚠ round-1 期间的代码漂移（如实记录时间线）

round-1 **不是**对静止快照的审查——Codex 读实时文件，我边审边改了三处：
① 顶层 `refusal_reason` 带上码位（自查发现诊断只落在 boards 明细里）；
② 竞态冲突不再静默（**看到它的注入实验输出**后主动加固）；③ `ruff format`。
它后段的核对已覆盖这些改动（自己标注了 "Planning rerun after formatting changes"），
但报告前段针对早期状态的判断可能已过期。round-2/3 的审阅对象则是稳定快照。

### 我自己犯的两个错（不是审查发现的，是测试当场抓住的）

1. 把组合态补句写成 `if/elif` 链**中间**的一个 `if`，直接把渲染 `else` 挂错到它身上
   （「有缺板但无冲突」也会去渲染）——Python 对此没有语法提示，是**既有的老测试**抓红的。
2. `_cross_board_totals` 在冲突检查提前后没容下「板不存在」的板，`KeyError: member_ids`
   ——同样是既有测试抓的。
