## A2 锚：空 key 是**故意的**，塞 key = 毁负控

```python
# test_sync_exception_classification.py:48-58

    """Dev-mode settings so the auth dependency lets the request through."""
    return Settings(..., DEBUG=True, ..., INTERNAL_API_KEY="")
```

docstring 逐字如卡文所述。`c9bb6c9a` 之前「DEBUG=True + 空 key」会放行；
之后改成 fail-closed（要 `ALLOW_UNSAFE_DEV_AUTH_BYPASS=true` **且** loopback），
于是这 9 条全部撞 503。

其中 3 条的失败身份是 assert 而非 503：
`assert 'Internal API...loopback dev.' == 'Neo4j unavailable'`
⇒ **状态码仍是 503，但 503 的来源变了** —— 测试想验的是「Neo4j 不可用时返回 503」，
现在先被 auth 拦下，503 的 detail 换了人。

> ### ⛔ 上面这段被分诊 agent 推翻了一半，如实更正
>
> 我（和卡文 §〇.16）把这 9 条整体读成「有意的空 key 负控，塞 key = 毁负控」。

> **嫌疑 commit 须更正为 `f718d040`（2026-05-08）**，不是卡文点名的

> **本次运行全部 PASSED**（日志 25255/25303/25307 行）—— **根本不在红基线里**。
