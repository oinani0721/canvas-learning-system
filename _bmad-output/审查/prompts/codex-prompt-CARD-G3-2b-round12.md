# 复核请求：一个本地笔记工具的「先记日志、后改文件」一致性实现（第十次有结论的复核）

你是独立代码复核者。请复核一个**单机离线学习笔记工具**的一致性实现，并按末尾格式给出结论。

## 背景（三句话）

用户在 Obsidian 里给自己的笔记做自测评分。评分结果要写两处：一份追加式的 JSON Lines 日志（`learning_events.jsonl`），和笔记文件头部的 YAML 字段（记录下次复习时间、掌握度、已考次数等）。实现采用「先把事件追加进日志、再改笔记」的顺序，这样程序中途退出时，下次运行可以从日志把没做完的那一步补上。

**要复核的问题只有一个**：在「程序中途退出 / 用户重跑同一次评分 / 日志被别的程序写坏」这三种情况下，会不会**漏算一次评分**，或者**把同一次评分算两遍**。

这是个人学习工具，没有网络接口、没有多用户、不处理任何凭据。

## 本次改动的完整规则清单（请判断是否正确且完整）

1. 日志行与本次评分是否「同一件事」，比较一个固定 8 键的信封，candidate 侧**独立构造**，不从日志行复制任何键；两个记录环境快照的键明确排除在外。
2. 日志行的时刻必须是 canonical 整秒 UTC（复用校验器本体的正则再叠加 UTC 偏移为 0），不合规就停下，**不做归一化**。
3. 「这是第几次评分」的序数从日志边界回推，不取笔记的当前值；同步时按「校准记录里有没有这次评分」分支算出**可证的期望值**，不符即停（不取两者较大值）。
4. 正常写入与崩溃恢复两条路径的产物逐字节相同（业务时刻与业务分数都取日志行里的值，不取本次重试的输入）。
5. 日志行的评分档位必须**存在**且与分数自洽，缺失或类型不对就在应用前停下。
6. 上述裁决已回写规格 §6.2。
7. 判断「日志最后一行是被腰斩的半行」的依据是：**最后一个非空行**后面有没有换行符（不是文件末尾有没有）。
8. 标了「乱序」的行，其时刻必须不晚于水位线；该键只接受布尔 `true`。
9. 日志按**字节**切行再逐行解码（首行剥 BOM）；解码失败的末行且无终止换行按截断容忍，其余停下。
10. 一行 JSON 里出现重复键就停下。
11. 同时存在多个「已入日志未应用」事件时停下（正常路径下不会出现）。
12. 六种状态（日志有无该事件 × 笔记是否已记录 × 时刻是否已过水位线）逐一有测试覆盖。
13. 校验器负责拦下写入端管不着的行；而**缺少可用的 `node_id`** 属于「无法判定归属」，写入端必须自己停下。
14. 重放**别人的**事件时逐项复放掌握度/上次复习时间/校准记录/已考次数；**本次事件自己不在此列**。
15. 已在「降级模式」下落过账的事件被重放时**不得**再算一次掌握度——判据是「校准记录里有没有它」。
16. 时刻不晚于水位线、未标「乱序」、且校准记录里没有它的行，一律停下。
17. 幂等键首尾含空白就停下（不静默去空白）。
18. 事件类型必须是两种评分事件之一；概念标识必须等于笔记标识；库标识必须等于本库。
19. 本笔记的行若带着复习扩展标记却不是合法值，不得当历史行跳过。
20. **本次新增**：消费本笔记的一条日志行**之前**，先调校验器本体的 `validate_record_full()`；有违规就停下。在它之上再叠加 1–19 里更严的几条。顶层不是 JSON object 的行停下；归属判断排在「缺 payload 就跳过」**之前**（本笔记的行缺 payload 时它仍可能是一次真实评分）；但**别的笔记**的不合规行不得阻塞本次写入。

21. **本次新增**：判断「这次评分是否已应用」一律用**完整** id；剥前缀形态只在能证明映射唯一时作为历史兼容回落，两种形态的 id 并存时**停下**（猜一个就会让另一个静默不入账）。
22. **本次新增**：本次输入的时刻按**字面**校验（复用校验器的受理正则）且**拒而不洗**——它会被原样写进日志，洗值等于程序自己产出不合规的行。

23. **本次新增**：判断「后续事件是否已计入次数」用**校准记录**，不用「时刻是否过了水位线」——降级落账那条路径会写次数与校准却不写水位线，两者会分道。
24. **本次新增**：历史行的序数优先用**日志自身能证明的**值回推（日志是追加式的，行号即写序；某行的次数 = 写它时笔记里的值 + 1）；证不出来才停，且拒绝理由要指名哪几行缺什么。

25. **本次新增**：比较用的候选记录，其业务时刻取自**本次输入里的稳定值**（评分那一步记一次、续跑只读不重取），不抄日志行里的值。⚠️ 也不能直接用「本次运行的时刻」——那个每次续跑都会变，会让真实续跑也报冲突。
26. **本次新增**：序数证明跨过 k 条「会推进次数但证不出推进了几次」的行时，回推值要相应折算；有证不出的间隙就停，不猜。

27. **本次新增**：三个时刻各司其职（见上表）；比较「同一件事」用**原始稳定时刻**，缺它就停下，**不回抄日志里的值**。
28. **本次新增**：无标记的历史行上出现「乱序」同名键不具契约语义；校准记录解析容 YAML 尾注释；ID 空白拒绝只管本笔记的行。

29. **本次新增**：日志 ID 全局唯一 —— 同键异主/异型一律停下；追加前对整条新记录跑校验器自检；校准记录用真正的 YAML 解析器读。
30. **本次新增**：校准记录必须绑定「同一次评分」的四项可证事实（完整 ID / 原始稳定时刻 / 次数序号 / 分数）；日志行丢失时拿它逐项比对，对不上就停。

31. **本次新增**：归属比较一律走统一的归一化键（六处）；校准记录按六类事实逐项严格校验；唯一性证据不含本次待判定的 ID。
32. **本次新增**：日志里的**调度采用时刻**由校准记录绑定；日志行丢失时还要证明水位线已覆盖它；校准写回结构化并在落账前预演。

33. **本次新增**：候选 token 与来源反查只有**一份实现**（`_cands_and_sources`），
两个消费方共用；两者严格度的差异是**显式声明**的，不是分叉遗留。

## 关于「正常与恢复逐字节相同」的范围（上次 MEDIUM，已按你的建议收窄表述）
