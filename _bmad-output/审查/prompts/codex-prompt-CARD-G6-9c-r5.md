## 二 整改自述（请独立核对，不要采信）

**HIGH-1（根治 = 不再包装 libc）**：`_SystemLocalTZ` 整个删除。POSIX TZ 串改为
**规格驱动**：`parse_posix_tz` 解析 POSIX 语法（`Mm.w.d` / `Jn` / `n`，切换时刻缺省
02:00:00，`<引用名>`，偏移西为正取负），`_PosixTZ(tzinfo)` 按规则**逐时刻**判定：
- `fromutc`：epoch → 规则窗口判定 → 墙钟 + fold（第二次出现 = std 侧探测
  `ts − (dst−std)` 仍落 DST 窗口）；只走 epoch 算术，不经 `mktime`。
- `utcoffset(dt)`：对墙钟做 DST/STD 双候选窗口验证（d_ok = 墙钟按 DST 偏移解释落在

  POSIX 串 → 垃圾/空串 = UTC。
开发中另修掉三处实现 bug（都有教训注释）：Py3.14 aware `timetuple()` 经 tz 协议取

## 二·补 送审前我自己又抓出的三个缺陷（已改，请一并核）

跑完全部裁判后，我拿本文件第三节**自己列给你的问题**反过来查自己，用两个探针（与 C 库
逐分钟对照、fold 契约直接断言）抓出三个真缺陷。三个都属于「已有的门在**结构上**看不见」：

1. **POSIX 缺省切换时刻写成当地 02:02（规格是 02:00）**，切换后头两分钟的墙钟比 C 库
   慢一档。原门 ⑦ 的 9 个探针全是整点/半点，`[02:00, 02:02)` 一格都踩不到——上面自述的
   「238 组全绿」当时就带着这个缺陷。已改正，补「切换点前后逐分钟扫描」门（3 组 × 2 副本）。
2. **折叠/空缺的选侧按夏令时身份写死**，在标准侧偏移更大的规格（`IST-1GMT0,M10.5.0,M3.5.0/1`）
   上 fold 语义整个颠倒。墙钟扫描只测 `fromutc`（epoch→墙钟），而空缺时段没有 epoch 映射
   过去，结构上测不到 `utcoffset` 对折叠/空缺墙钟的选侧；时刻守恒也测不到，因为 fold 是
   `fromutc` 自己写的。已改为按**偏移大小**选侧（折叠取较大 = 先发生，空缺取较小 = 切换前），
   补 fold 契约门（3 规格 × 2 副本）。该门**不与 C 库对照**——C 库对折叠墙钟取哪侧是实现
   定义的，判据用的是 Python 自己的 fold 契约。
3. **`Jn`（1..365）与裸 `n`（0..365）共用一个取值域**，放行了 C 库拒收的 `J0`。原门里
   没有任何「该被拒绝」方向的用例。已按规格分开，补取舍表门（10 串 × 2 副本，接受/拒绝两侧都有）。

**另有一处与 C 库有意分歧、登记不跟**：`TZ=AB3`（两字母简名）C 库给 UTC-3，本实现按 POSIX
（简名 ≥ 3 字符）拒收 ⇒ 回落 UTC，归日差 3 小时。整条路线是规格驱动而非包装 C 库，此处站规格。
请判断这个取舍是否可接受，以及**还有没有别的地方我站规格站错了**。
