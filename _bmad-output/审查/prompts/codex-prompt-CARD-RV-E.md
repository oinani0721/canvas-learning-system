## 二、这段脚本是什么 + 作者自述（请独立核对，**不要采信**）

`lefthook.yml:286-334` 的 `mutant-residue-scan` 是一道提交前检查：它枚举**暂存区里
新增/修改**的文件，对每个文件取 `git diff --cached -U0`，用 awk 在**新增行**里找一个
运行时拼出来的标记串。找到就打印文件:行号并 `exit 1`（阻断提交），没找到就打印
`[Mutant-Scan] OK` 并 `exit 0`。它的用途是拦住「变异测试脚本改完生产文件没还原干净
就被提交」这一类事故。块自称按 fail-closed 设计。

`870e52b3` 这次改动，作者声称补了**六处**「本该拦下却静默放行」的输入路径。作者的
自述表（**待你核对**）：

| # | 补法 | 现行行号 | 作者声称拦下的是什么输入 |
|---|---|---|---|
| ① | `--name-only … -z` + `tr '\000' '\n'` | :294-295、:298 | 文件名含 `"` / `\` / TAB 时，旧写法输出被 C 引号化，拿去当 pathspec 匹配不到，于是该文件整个跳过 |
| ② | `--literal-pathspecs` | :308 | 文件名含 `*` `?` `:` 时被当成 pathspec 通配/魔法前缀解释 |
| ③ | `--no-color`（diff 的**标志**，不是 `-c color.ui=never`） | :294、:308 | git 配置开了强制着色时，diff 行带 ANSI 前缀，awk 的 `/^\+/` 不再命中 |
