没有网络接口、没有多用户、不处理任何凭据。

## 背景（三句话）

用户在 Obsidian 里让 AI 生成学习白板的「回顾报告」。报告里出现的计数
（「本板共有 N 个子节点」这类）必须能在扫描结果 JSON 里找到同值来源，
否则校验器报错、报告打回重写。目的是**防止 AI 在报告里编造数字**。

要复核的问题只有一个：**校验器读到的数，与用户在 Obsidian 里渲染后看到的数，
是不是同一个**。

## 距上一轮之后发生了什么（两轮，都请复核）

### round-35：一处 BLOCKER 修复（分隔符「第三态」）

千分位归一 `_normalize_number_seps` 的前瞻原为 `(?=[0-9]{3}(?![0-9]))`
（「恰好三位分组」）。于是 `987654,0` 里的逗号落进**第三态**：
既不被归一删掉、也不算连接字符 ⇒ 成为**硬断点** ⇒ 取数正则从断点后**重新起锚**，
只看见尾片 `0`，而 **0 恒在池内**（`abs(a-a)`）⇒ 整条放行。

修：前瞻收窄为 `(?=[0-9])`，分隔符只剩「删」与「不是分隔符」两态。
实测 `987654,0` / `987654，0` / `987654'0` / `1,05` 全部拦截，
合法千分位 `987654,000` 未误伤。配 `r29` 行为门 + `survivor-66` 变体。

### round-36：变异脚本的判据从 `-k` 改为 nodeid 绑定

**这正是你连续多轮点名、我一直登记「未改」的那条**：
「`-k` 只确认匹配集合里有失败，不证明是指定的那道门失败」。

实测 66 条变体里 **12 条**的 `-k` 解析到 2–9 个用例（最多 9 个）。
现改为：新增 `DESIGNATED` 冻结表（66 变体 → 73 个精确 nodeid），
判据为「跑**恰好**指名的 nodeid，要求 `collected == failed == len(指名)`」——
**每一个指定门都必须死**。指名来源两类，**都不从行为反推**：
54 条是原 `-k` 本就唯一解析到的那个 nodeid（机械解析）；
12 条是读变体自述禁掉的**性质**后人工指名。
预检加 fail-closed：键集须与变体 id 集完全相等，每个 nodeid 须真实存在。

判据本身已用同一变异体三态验伪：指名对的门 ✅1/1 · 指名不相干的门 ❌ ·
**指名 2 个只死 1 个 ❌**（第三态是那 12 条多指名变体真正依赖的分支）。

### round-36 另修：SIGTERM 不做栈展开 ⇒ `finally` 的还原不跑

变异脚本原地改生产文件再还原。我把它挂在有超时的前台跑，超时发 SIGTERM，
**默认处置当场终止、不做栈展开**，`finally` 的还原一行没跑，
**变异体留在了生产文件里**（脚本自身零信号，靠 `git status` 才发现）。
已装 SIGTERM/SIGINT handler 转异常，并用负控证明它承重
（禁掉 handler → 变异体**和锁**双残留；handler 在位 → 两者都清）。
