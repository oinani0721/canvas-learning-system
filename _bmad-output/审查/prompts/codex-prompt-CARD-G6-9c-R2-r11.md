### 三条有意收紧（M6 / M7 / M8）——如实登记，不修

这三条现在都写进了接受域表的「⚠️分歧」栏，**每条都要求依据栏说清取舍**，
门会强制检查这一点（`why.startswith("⚠️分歧")`）：

- **M6 非 UTF-8**：不可严格 UTF-8 编码的规格串整个不接受。理由是 `.key` 会进 API 响应，
  本卡 r5→r6 在这里栽过两次（先是严格 encode 让模块级启动校验抛，再是 `surrogateescape`
  把失败挪到响应出口——修复只是移位）。
- **M7 偏移可表示性**：`|std_off| ≥ 24h` 与「两侧之差 ≥ 24h」都拒。前者是 Python `tzinfo`
  的硬限制（接受了 `utcoffset()` 会抛），后者是 `dst()` / `timetuple()` 会抛。
  退 UTC 是可预测的降级，运行时抛不是。
- **M8 年份**：省略规则族的对齐作用域是 2007..2037（C 库那张 32 位表的边界），已在注释里
  写清这只对该族成立。

## 二 本轮最重要的改动：判据从「手写样本」换成「组合枚举」

你 r10 的 M1/M2/M3 有一个共同根因——**判据面是手写的 22 条样本**。

**这道门有两个阶段**，因为本轮负控实测发现只比「收不收」是不够的：

- **阶段一·接受域**：误收（本实现收 / C 库拒）硬性 **0**；
  误拒必须逐条落在 `_declared_narrowing()` 这个**可执行**的声明判据里，
  出现任何一条声明外的误拒就红。
- **阶段二·换算结果**：对两边**都接受**的串逐时刻比 `utcoffset()`（54040 个「串 × 时刻」点）。
