## §四 两种口径各得多少、按哪一种判、为什么

| 口径 | 定义 | 得数 | 采信？ |
|---|---|---|---|
| **口径 A**（census §0.1，本卡采信） | 排除所有权模块 `review_service.py` 后，仓内非测试非文档、且（直接读写 JSON/`_card_states` **或** 经所有权模块公开 API 间接消费 **或** 发 `GET /review/fsrs-state`、`PUT /review/record`）的文件 | **N = 1**（`review.py`） | ✅ **按这一种判** |
| 口径 B（卡文 (b) 括注转述的勘探时点实测） | 只在 `frontend/obsidian-plugin/src` / `canvas-vault/.claude` / `scripts` 三个目录搜 `fsrs_card_states\|_card_states\|fsrs-state` 三个字符串 | **0** | ❌ 不用于判 N，理由见下 |

**为什么按口径 A 判（三条，逐条可证）**：

1. **卡文 (b) 的两个「重算触发条款」都不命中**。卡文原文：「若 U9-B 交来的 census 表口径**含所有权模块自身**（或**只量了 `fsrs_card_states` 一个面**、没量 `_card_states` 与 `fsrs-state`），先按本条口径重算」。实测：census §0.1 第 1 条逐字排除了所有权模块（§0.2 整节论证「若不排除则 N 恒 ≥ 1，U9-C『N=0 ⇒ 乙』字面不可达」——与卡文担忧同源）；§0.4 量了①`fsrs_card_states`②`_card_states`③`fsrs-state`三面并集 + §0.5 面④ AST 公开方法调用，共四面。⇒ 无需重算，census 的 N 直接可用。

2. **口径 B 的 0 与口径 A 的 1 在事实层面不矛盾，因为它们量的是不相交的两块地**。口径 A 的那个 1 = `backend/app/api/v1/endpoints/review.py`，**不在**口径 B 的三个目录中的任何一个。

   口径 B 还有一个更根本的问题：它用**字符串命中**代替**调用关系**，两个方向都不可靠 ——
   - **会漏**：`await review_service.get_fsrs_state(...)` 这类调用表达式本身不含那三个字符串（census §0.5 原话：「一句 `await svc.get_fsrs_state(cid)` 不含这三个串中的任何一个」），封装越好漏得越多；
   - **会误**：`review.py:1383` 的路由字面量确实含 `fsrs-state`，`review_service.py` 更大量含另外两串 —— 命中它们不等于判出了「谁在消费这份状态」，命中的可能只是路由声明、常量定义或注释。

   > ⚠️ **两次更正记录**：
   > - **Codex r1 LOW-1**：本节初版写过「即便把口径 B 的检索原样搬到 `backend/app` 上跑，也照样 0 命中」——**直接错误**，已删（`review.py:1383` 就命中）。
   > - **Codex r3 L1**：第一次更正只加了限定块，主句仍写着「字符串命中的做法在 review.py 上判不出它是消费方」——这句**同样过强**（字符串命中能命中该文件，只是命中的不是调用关系），已按上面的「会漏 / 会误」两条改写。教训：更正一处过强断言时，必须把**主句本身**改掉；只在旁边加限定块，等于让两个相反的说法并存。

   ⇒ 口径 B 的 0 是「搜索面收窄（不含 `backend/app`）+ 判据错配（字符串命中 ≠ 调用关系）」的产物，**不是「消费方为零」的证明**，不构成对 N=1 的反驳。

3. **「只认直接触碰」这个更窄的口径已被 U9-B 的 Codex round-1 HIGH-1 显式打回过**。census §0.3 撤回声明：初版曾写「若只认直接触碰 ⇒ N 恒等于 0」，该句已删，理由是「只认直接触碰会**系统性地漏掉经公开 API 的消费**，封装越好漏得越多」。本卡若为走乙而重新捡起这个被否掉的口径当判据，等于把审查已打回的东西写回正式依据。

**「review.py 计入会不会让 N 恒 ≥ 1、把乙支变成不可达？」——不会**。census §0.2 排除所有权模块的理由是「它**持有**这份状态」（持有字典 `:526`、文件常量 `:117`、锁 `:121`）；review.py **不持有**，它只是调用者。若某天端点层不再暴露 FSRS 状态（端点下线、或改为不触碰这份投影），review.py 即不再命中、N 会掉到 0。census §0.3 末段亦明写「两条排除规则同时在，N 才既能取到 0、也能取到非 0」。⇒ 乙支在口径 A 下**在定义上可达**，本次只是没取到 0。

> ⚠️ **限定（Codex r1 LOW-1）**：「可达」是就**定义**而言 —— 需要所有非所有权消费方都消失才能取到 0。它**不能**靠「当前没有客户端流量」达成：现存的端点消费方是静态调用关系，没人调用它也仍然计数。本卡未证明、也无需证明「实际有多少请求在走这条链」。
