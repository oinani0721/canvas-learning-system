## §0 口径定义（写死，先于取数）

### 0.1 「在线消费方」的定义

一个文件计入**在线消费方**，当且仅当同时满足：

1. **不是** `backend/app/services/review_service.py`（**所有权模块**，见 §0.2）；
2. 在仓内、且**不是**测试（`backend/tests/**`）、**不是**文档（`docs/**` / `*.story.md` / `openspec/**` / `CURRENT_TASK.md` / `.gdr/**`）；
3. 并且满足下面任一行为：
   - 读或写 `backend/data/fsrs_card_states.json`，或读或写它的内存镜像 `_card_states`（**含**经所有权模块的公开 API 间接读写，见 §0.3）；
   - 发起 `GET /review/fsrs-state` 或 `PUT /review/record` 请求。
4. **不计**：`_CARD_STATES_FILE` 常量定义本身；纯注释 / docstring 锚点；仅声明响应模型形状而不触碰状态的 schema 定义；由工具生成的产物（`openapi.json`）；配置文件（`.gitignore`）。

### 0.2 为什么必须排除所有权模块 `review_service.py`

`review_service.py` 自己就**持有**这份状态：它写 `_card_states`（`:598` / `:620`）、读它（`:1096` / `:1274` / `:2358` / `:2360` / `:2469` / `:2414`）、定义文件常量（`:117`）、定义锁（`:121`）。它是**持有者**不是消费方。

若不排除，则 **N 恒 ≥ 1**，于是 U9-C (b) 的「N = 0 ⇒ 走乙支」这条分支**字面不可达**，D-23 的默认分支会被一句措辞推翻。排除它是这份数字**能不能判**的前提，不是取巧。

### 0.3 为什么「间接经所有权模块 API 读写」也算（与 0.2 对称的另一头）

所以判据取「**消费这份状态**」的语义：调用所有权模块的公开方法拿到由 `_card_states` 派生的数据、或触发它的写入，即算消费。实测中受此条影响的只有 `review.py` 一个文件（§一）。

> **⚠️ 撤回（Codex round-1 HIGH-1，r2 LOW-5 清理）**：本节初版的一句「若只认直接触碰 ⇒ N 恒等于 0」是错的，原句已删——即便只认直接触碰，非所有权模块仍可以直接读文件或发 HTTP 请求。即便只认「直接触碰」，一个非所有权模块仍可以直接读 `backend/data/fsrs_card_states.json` 这个文件、或直接发 HTTP 请求，两者都满足定义。正确的说法是：只认直接触碰会**系统性地漏掉经公开 API 的消费**（封装越好漏得越多），而不是让 N 恒为零。
>
> **两条排除规则的作用**：§0.2 防止 N 因所有权模块自身而恒 ≥1（否则乙支不可达）；§0.3 防止 N 漏掉经 API 的消费方。两条同时在，N 才既能取到 0、也能取到非 0。

## §七 不可证边界（本 census 覆盖不到的面）

同 `_bmad-output/审查/evidence-g37/decision.md:32` 口径。以下一律是**「本 census 没看见」，不得读成「不存在」**：

1. **仓外调用者**：不在本仓的任何客户端（他人脚本、Obsidian 社区插件、curl、Postman、别的服务）都不在扫描面内。
2. **运行期拼出的 URL**：形如 `base + "/review/" + name` 的字符串拼接，静态 grep `fsrs-state` / `review/record` 看不见。
3. **反射 / 动态调用**：`getattr(svc, "save_card_state")` / `globals()[...]` 一类调用，本 census 与本卡的退役判据（静态 grep）都看不见。
4. **未纳入本仓的分支 / worktree**：本表只在 `card-u9-mastery` @ `8f7440ef` 一棵树上实测；其他车道树、未合入分支上的新增消费方不在面内。
5. **计数单位**：N/M/K 是**文件数**。改按调用点、按函数、按端点计数都会得到不同的数——下游引用本表前必须先对齐单位。
6. **时效**：本表是 2026-09-08 07:39 CST 于 `8f7440ef` 的**快照**，不是不变量。主干前进后复用本表前须重测（引用的历史数字会过期）。
7. **面④ 自身的残余盲区**（Codex round-1 HIGH-1 促成本节）：§0.5 的三步法覆盖「AST 能枚举出的方法 × 静态可见的调用点 × 全仓 tracked 文件的方法名扫描」。它**看不到**：
   - 反射 / 动态派发调用（`getattr(svc, name)()`、字符串路由表、插件式注册）；
   - 通过别名或包装器转调（`f = svc.get_fsrs_state` 后在别处 `f()`，若赋值与调用不在同一静态可达面内）；
   - 继承或猴子补丁引入的新调用方。
   - r2 MEDIUM-3 已补第三步（仓内其余代码面逐方法扫描，全 0 命中带正控），但**仓外**（不在本 git 仓库的代码）仍不在任何一步的覆盖内；
   因此 **N = 1 的正确读法是「在 §0.5 三步法（AST 枚举 × 逐方法调用点 × 全仓方法名扫描）的覆盖面内，发现且仅发现 1 个」**，而不是「已证明总数就是 1」。本表未发现第二个消费方，**不等于**已证明第二个不存在。
