## 一、三条 HIGH 性质不同，但都值得修

### HIGH-1 —— 产品行为错误：3B 只修了一半

round-7 的 3B 我把 `unlink` 的 `FileNotFoundError` 归了 `absent`，
**但回读块仍被宽泛的 `except OSError` 兜住**。可达路径：

```
lstat 成功 → 并发者删除文件 → os.open 抛 FileNotFoundError
→ 归 kept → 回执「撤销结果未确认…目标可能仍在」，而它已经不存在
```

第三调用点传的正是 `expect_sha`，所以这条路径**实际可达**。
⇒ 回读块单列 `FileNotFoundError → ("absent", None)`。承重变体 **AF**。

> 教训：**同一个修法要施加到同一语义的所有出现处**。
> 我改 `unlink` 时没有回头看还有哪些地方在做同类判断。

### HIGH-3 —— ⛔ 我 round-7 加的自检门是**循环论证**

```python
ran = 0
for ... in VARIANTS:
    ran += 1              # ← 在 mutation 校验与 pytest 执行**之前**
...
declared = len(VARIANTS)  # ← 期望值取自**被检对象本身**
if declared != ran: ...
```

两个致命缺陷：
1. 再误删 W/X 时，`len(VARIANTS)` 与 `ran` **一起减少**，仍显示「一致」；
2. mutation 未命中、pytest 根本没跑，也已计入「实跑」。

**它抓不到它本该抓的那个失败。**

修法（三条独立判据）：
- `EXPECTED_NAMES` 改为**独立冻结的常量**，不由 `VARIANTS` 推导；
- `executed_names` 只在 pytest **真的返回**之后才追加；
- 校验「冻结期望 / 定义集合 / 实跑集合」三者完全一致 + 变体名唯一性。

**并且这次做了验伪**（上一轮正是漏了这步）：手工模拟误删变体 X，
新门精确报出 `定义 30 / 冻结期望 31 / 缺失 ['X']`；旧门在同场景下显示「一致」。

> **任何自检的期望值都必须有独立来源**，否则它只是把断言写得像门。
> 加了门却不验它，就是我这两轮连续犯的错。

### HIGH-2 —— 归因完整性：本可移交，评估后选择做掉

复核者指出 12 格「调用点 × 状态」矩阵只有 2 格明确承重：
共享 helper 变异只能证明**状态生产端**，不能证明三个调用点**分别正确消费**四态。

这属于停轮规则理由里引用 G3-1 的那句
「发现性质已从**产品缺陷**转为**验证工装的归因完整性**」——按规则本可结案移交。

**本卡的选择是先评估工作量再决定**：12 格各一条注入式测试（固定
`_rollback_published` 返回指定状态，断言该调用点的可观察行为），代价可接受；
且它确实堵住「某调用点误消费某状态而无门察觉」的真实缺口。⇒ **做掉，不移交。**

新增两个参数化矩阵门：`test_matrix_callsite1_2_consumes_each_state`（①②共 8 格）
与 `test_matrix_callsite3_consumes_each_state`（③ 4 格），承重变体 **AG/AH**。
