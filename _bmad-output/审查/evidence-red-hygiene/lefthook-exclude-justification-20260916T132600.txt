二、spec-sync-root —— 跳过依据：本卡不改变 OpenAPI 面
================================================================================

lefthook.yml:62-73 的 glob 是 `backend/app/{main.py,config.py}`，本卡改了 config.py，
于是该 hook 会重生成并 `git add backend/openapi.json`，使 commit 出现第 7 个文件
（本卡地盘只有 6 个）= 地盘越界。

实测该重生成对快照的实际影响：

  跑前 sha256 = 1455eb7dc5d46bbdb14aba984ef9c08991b3ffe250a8638c532eb491c56e4764
  跑后 sha256 = f6c939d4e3f3b3881e10a674e38e40dd0a3dbaf1456c249c2c4c60df13617849
  脚本自报    = WROTE: backend/openapi.json (paths=197 schemas=357, ...)
  git diff --stat 实数 = 1 file changed, 1 insertion(+), 1 deletion(-)
  唯一变动行  = "x-generated-at" 时间戳

  ⇒ paths=197 / schemas=357 与快照内既有值一致，API 面零变化
    （本卡删的是 Settings 的两个配置字段，不进任何 request/response 模型）。
  ⇒ 该 hook 唯一会写入的差异是生成时间戳，不是需要同步的内容。

因此跳过它，并保持 backend/openapi.json 与 $PREV 逐字节相同（收工 territory 判据复核）。
⚠️ 这不是「快照过期没同步」：若哪天 config.py 的改动真的动了 API 面，
   本依据即不成立，必须让该 hook 正常跑完并把 openapi.json 纳入当卡地盘。
