## MEDIUM-1 guard 仍有同类漏面 —— ✅ 已修（本卡选择修而非登记）

r2 用 r1 那套方法（抽真实 helper、内存替换 `inspect.getsource`）实测出**三个新反例**，
车道逐条复现属实：

| 绑定后的操作 | r2 实测 | 车道复现 | 根因 |
|---|---|---|---|
| `expected_templates[0] += "-renamed"` | 绿（漏） | 绿（漏） | `AugAssign.target` 可以是 `Subscript`，而旧代码只接受 `Name` |
| `del expected_templates[0], other[0]` | 绿（漏） | 绿（漏） | 多 target，旧循环用 `target = …` 覆盖，只留最后一个 |
| `expected_templates[0] = other[0] = "renamed"` | 绿（漏） | 绿（漏） | 同上 |

**为什么修而不是登记**：这是本卡这次自己写进去的逻辑错误（「最后一个 target 覆盖前面的」
是实打实的 bug，不是覆盖面取舍），且 r2 指出本卡 docstring 里
「门通过时声明与运行时必然一致」这句话**因此不成立** —— 留着就是一句假话。

**修法**（`test_agents_health.py`）：
1. 新增 `_root_name()`：把 `a[0][1].x` / `*a` 剥到根 `Name`，不以 Name 为根则返回 None；
2. 新增 `_iter_write_targets()`：**逐个产出**该语句所有写目标，并展开 `Tuple`/`List` 解包；
   覆盖 `AugAssign` / `Assign` / `AnnAssign` / `Delete` / `For` / `AsyncFor` / `NamedExpr`
   / 八个 list 变更方法调用；
3. 裸 `Name` 的再绑定仍由「恰好 1 处绑定」断言（FOUND-N）覆盖，此处跳过以免重复报。

**复验**（`FINAL-R3-guard-shapes-*.txt`）：**19 格，逐格写死预期并由探针自己断言**，
`预期不符的格数 = 0`，探针退出码 0。含 r2 的三格（06/07/08）、r1 的两格（04/05）、
以及车道自己补的元组解包写下标（09）、`for` 重绑（13）、walrus 重绑（14）。

**覆盖边界如实声明**（写进代码 docstring）：本函数只认「语法上直接写到这个名字上」的形态。
**通过别名写入**（`alias = expected_templates` 后改 `alias`）、传进函数由被调方改、
`locals()` / `setattr` 等动态手段，**看不见** —— 那需要别名分析，不在本 guard 能力范围内。
