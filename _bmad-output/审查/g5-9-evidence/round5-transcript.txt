# Canvas adversarial audit

## When to use

Use for a user-requested adversarial or closure audit in the Canvas Learning System worktree, particularly P1-05/P1-01/P1-08. Do not use to implement fixes, access prohibited raw-vault content, or declare a historical finding current without revalidation.

## Inputs / context to gather

1. Read the task book, `AGENTS.md`, worktree topology, allowed/prohibited paths, and reporting contract.
2. Record checkout SHA, branch, WT/MAIN labels, current `CURRENT_TASK.md`, and requested P1 claims.
3. Identify actual production entrypoints, not merely the tests that claim to cover them.

## Procedure

1. Split independent tracks: vault admission/indexing and tests; Graphiti quarantine/retrieval; SnapshotV3/recovery anchors. Keep the audit read-only.
2. For each claim, build an evidence matrix: claim, `file:line`, adversarial input/state, actual entrypoint/path, observed result, severity, PASS/PARTIAL/FAIL, and limitations.
3. Directly exercise real entrypoints with temporary fixtures where permitted. For path admission include symlink, directory symlink, blacklisted filename in an allowed directory, case variant, and nonexistent path. Assert rejected inputs perform zero open/hash/index/write.
4. For quarantine, test ordinary edge search plus node search and exact-reader paths (`search_nodes`, `read_node_tips`, `read_node_errors`, `read_node_edge_reasons`). Use read-only Neo4j queries and `EXPLAIN` where allowed; distinguish observed metadata exposure from unproven fact-body leakage.
5. For SnapshotV3, test same-generation invalid/future version self-healing, extra fields, strict typing, huge finite values that may produce NaN/Infinity, and identity/length collision boundaries.
6. Compare recovery anchors with machine facts: current HEAD, Actions status, test counts, and unresolved findings. Separate targeted-test results from whole CI.
7. Cross-check high-severity findings independently. Write the final matrix before closure language; explicitly retain `UNVERIFIABLE` items and failed counterexample attempts.

## Efficiency plan

- Start from task-book source handles and `rg` for real call sites; cache the entrypoint map for all tracks.
- Parallelize independent tracks, then have the primary reviewer re-open only high-severity evidence.
- Stop treating a test as evidence once it only hits source text, a helper, fake client, `__new__`, or monkeypatch; pivot to the real entrypoint.

## Pitfalls and fixes

- Green tests but unsafe closure -> tests do not reach production behavior. Add direct entrypoint fixtures and capture full stdout/trace before an assertion.
- `session:` IDs used as provenance -> ID shape alone is not proof. Preserve provenance or report PARTIAL.
- Quarantine count passes -> exact-reader/node-search surfaces may still cross groups. Test those surfaces specifically.
- `CURRENT_TASK.md` says closed but anchors disagree -> rebuild anchors from current HEAD, Actions, and unresolved findings.

## Verification checklist

- Every finding has `file:line`, reproduction, severity, result, and claim-conflict explanation.
- Final report labels WT/MAIN and all verification limits; no prohibited files or raw vault were read.
- Production entrypoints, not only helpers, were tested for each security claim.
- CI status is reported as whole-workflow status, not only passing targeted jobs.
- P1 closure is withheld whenever a reproducible bypass or unverified critical surface remains.

    90	def _sanitize_ghost_id(raw: str) -> str:
    91	    """幽灵 id 入产物前的结构净化 (round-4 H9)。
    92	
    93	    幽灵 id 是白板 Concepts 小节里的**自由文本**（成员正则允许换行、反引号
    94	    等）。原样放进 `` `…` `` 会被换行终止行、被反引号闭合代码跨度, 从而在
    95	    产物里生成独立的 Markdown 行。这里折叠全部空白、剔除反引号与会起结构
    96	    作用的字符, 并硬截断 —— 产物只把它当**标识串回显**, 不承载任何格式。
    97	    """
    98	    s = " ".join(str(raw or "").split())
    99	    s = re.sub(r"[`\[\]|<>\\]", "", s)
   100	    s = "".join(ch for ch in s if ch.isprintable())
   101	    return s[:120] or "(空名)"

   104	def _scan_board(vault: Path, stem: str) -> dict:
   105	    """单板只读扫描 (fallback 口径, 与 recap_scan 第一刀一致)。"""
   106	    board_path = _rs._contained_md(vault / BOARD_DIR, stem)
   107	    if board_path is None:
   108	        return {
   109	            "board_stem": stem,
   110	            "exists": False,
   111	            "refusal_reason": "板名非法 (containment 拒绝)",
   112	        }
   113	    if not board_path.is_file():
   114	        return {
   115	            "board_stem": stem,
   116	            "exists": False,
   117	            "refusal_reason": "原白板文件不存在",
   118	        }
   119	    board_text = _rs._read(board_path)
   120	    _, board_body = _rs._frontmatter_and_body(board_text)
   121	    sec = _rs._CONCEPTS_SECTION_RE.search(board_body)
   122	    sec_body = re.sub(r"<!--.*?-->", "", sec.group(1), flags=re.S) if sec else ""
   123	    bullet_lines = "\n".join(
   124	        ln for ln in sec_body.splitlines() if re.match(r"^\s*-\s", ln)
   125	    )
   126	    members = list(
   127	        dict.fromkeys(m.strip() for m in _rs._CONCEPT_LINK_RE.findall(bullet_lines))
   128	    )
   129	    ledger = _rs._ledger_from_local(vault, members)
   130	    tips_total = sum(r.get("tips_count", 0) for r in ledger)
   131	    # 幽灵链接 (workflow round-2 confirmed): Concepts 里列了但节点文件不存在/
   132	    # 名非法/不可读 → _ledger_from_local 给 role="unknown" + exists=False。
   133	    # 原实现把它们计进 members 却不进 seeds/derived, 产出「成员 3(1 种子 +
   134	    # 0 派生)」这种自相矛盾数字, 还把死 wikilink 原样写进产物且零标记。
   135	    # 现在: 分开计数, member_ids 只留真实存在的, 幽灵单列并在产物显式成段。
   136	    live_rows = [r for r in ledger if r.get("role") in ("seed", "derived")]
   137	    # round-4 H9: ghost id 来自白板 Concepts 的自由文本 (成员正则允许换行与
   138	    # 反引号) — 原样嵌进 `…` 会被换行/反引号突破隔离, 在产物里生成独立行。
   139	    # 一律折叠空白 + 剔除反引号与 Markdown 结构字符后再入产物。
   140	    ghosts = [
   141	        {
   142	            "node_id": _sanitize_ghost_id(r["node_id"]),
   143	            "reason": r.get("role_source") or "unknown",
   144	        }
   145	        for r in ledger
   146	        if r.get("role") not in ("seed", "derived")
   147	    ]
   148	    return {
   149	        "board_stem": stem,
   150	        "exists": True,
   151	        "board_sha256": hashlib.sha256(board_text.encode("utf-8")).hexdigest(),
   152	        # members 只数可解析成员, 与 seeds+derived 恒等 (X+Y==N 不再矛盾)
   153	        "members": len(live_rows),
   154	        "seeds": sum(1 for r in live_rows if r.get("role") == "seed"),
   155	        "derived": sum(1 for r in live_rows if r.get("role") == "derived"),
   156	        "listed_in_concepts": len(ledger),
   157	        "ghost_links": ghosts,
   158	        "ghost_count": len(ghosts),
   159	        "tips_total": tips_total,
   160	        # 学习 vault 无「已答」标记 → 未答 = 全部 tips 上界 (C5 同口径)
   161	        "tips_unanswered_upper_bound": tips_total,
   162	        "member_ids": [r["node_id"] for r in live_rows],
   163	    }

   166	def _render_content(boards: list[dict], anchor: str, ts: str, created_at: str) -> str:
   167	    """产物全文 — 链接 + 脚本数字 + 固定模板句, 零正文复制。
   168	
   169	    frontmatter 契约: 无 questions 键 / 0 个 concept: 行 / status: done /
   170	    type: exam_board — 消费面兼容判据见模块 docstring。
   171	    """
   172	    n = len(boards)
   173	    # ⛔ round-6 终裁复核: 节点/ 是**一 vault 一学科的扁平共享池**, 同一节点被
   174	    # 两块板的 ## Concepts 同时列出是正常形态。原先各板 members/tips 直接相加
   175	    # → 跨板成员在「阶段数字」里被重复计数, 且产物把同一节点重复列成员链接,
   176	    # 全程零去重零声明。现在: 总计按 node_id 去重, 并如实声明去重量。
   177	    all_member_ids: list[str] = []
   178	    for b in boards:
   179	        all_member_ids.extend(b["member_ids"])
   180	    uniq_members = list(dict.fromkeys(all_member_ids))
   181	    total_members = len(uniq_members)
   182	    dup_members = len(all_member_ids) - total_members
   183	    total_tips = sum(b["tips_total"] for b in boards)
   184	    fm = [
   185	        "---",
   186	        "type: exam_board",
   187	        "recap_kind: stage_recap",
   188	        f'source_board: "[[原白板/{anchor}]]"',
   189	        "recap_boards:",
   190	        *[f'  - "[[原白板/{b["board_stem"]}]]"' for b in boards],
   191	        f'created_at: "{created_at}"',
   192	        "status: done",
   193	        f"generated_by: {GENERATED_BY}",
   194	        "---",
   195	    ]
   196	    lines = [
   197	        *fm,
   198	        "",
   199	        f"# 阶段回顾 · {anchor} 等 {n} 板 · {ts[:10]}",
   200	        "",
   201	        "> [!info]+ 阶段回顾检验白板（链接回原板 · 不含正文 · 无题面）",
   202	        "> 本板是阶段回顾产物：只列链接与脚本数字，不复制任何正文，也不含题目。",
   203	        "> 要出题请对某块原白板运行 /start-exam-board（本板不可作为出题源）。",
   204	        "",
   205	        "## 覆盖范围",
   206	        "",
   207	    ]
   208	    total_ghosts = sum(b["ghost_count"] for b in boards)
   209	    for b in boards:
   210	        ghost_note = (
   211	            f" · ⚠ Concepts 另列 {b['ghost_count']} 条链接指向不存在/不可读的节点（见下）"
   212	            if b["ghost_count"]
   213	            else ""
   214	        )
   215	        lines.append(
   216	            f"- [[原白板/{b['board_stem']}]] — 成员 {b['members']}"
   217	            f"（{b['seeds']} 种子 + {b['derived']} 派生）/ 批注 {b['tips_total']} 条"
   218	            f"（未答上界 {b['tips_unanswered_upper_bound']}，无已答标记）{ghost_note}"
   219	        )
   220	    lines += ["", "## 成员链接（回原节点）", ""]
   221	    for b in boards:
   222	        lines.append(f"### [[原白板/{b['board_stem']}]]")
   223	        lines.append("")
   224	        if b["member_ids"]:
   225	            lines += [f"- [[节点/{m}]]" for m in b["member_ids"]]
   226	        else:
   227	            lines.append("- （本板 Concepts 小节无可解析成员）")
   228	        lines.append("")
   229	    if total_ghosts:
   230	        # 幽灵链接单列成段并**不写成 wikilink**（写了就是死链），如实标原因
   231	        lines += [
   232	            "## 待修链接（Concepts 里列了但打不开）",
   233	            "",
   234	        ]
   235	        for b in boards:
   236	            for g in b["ghost_links"]:
   237	                lines.append(
   238	                    f"- `{b['board_stem']}` → `节点/{g['node_id']}.md`（{g['reason']}）"
   239	                )
   240	        lines.append("")
   241	    lines += [
   242	        "## 阶段数字（脚本产出 · 判读留人）",
   243	        "",
   244	        f"- 覆盖 {n} 板 / 总成员 {total_members}（按节点去重）/ 总批注 {total_tips} 条（未答上界 {total_tips}）"
   245	        + (f" / 跨板重复成员 {dup_members} 个" if dup_members else "")
   246	        + (f" / 待修链接 {total_ghosts} 条" if total_ghosts else ""),
   247	        f"- 数据面：本地只读扫描（fallback 口径，与 /board-recap 第一刀一致）· 取数时刻 {created_at}",
   248	        "",
   249	    ]
   250	    return "\n".join(lines)

   253	def _symlink_probe(vault: Path, target: Path, tmp: Path) -> str | None:
   254	    """写前 lstat 预检 — 目录 / 最终目标 / **落盘用的 tmp 路径** 三者。
   255	
   256	    W4 (workflow round-1 复现, BLOCKER): 只查目录与 target 而漏 tmp,
   257	    预置 ``<target>.g59-tmp`` symlink 会让 write_text 跟随链接写到 vault
   258	    外 (覆盖任意外部文件), 随后 os.replace 把 target 本身变成指向 vault
   259	    外的 symlink; 且 undo 的 resolve() 会逃出 exam_root 导致无法回退。
   260	    本函数是第一道; 真正的防线是 _atomic_write 的 O_EXCL|O_NOFOLLOW。
   261	    """
   262	    for p in (vault / EXAM_DIR, target, tmp):
   263	        if p.is_symlink():
   264	            return f"写入目标被 symlink 布防: {p}"
   265	    return None

   280	def _fsync_dir(d: Path) -> tuple[str, str | None]:
   281	    """目录项持久化 (round-3 M5): 只 fsync 文件不 fsync 父目录时,
   282	    崩溃后可能文件内容在而目录项丢失。
   283	
   284	    ⛔ round-3 HIGH-4: 原实现把 open/fsync 的失败**全部静默吞掉并返回 None**,
   285	    调用方无从分辨"成功"与"失败"。undo 因此会在**留痕目录项未持久化**的情况下
   286	    继续删除源文件 —— 崩溃模型下可能**两端皆失**(源已删、留痕的目录项没落盘)。
   287	    修法: 返回失败原因, 由调用方决定是否 fail-closed。
   288	    → ("ok"|"unsupported"|"failed", 说明|None)。
   289	    round-4 HIGH-4 起改为**三态**: "unsupported" 单列, 因为「该 FS 不支持 fsync 目录」
   290	    只说明**无法证明已持久化**, 既不是成功也不是失败 —— 把它伪装成成功会让 undo
   291	    在无从证明的情况下继续删源。调用方须显式决定如何对待这一档。
   292	
   293	    诚实边界: 部分文件系统对目录 fd 的 fsync 返回 EINVAL/ENOTSUP, 那**不是**
   294	    持久化失败而是"不支持"。这两类必须区分, 否则会在正常 FS 上误拒。
   295	    """
   296	    try:
   297	        fd = os.open(d, os.O_RDONLY)
   298	    except OSError as e:
   299	        return "failed", f"目录打开失败 {type(e).__name__}"
   300	    unsupported = None
   301	    try:
   302	        try:
   303	            os.fsync(fd)
   304	        except OSError as e:
   305	            errno_ = getattr(e, "errno", None)
   306	            # ⛔ round-4 HIGH-4: 原豁免集含 EPERM —— 它**不能**证明「不支持」,
   307	            # 更可能是真实的权限/策略拒绝, 当成成功会让 undo 继续删源。已移除。
   308	            # 且 EINVAL/ENOTSUP 只说明「**无法证明**已持久化」, 不等于成功 ——
   309	            # 改为单独一档 "unsupported", 由调用方决定怎么办(而不是伪装成 None)。
   310	            if errno_ in (errno.EINVAL, errno.ENOTSUP):
   311	                unsupported = f"该文件系统不支持 fsync 目录 ({type(e).__name__})"
   312	            else:
   313	                return "failed", f"目录 fsync 失败 {type(e).__name__}"
   314	    finally:
   315	        # round-4 MEDIUM-2: close 若抛错, 原实现会直接逸出并破坏 JSON 回执契约。
   316	        try:
   317	            os.close(fd)
   318	        except OSError:
   319	            pass
   320	    if unsupported:
   321	        return "unsupported", unsupported
   322	    return "ok", None

   325	def _open_exam_dirfd(vault: Path) -> tuple[int | None, str | None]:
   326	    """打开 检验白板/ 并返回一个**钉死该目录 inode** 的 dir_fd。
   327	
   328	    主 session 并行复核 HIGH-4 的正解。三重校验:
   329	    1. ``O_DIRECTORY|O_NOFOLLOW`` —— 目录本身若是 symlink 直接 ELOOP 失败;
   330	    2. ``os.fstat(dfd)`` 与 ``os.stat(vault/EXAM_DIR)`` 的 (dev, ino) 必须相同
   331	       —— 打开的确是我们校验过的那个目录, 不是打开后被换掉的另一个;
   332	    3. dfd 与 vault 必须**同一文件系统** (st_dev 相同) —— 目录被换成指向外部
   333	       挂载点的链接时, 即便前两条侥幸通过也会在这里被拦。
   334	    → (dfd | None, 失败原因 | None)。调用方负责 os.close(dfd)。
   335	    """
   336	    exam = vault / EXAM_DIR
   337	    try:
   338	        dfd = os.open(exam, os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW)
   339	    except OSError as e:
   340	        return (
   341	            None,
   342	            f"{EXAM_DIR}/ 打开失败 (被 symlink 布防或不是目录): {type(e).__name__}",
   343	        )
   344	    try:
   345	        st_dfd = os.fstat(dfd)
   346	        st_path = os.stat(exam)
   347	        st_vault = os.stat(vault)
   348	    except OSError as e:
   349	        os.close(dfd)
   350	        return None, f"{EXAM_DIR}/ 身份校验失败: {type(e).__name__}"
   351	    if (st_dfd.st_dev, st_dfd.st_ino) != (st_path.st_dev, st_path.st_ino):
   352	        os.close(dfd)
   353	        return None, f"{EXAM_DIR}/ 在打开前后被替换 (inode 变化), 拒绝写入"
   354	    if st_dfd.st_dev != st_vault.st_dev:
   355	        os.close(dfd)
   356	        return None, f"{EXAM_DIR}/ 与 vault 不在同一文件系统 (疑似越界挂载), 拒绝写入"
   357	    return dfd, None

   360	def _dirfd_still_in_vault(dir_fd: int, vault: Path) -> str | None:
   361	    """复核 dir_fd 指向的仍是 vault 内那个 检验白板/ 目录。
   362	
   363	    ⛔ round-3 HIGH-1: `_open_exam_dirfd` 只在**打开那一刻**做一次 inode 快照。
   364	    校验通过之后, 若有人把该目录 rename 到 vault **外**(同一文件系统),
   365	    dfd 仍指向那个已被移走的 inode —— 写入会真的落在 vault 外, 而回执照旧
   366	    按词法路径报 `created: true`, 用户以为文件在 vault 里。
   367	    修法: 发布完成后**再核一次**「vault/检验白板 这个路径今天解析出来的 inode,
   368	    是否还等于我们手里 dfd 的 inode」。不等 = 目录已被移走/替换。
   369	    → None = 仍在; str = 失败原因。
   370	
   371	    诚实边界: 这是**事后检测**, 不是事前阻止 —— POSIX 没有"把 inode 钉在某个
   372	    父目录里"的原语。它保证的是**不会谎报成功**(检测到就如实回报并撤销),
   373	    而不是"不可能被移走"。残留窗口与 lstat→unlink 那处同源, 已在验收单声明。
   374	    """
   375	    try:
   376	        # ⛔ round-4 HIGH-1: 原用 os.stat —— 它**跟随 symlink**。反例: 把目录 rename
   377	        # 出 vault 后, 在原路径放一个指回它的 symlink, os.stat 解析后拿到的 inode
   378	        # 仍等于 dir_fd 的 inode ⇒ 复核通过, 文件照旧落在 vault 外而回执报成功。
   379	        # 改用 lstat 并**显式拒绝 symlink**: 该路径本就应当是真目录, 不是别名。
   380	        st_now = os.lstat(vault / EXAM_DIR)
   381	        st_dfd = os.fstat(dir_fd)
   382	    except OSError as e:
   383	        return f"写入后复核 {EXAM_DIR}/ 失败: {type(e).__name__}"
   384	    if stat.S_ISLNK(st_now.st_mode):
   385	        return f"{EXAM_DIR}/ 在写入期间被替换成 symlink — 写入落点不可信"

   453	    unlink tmp → fsync 父目录。
   454	
   455	    W4 纵深防御: O_NOFOLLOW 让 tmp 若是 symlink 直接 ELOOP 失败 (不跟随),

   457	    lstat 预检与实际写之间的 TOCTOU 窗口由内核标志封死。

   459	    target) —— 改用 ``os.link``: 目标已存在时内核直接 EEXIST, 原子且永不
   460	    覆盖; 成功后 unlink tmp, 目标是同一 inode 的硬链接 (内容已 fsync)。

   468	    操作 —— 检查与使用之间隔着可被替换的路径解析, O_NOFOLLOW 只护住最后一段,
   469	    中段/父目录被换掉时护不住。修法 = **dirfd 锚定**: 调用方用
   470	    O_DIRECTORY|O_NOFOLLOW 打开 检验白板/ 拿到 dfd 并校验它确在 vault 内,

   280	def _fsync_dir(d: Path) -> tuple[str, str | None]:
   281	    """目录项持久化 (round-3 M5): 只 fsync 文件不 fsync 父目录时,
   282	    崩溃后可能文件内容在而目录项丢失。
   283	
   284	    ⛔ round-3 HIGH-4: 原实现把 open/fsync 的失败**全部静默吞掉并返回 None**,
   285	    调用方无从分辨"成功"与"失败"。undo 因此会在**留痕目录项未持久化**的情况下
   286	    继续删除源文件 —— 崩溃模型下可能**两端皆失**(源已删、留痕的目录项没落盘)。
   287	    修法: 返回失败原因, 由调用方决定是否 fail-closed。
   288	    → ("ok"|"unsupported"|"failed", 说明|None)。
   289	    round-4 HIGH-4 起改为**三态**: "unsupported" 单列, 因为「该 FS 不支持 fsync 目录」
   290	    只说明**无法证明已持久化**, 既不是成功也不是失败 —— 把它伪装成成功会让 undo
   291	    在无从证明的情况下继续删源。调用方须显式决定如何对待这一档。
   292	
   293	    诚实边界: 部分文件系统对目录 fd 的 fsync 返回 EINVAL/ENOTSUP, 那**不是**
   294	    持久化失败而是"不支持"。这两类必须区分, 否则会在正常 FS 上误拒。
   295	    """
   296	    try:
   297	        fd = os.open(d, os.O_RDONLY)
   298	    except OSError as e:
   299	        return "failed", f"目录打开失败 {type(e).__name__}"
   300	    unsupported = None
   301	    try:
   302	        try:
   303	            os.fsync(fd)
   304	        except OSError as e:
   305	            errno_ = getattr(e, "errno", None)
   306	            # ⛔ round-4 HIGH-4: 原豁免集含 EPERM —— 它**不能**证明「不支持」,
   307	            # 更可能是真实的权限/策略拒绝, 当成成功会让 undo 继续删源。已移除。
   308	            # 且 EINVAL/ENOTSUP 只说明「**无法证明**已持久化」, 不等于成功 ——
   309	            # 改为单独一档 "unsupported", 由调用方决定怎么办(而不是伪装成 None)。
   310	            if errno_ in (errno.EINVAL, errno.ENOTSUP):
   311	                unsupported = f"该文件系统不支持 fsync 目录 ({type(e).__name__})"
   312	            else:
   313	                return "failed", f"目录 fsync 失败 {type(e).__name__}"
   314	    finally:
   315	        # round-4 MEDIUM-2: close 若抛错, 原实现会直接逸出并破坏 JSON 回执契约。
   316	        try:
   317	            os.close(fd)
   318	        except OSError:
   319	            pass
   320	    if unsupported:
   321	        return "unsupported", unsupported
   322	    return "ok", None

   394	def _rollback_published(
   395	    name: str,
   396	    dir_fd: int,
   397	    identity: tuple[int, int] | None = None,
   398	    *,
   399	    expect_sha: str | None = None,
   400	) -> tuple[str, str | None]:
   401	    """撤销**我们自己**刚发布的 target —— 仅当它当前确实还是我们那一份。
   402	
   403	    round-3 HIGH-3: 原实现按 basename 直接 unlink 并静默吞掉失败, 两个问题:
   404	      · identity 快照可能已过时 —— 期间路径被换入他人文件时会误删;
   405	      · 删除失败被吞 ⇒ 错误字节的 target 留在 vault 里, 回执却只报失败。
   406	
   407	    「还是我们那一份」有两种判法, 按调用场景取其一:
   408	      · ``identity``  —— 比 (dev, ino), 用于「刚 link 出来、inode 已知」的场景;
   409	      · ``expect_sha`` —— 比内容 SHA, 用于 HIGH-1 那种「目录整体被移走」的场景
   410	        (此时 inode 仍是我们的, 但我们想确认删的确是自己写的那份字节)。
   411	    两者都给则必须同时满足。任一不符 ⇒ **不删**(那不是我们的东西)。
   412	    ⛔ round-4 HIGH-3: 原先只返回 `None | str`, 而 `None` 同时表示四种截然不同的
   413	    结果(已删 / 本就不存在 / identity 不符**没删** / SHA 不符**没删**)。调用方无法
   414	    分辨, 于是一律拼「已撤销该文件」—— **回执与实际副作用直接不一致**。
   415	    改为三态: ("deleted"|"absent"|"kept", 失败原因|None)。
   416	    · deleted = 确实删了; · absent = 本就不在; · kept = **判据不符, 故意没删**。
   417	    """
   418	    if identity is None and expect_sha is None:
   419	        # round-4 LOW-1: 两个判据都不给 ⇒ 无从证明「这是我们的」, 拒绝删除。
   420	        return "kept", "未提供任何身份判据, 拒绝删除"
   421	    try:
   422	        st_now = os.lstat(name, dir_fd=dir_fd)
   423	    except FileNotFoundError:
   424	        return "absent", None  # 已经不在了, 无需撤销
   425	    except OSError as e:
   426	        return "kept", f"撤销前复核失败 {type(e).__name__}"
   427	    if identity is not None and (st_now.st_dev, st_now.st_ino) != identity:
   428	        return "kept", None  # 已不是我们的 inode ⇒ 是别人的文件, 绝不删
   429	    if expect_sha is not None:

   435	                    buf += chunk
   436	            finally:
   437	                os.close(cfd)
   438	        except OSError as e:
   439	            return "kept", f"撤销前回读失败 {type(e).__name__}"
   440	        if hashlib.sha256(buf).hexdigest() != expect_sha:
   441	            return "kept", None  # 内容已不是我们写的那份 ⇒ 不删
   442	    try:
   443	        os.unlink(name, dir_fd=dir_fd)
   444	    except OSError as e:
   445	        return "kept", f"unlink 失败 {type(e).__name__}"
   446	    return "deleted", None

   449	def _atomic_write(
   450	    tmp: Path, target: Path, content: str, dir_fd: int
   451	) -> tuple[str | None, str | None]:
   452	    """O_EXCL|O_NOFOLLOW 写 tmp → fsync → **link 到 target (no-replace)** →
   453	    unlink tmp → fsync 父目录。
   454	
   455	    W4 纵深防御: O_NOFOLLOW 让 tmp 若是 symlink 直接 ELOOP 失败 (不跟随),
   456	    O_CREAT|O_EXCL 让 tmp 已存在时直接失败 (不覆盖并发/残留文件) —
   457	    lstat 预检与实际写之间的 TOCTOU 窗口由内核标志封死。
   458	    round-3 H6: 落盘不再用 ``os.replace`` (它会**覆盖**预检之后才出现的
   459	    target) —— 改用 ``os.link``: 目标已存在时内核直接 EEXIST, 原子且永不
   460	    覆盖; 成功后 unlink tmp, 目标是同一 inode 的硬链接 (内容已 fsync)。

     """O_EXCL|O_NOFOLLOW 写 tmp → fsync → **link 到 target (no-replace)** →
     unlink tmp → fsync 父目录。
 
     W4 纵深防御: O_NOFOLLOW 让 tmp 若是 symlink 直接 ELOOP 失败 (不跟随),
     O_CREAT|O_EXCL 让 tmp 已存在时直接失败 (不覆盖并发/残留文件) —
     lstat 预检与实际写之间的 TOCTOU 窗口由内核标志封死。

     target) —— 改用 ``os.link``: 目标已存在时内核直接 EEXIST, 原子且永不
