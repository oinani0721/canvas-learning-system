# Canvas adversarial audit

## When to use

Use for a user-requested adversarial or closure audit in the Canvas Learning System worktree, particularly P1-05/P1-01/P1-08. Do not use to implement fixes, access prohibited raw-vault content, or declare a historical finding current without revalidation.

## Inputs / context to gather

1. Read the task book, `AGENTS.md`, worktree topology, allowed/prohibited paths, and reporting contract.
2. Record checkout SHA, branch, WT/MAIN labels, current `CURRENT_TASK.md`, and requested P1 claims.
3. Identify actual production entrypoints, not merely the tests that claim to cover them.

## Procedure

1. Split independent tracks: vault admission/indexing and tests; Graphiti quarantine/retrieval; SnapshotV3/recovery anchors. Keep the audit read-only.
2. For each claim, build an evidence matrix: claim, `file:line`, adversarial input/state, actual entrypoint/path, observed result, severity, PASS/PARTIAL/FAIL, and limitations.
3. Directly exercise real entrypoints with temporary fixtures where permitted. For path admission include symlink, directory symlink, blacklisted filename in an allowed directory, case variant, and nonexistent path. Assert rejected inputs perform zero open/hash/index/write.
4. For quarantine, test ordinary edge search plus node search and exact-reader paths (`search_nodes`, `read_node_tips`, `read_node_errors`, `read_node_edge_reasons`). Use read-only Neo4j queries and `EXPLAIN` where allowed; distinguish observed metadata exposure from unproven fact-body leakage.
5. For SnapshotV3, test same-generation invalid/future version self-healing, extra fields, strict typing, huge finite values that may produce NaN/Infinity, and identity/length collision boundaries.
6. Compare recovery anchors with machine facts: current HEAD, Actions status, test counts, and unresolved findings. Separate targeted-test results from whole CI.
7. Cross-check high-severity findings independently. Write the final matrix before closure language; explicitly retain `UNVERIFIABLE` items and failed counterexample attempts.

## Efficiency plan

- Start from task-book source handles and `rg` for real call sites; cache the entrypoint map for all tracks.
- Parallelize independent tracks, then have the primary reviewer re-open only high-severity evidence.
- Stop treating a test as evidence once it only hits source text, a helper, fake client, `__new__`, or monkeypatch; pivot to the real entrypoint.

## Pitfalls and fixes

- Green tests but unsafe closure -> tests do not reach production behavior. Add direct entrypoint fixtures and capture full stdout/trace before an assertion.
- `session:` IDs used as provenance -> ID shape alone is not proof. Preserve provenance or report PARTIAL.
- Quarantine count passes -> exact-reader/node-search surfaces may still cross groups. Test those surfaces specifically.
- `CURRENT_TASK.md` says closed but anchors disagree -> rebuild anchors from current HEAD, Actions, and unresolved findings.

## Verification checklist

- Every finding has `file:line`, reproduction, severity, result, and claim-conflict explanation.
- Final report labels WT/MAIN and all verification limits; no prohibited files or raw vault were read.
- Production entrypoints, not only helpers, were tested for each security claim.
- CI status is reported as whole-workflow status, not only passing targeted jobs.
- P1 closure is withheld whenever a reproducible bypass or unverified critical surface remains.

    89	def _sanitize_ghost_id(raw: str) -> str:
    90	    """幽灵 id 入产物前的结构净化 (round-4 H9)。
    91	
    92	    幽灵 id 是白板 Concepts 小节里的**自由文本**（成员正则允许换行、反引号
    93	    等）。原样放进 `` `…` `` 会被换行终止行、被反引号闭合代码跨度, 从而在
    94	    产物里生成独立的 Markdown 行。这里折叠全部空白、剔除反引号与会起结构
    95	    作用的字符, 并硬截断 —— 产物只把它当**标识串回显**, 不承载任何格式。
    96	    """
    97	    s = " ".join(str(raw or "").split())
    98	    s = re.sub(r"[`\[\]|<>\\]", "", s)
    99	    s = "".join(ch for ch in s if ch.isprintable())
   100	    return s[:120] or "(空名)"

   103	def _scan_board(vault: Path, stem: str) -> dict:
   104	    """单板只读扫描 (fallback 口径, 与 recap_scan 第一刀一致)。"""
   105	    board_path = _rs._contained_md(vault / BOARD_DIR, stem)
   106	    if board_path is None:
   107	        return {
   108	            "board_stem": stem,
   109	            "exists": False,
   110	            "refusal_reason": "板名非法 (containment 拒绝)",
   111	        }
   112	    if not board_path.is_file():
   113	        return {
   114	            "board_stem": stem,
   115	            "exists": False,
   116	            "refusal_reason": "原白板文件不存在",
   117	        }
   118	    board_text = _rs._read(board_path)
   119	    _, board_body = _rs._frontmatter_and_body(board_text)
   120	    sec = _rs._CONCEPTS_SECTION_RE.search(board_body)
   121	    sec_body = re.sub(r"<!--.*?-->", "", sec.group(1), flags=re.S) if sec else ""
   122	    bullet_lines = "\n".join(
   123	        ln for ln in sec_body.splitlines() if re.match(r"^\s*-\s", ln)
   124	    )
   125	    members = list(
   126	        dict.fromkeys(m.strip() for m in _rs._CONCEPT_LINK_RE.findall(bullet_lines))
   127	    )
   128	    ledger = _rs._ledger_from_local(vault, members)
   129	    tips_total = sum(r.get("tips_count", 0) for r in ledger)
   130	    # 幽灵链接 (workflow round-2 confirmed): Concepts 里列了但节点文件不存在/
   131	    # 名非法/不可读 → _ledger_from_local 给 role="unknown" + exists=False。
   132	    # 原实现把它们计进 members 却不进 seeds/derived, 产出「成员 3(1 种子 +
   133	    # 0 派生)」这种自相矛盾数字, 还把死 wikilink 原样写进产物且零标记。
   134	    # 现在: 分开计数, member_ids 只留真实存在的, 幽灵单列并在产物显式成段。
   135	    live_rows = [r for r in ledger if r.get("role") in ("seed", "derived")]
   136	    # round-4 H9: ghost id 来自白板 Concepts 的自由文本 (成员正则允许换行与
   137	    # 反引号) — 原样嵌进 `…` 会被换行/反引号突破隔离, 在产物里生成独立行。
   138	    # 一律折叠空白 + 剔除反引号与 Markdown 结构字符后再入产物。
   139	    ghosts = [
   140	        {
   141	            "node_id": _sanitize_ghost_id(r["node_id"]),
   142	            "reason": r.get("role_source") or "unknown",
   143	        }
   144	        for r in ledger
   145	        if r.get("role") not in ("seed", "derived")
   146	    ]
   147	    return {
   148	        "board_stem": stem,
   149	        "exists": True,
   150	        "board_sha256": hashlib.sha256(board_text.encode("utf-8")).hexdigest(),
   151	        # members 只数可解析成员, 与 seeds+derived 恒等 (X+Y==N 不再矛盾)
   152	        "members": len(live_rows),
   153	        "seeds": sum(1 for r in live_rows if r.get("role") == "seed"),
   154	        "derived": sum(1 for r in live_rows if r.get("role") == "derived"),
   155	        "listed_in_concepts": len(ledger),
   156	        "ghost_links": ghosts,
   157	        "ghost_count": len(ghosts),
   158	        "tips_total": tips_total,
   159	        # 学习 vault 无「已答」标记 → 未答 = 全部 tips 上界 (C5 同口径)
   160	        "tips_unanswered_upper_bound": tips_total,
   161	        "member_ids": [r["node_id"] for r in live_rows],
   162	    }

   165	def _render_content(boards: list[dict], anchor: str, ts: str, created_at: str) -> str:
   166	    """产物全文 — 链接 + 脚本数字 + 固定模板句, 零正文复制。
   167	
   168	    frontmatter 契约: 无 questions 键 / 0 个 concept: 行 / status: done /
   169	    type: exam_board — 消费面兼容判据见模块 docstring。
   170	    """
   171	    n = len(boards)
   172	    # ⛔ round-6 终裁复核: 节点/ 是**一 vault 一学科的扁平共享池**, 同一节点被
   173	    # 两块板的 ## Concepts 同时列出是正常形态。原先各板 members/tips 直接相加
   174	    # → 跨板成员在「阶段数字」里被重复计数, 且产物把同一节点重复列成员链接,
   175	    # 全程零去重零声明。现在: 总计按 node_id 去重, 并如实声明去重量。
   176	    all_member_ids: list[str] = []
   177	    for b in boards:
   178	        all_member_ids.extend(b["member_ids"])
   179	    uniq_members = list(dict.fromkeys(all_member_ids))
   180	    total_members = len(uniq_members)
   181	    dup_members = len(all_member_ids) - total_members
   182	    total_tips = sum(b["tips_total"] for b in boards)
   183	    fm = [
   184	        "---",
   185	        "type: exam_board",
   186	        "recap_kind: stage_recap",
   187	        f'source_board: "[[原白板/{anchor}]]"',
   188	        "recap_boards:",
   189	        *[f'  - "[[原白板/{b["board_stem"]}]]"' for b in boards],
   190	        f'created_at: "{created_at}"',
   191	        "status: done",
   192	        f"generated_by: {GENERATED_BY}",
   193	        "---",
   194	    ]
   195	    lines = [
   196	        *fm,
   197	        "",
   198	        f"# 阶段回顾 · {anchor} 等 {n} 板 · {ts[:10]}",
   199	        "",
   200	        "> [!info]+ 阶段回顾检验白板（链接回原板 · 不含正文 · 无题面）",
   201	        "> 本板是阶段回顾产物：只列链接与脚本数字，不复制任何正文，也不含题目。",
   202	        "> 要出题请对某块原白板运行 /start-exam-board（本板不可作为出题源）。",
   203	        "",
   204	        "## 覆盖范围",
   205	        "",
   206	    ]
   207	    total_ghosts = sum(b["ghost_count"] for b in boards)
   208	    for b in boards:
   209	        ghost_note = (
   210	            f" · ⚠ Concepts 另列 {b['ghost_count']} 条链接指向不存在/不可读的节点（见下）"
   211	            if b["ghost_count"]
   212	            else ""
   213	        )
   214	        lines.append(
   215	            f"- [[原白板/{b['board_stem']}]] — 成员 {b['members']}"
   216	            f"（{b['seeds']} 种子 + {b['derived']} 派生）/ 批注 {b['tips_total']} 条"
   217	            f"（未答上界 {b['tips_unanswered_upper_bound']}，无已答标记）{ghost_note}"
   218	        )
   219	    lines += ["", "## 成员链接（回原节点）", ""]
   220	    for b in boards:
   221	        lines.append(f"### [[原白板/{b['board_stem']}]]")
   222	        lines.append("")
   223	        if b["member_ids"]:
   224	            lines += [f"- [[节点/{m}]]" for m in b["member_ids"]]
   225	        else:
   226	            lines.append("- （本板 Concepts 小节无可解析成员）")
   227	        lines.append("")
   228	    if total_ghosts:
   229	        # 幽灵链接单列成段并**不写成 wikilink**（写了就是死链），如实标原因
   230	        lines += [
   231	            "## 待修链接（Concepts 里列了但打不开）",
   232	            "",
   233	        ]
   234	        for b in boards:
   235	            for g in b["ghost_links"]:
   236	                lines.append(
   237	                    f"- `{b['board_stem']}` → `节点/{g['node_id']}.md`（{g['reason']}）"
   238	                )
   239	        lines.append("")
   240	    lines += [
   241	        "## 阶段数字（脚本产出 · 判读留人）",
   242	        "",
   243	        f"- 覆盖 {n} 板 / 总成员 {total_members}（按节点去重）/ 总批注 {total_tips} 条（未答上界 {total_tips}）"
   244	        + (f" / 跨板重复成员 {dup_members} 个" if dup_members else "")
   245	        + (f" / 待修链接 {total_ghosts} 条" if total_ghosts else ""),
   246	        f"- 数据面：本地只读扫描（fallback 口径，与 /board-recap 第一刀一致）· 取数时刻 {created_at}",
   247	        "",
   248	    ]
   249	    return "\n".join(lines)

   279	def _fsync_dir(d: Path) -> str | None:
   280	    """目录项持久化 (round-3 M5): 只 fsync 文件不 fsync 父目录时,
   281	    崩溃后可能文件内容在而目录项丢失。
   282	
   283	    ⛔ round-3 HIGH-4: 原实现把 open/fsync 的失败**全部静默吞掉并返回 None**,
   284	    调用方无从分辨"成功"与"失败"。undo 因此会在**留痕目录项未持久化**的情况下
   285	    继续删除源文件 —— 崩溃模型下可能**两端皆失**(源已删、留痕的目录项没落盘)。
   286	    修法: 返回失败原因, 由调用方决定是否 fail-closed。
   287	    → None = 成功 (或该 FS 不支持 fsync 目录, 见下); str = 失败原因。
   288	
   289	    诚实边界: 部分文件系统对目录 fd 的 fsync 返回 EINVAL/ENOTSUP, 那**不是**
   290	    持久化失败而是"不支持"。这两类必须区分, 否则会在正常 FS 上误拒。
   291	    """
   292	    try:
   293	        fd = os.open(d, os.O_RDONLY)
   294	    except OSError as e:
   295	        return f"目录打开失败 {type(e).__name__}"
   296	    try:
   297	        os.fsync(fd)
   298	    except OSError as e:
   299	        if getattr(e, "errno", None) in (errno.EINVAL, errno.ENOTSUP, errno.EPERM):
   300	            return None  # FS 不支持 fsync 目录 —— 不是持久化失败
   301	        return f"目录 fsync 失败 {type(e).__name__}"
   302	    finally:
   303	        os.close(fd)
   304	    return None
   305

   307	def _open_exam_dirfd(vault: Path) -> tuple[int | None, str | None]:
   308	    """打开 检验白板/ 并返回一个**钉死该目录 inode** 的 dir_fd。
   309	
   310	    主 session 并行复核 HIGH-4 的正解。三重校验:
   311	    1. ``O_DIRECTORY|O_NOFOLLOW`` —— 目录本身若是 symlink 直接 ELOOP 失败;
   312	    2. ``os.fstat(dfd)`` 与 ``os.stat(vault/EXAM_DIR)`` 的 (dev, ino) 必须相同
   313	       —— 打开的确是我们校验过的那个目录, 不是打开后被换掉的另一个;
   314	    3. dfd 与 vault 必须**同一文件系统** (st_dev 相同) —— 目录被换成指向外部
   315	       挂载点的链接时, 即便前两条侥幸通过也会在这里被拦。
   316	    → (dfd | None, 失败原因 | None)。调用方负责 os.close(dfd)。
   317	    """
   318	    exam = vault / EXAM_DIR
   319	    try:
   320	        dfd = os.open(exam, os.O_RDONLY | os.O_DIRECTORY | os.O_NOFOLLOW)
   321	    except OSError as e:
   322	        return (
   323	            None,
   324	            f"{EXAM_DIR}/ 打开失败 (被 symlink 布防或不是目录): {type(e).__name__}",
   325	        )
   326	    try:
   327	        st_dfd = os.fstat(dfd)
   328	        st_path = os.stat(exam)
   329	        st_vault = os.stat(vault)
   330	    except OSError as e:
   331	        os.close(dfd)
   332	        return None, f"{EXAM_DIR}/ 身份校验失败: {type(e).__name__}"
   333	    if (st_dfd.st_dev, st_dfd.st_ino) != (st_path.st_dev, st_path.st_ino):
   334	        os.close(dfd)
   335	        return None, f"{EXAM_DIR}/ 在打开前后被替换 (inode 变化), 拒绝写入"
   336	    if st_dfd.st_dev != st_vault.st_dev:
   337	        os.close(dfd)
   338	        return None, f"{EXAM_DIR}/ 与 vault 不在同一文件系统 (疑似越界挂载), 拒绝写入"
   339	    return dfd, None

   342	def _dirfd_still_in_vault(dir_fd: int, vault: Path) -> str | None:
   343	    """复核 dir_fd 指向的仍是 vault 内那个 检验白板/ 目录。
   344	
   345	    ⛔ round-3 HIGH-1: `_open_exam_dirfd` 只在**打开那一刻**做一次 inode 快照。
   346	    校验通过之后, 若有人把该目录 rename 到 vault **外**(同一文件系统),
   347	    dfd 仍指向那个已被移走的 inode —— 写入会真的落在 vault 外, 而回执照旧
   348	    按词法路径报 `created: true`, 用户以为文件在 vault 里。
   349	    修法: 发布完成后**再核一次**「vault/检验白板 这个路径今天解析出来的 inode,
   350	    是否还等于我们手里 dfd 的 inode」。不等 = 目录已被移走/替换。
   351	    → None = 仍在; str = 失败原因。
   352	
   353	    诚实边界: 这是**事后检测**, 不是事前阻止 —— POSIX 没有"把 inode 钉在某个
   354	    父目录里"的原语。它保证的是**不会谎报成功**(检测到就如实回报并撤销),
   355	    而不是"不可能被移走"。残留窗口与 lstat→unlink 那处同源, 已在验收单声明。
   356	    """
   357	    try:
   358	        st_now = os.stat(vault / EXAM_DIR)
   359	        st_dfd = os.fstat(dir_fd)
   360	    except OSError as e:
   361	        return f"写入后复核 {EXAM_DIR}/ 失败: {type(e).__name__}"
   362	    if (st_now.st_dev, st_now.st_ino) != (st_dfd.st_dev, st_dfd.st_ino):
   363	        return (
   364	            f"{EXAM_DIR}/ 在写入期间被替换或移出 vault "
   365	            "(目录 inode 已变) — 写入落点不可信"
   366	        )
   367	    return None

   370	def _rollback_published(
   371	    name: str,
   372	    dir_fd: int,
   373	    identity: tuple[int, int] | None = None,
   374	    *,
   375	    expect_sha: str | None = None,
   376	) -> str | None:
   377	    """撤销**我们自己**刚发布的 target —— 仅当它当前确实还是我们那一份。
   378	
   379	    round-3 HIGH-3: 原实现按 basename 直接 unlink 并静默吞掉失败, 两个问题:
   380	      · identity 快照可能已过时 —— 期间路径被换入他人文件时会误删;
   381	      · 删除失败被吞 ⇒ 错误字节的 target 留在 vault 里, 回执却只报失败。
   382	
   383	    「还是我们那一份」有两种判法, 按调用场景取其一:
   384	      · ``identity``  —— 比 (dev, ino), 用于「刚 link 出来、inode 已知」的场景;
   385	      · ``expect_sha`` —— 比内容 SHA, 用于 HIGH-1 那种「目录整体被移走」的场景
   386	        (此时 inode 仍是我们的, 但我们想确认删的确是自己写的那份字节)。
   387	    两者都给则必须同时满足。任一不符 ⇒ **不删**(那不是我们的东西)。
   388	    → None = 已撤销 / 无需撤销; str = 失败原因(调用方须写进回执, 不得吞)。
   389	    """
   390	    try:
   391	        st_now = os.lstat(name, dir_fd=dir_fd)
   392	    except FileNotFoundError:
   393	        return None  # 已经不在了, 无需撤销
   394	    except OSError as e:
   395	        return f"撤销前复核失败 {type(e).__name__}"
   396	    if identity is not None and (st_now.st_dev, st_now.st_ino) != identity:
   397	        return None  # 已不是我们的 inode ⇒ 是别人的文件, 绝不删
   398	    if expect_sha is not None:
   399	        try:
   400	            cfd = os.open(name, os.O_RDONLY | os.O_NOFOLLOW, dir_fd=dir_fd)
   401	            try:
   402	                buf = b""
   403	                while chunk := os.read(cfd, 1 << 20):
   404	                    buf += chunk
   405	            finally:
   406	                os.close(cfd)
   407	        except OSError as e:
   408	            return f"撤销前回读失败 {type(e).__name__}"
   409	        if hashlib.sha256(buf).hexdigest() != expect_sha:
   410	            return None  # 内容已不是我们写的那份 ⇒ 不删
   411	    try:
   412	        os.unlink(name, dir_fd=dir_fd)
   413	    except OSError as e:
   414	        return f"unlink 失败 {type(e).__name__}"
   415	    return None

   418	def _atomic_write(
   419	    tmp: Path, target: Path, content: str, dir_fd: int
   420	) -> tuple[str | None, str | None]:
   421	    """O_EXCL|O_NOFOLLOW 写 tmp → fsync → **link 到 target (no-replace)** →
   422	    unlink tmp → fsync 父目录。
   423	
   424	    W4 纵深防御: O_NOFOLLOW 让 tmp 若是 symlink 直接 ELOOP 失败 (不跟随),

   438	    中段/父目录被换掉时护不住。修法 = **dirfd 锚定**: 调用方用
   439	    O_DIRECTORY|O_NOFOLLOW 打开 检验白板/ 拿到 dfd 并校验它确在 vault 内,
   440	    此后所有操作只用 **basename + dir_fd=dfd**。dfd 钉死的是那一个目录 inode,
   441	    路径事后怎么换都改变不了操作落点 —— 窗口从根本上消失, 而不是被压小。

   444	    「**锚定成功之后**, `_atomic_write` 内部的落点不再依赖路径解析」。

   544	            "目标已存在 (并发创建), 拒绝覆盖"

   555	    try:
   556	        os.unlink(tmp_name, dir_fd=dir_fd)
   557	    except OSError as e:

   560	        os.fsync(dir_fd)  # dirfd 已在手, 直接 fsync 它 (不再按路径重开)
   561	    except OSError:
   562	        pass
   563	    return None, warn
