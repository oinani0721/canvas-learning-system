## 一、BLOCKER（3 条，全部为真，已改）

### B1 · 动态加载兄弟模块会往 vault 里写字节码缓存
`inbox_preview.py:120` — `spec.loader.exec_module()` 默认在被导入模块旁生成
`__pycache__/split_preview.*.pyc`。触发条件极低：全新 checkout、无既有缓存、
未设 `PYTHONDONTWRITEBYTECODE`，**跑任何命令（包括参数非法的拒绝路径）都会先落这个文件**。

**核实**：属实，且比 Codex 描述更严重 —— 落点在 `canvas-vault/.claude/skills/board-split/scripts/`，
既违反「零写侧」，也**越过本卡硬边界**（board-split 是 V2 车道地盘）。实测两个 `__pycache__`
目录都真实存在（板 02:52 / 本卡 03:33）。

**为什么两道零写门都没抓到它**（这条比缺陷本身更值得记）：
- fixture 快照门的取证树是 `tmp_path` 下的假 vault，真实 skills 目录根本不在树内；
- live 快照门跑的时候 `.pyc` 早已存在且是最新的 → Python 不重写 → 「前后相等」→ 假绿。
一道门看不见的东西，它报绿不代表没发生。

**处置**：`sys.dont_write_bytecode` 包住 `exec_module`（try/finally 还原）；裁判侧的
`load_module` / `load_split_module` 同样包住；清除既有两个 `__pycache__`；
新增门 `test_no_bytecode_cache_written_into_vault_skills` —— **先 rmtree 再跑**，
否则「缓存已在 → 本次没写 → 全绿」还是假绿。

### B2 · 逐字比对抹掉代码缩进 → 语义不同的代码被判「逐字相等」并建议删
`inbox_preview.py:357` — `substantive_body()` 对每行 `.strip()`。
触发：库内 `if ok:` + 缩进 `run()`，收件箱副本 `if ok:` + 顶格 `run()`，同在代码围栏内 →
归一化结果相同 → C4 → **建议删**。

**核实**：属实。这是本卡最严重的一条 —— 它让一个**有后果的提名**建立在错误依据上，
直接违背卡片核心红线。

**根因**：一个函数同时服务两个语义不同的问题 ——「这文件是不是空骨架」（需要激进归一化）
和「这两份正文是不是逐字相同」（必须逐字保真）。

**处置**：拆成 `has_substantive_content()`（C3 用，可激进）与 `dup_body()`（C4 用，
只 rstrip + 丢空行 + NFC，**不** strip、**不**剥列表符）。新增门
`test_code_indentation_is_not_normalized_away`。

### B3 · 不跟踪代码围栏 → 只有一段围栏代码的文件被判空骨架并建议删
`inbox_preview.py:260` — 触发：正文为 `~~~` / `# keep this shell comment` / `~~~` 三行；
围栏标记被 `_ONLY_STRUCT_RE`（含 `~`）删掉，围栏内的 `#` 注释被 `_HEADING_RE` 当标题删掉 →
正文为空 → 建议删。

**核实**：属实，且**与文件头第 364 行「代码块内容留在正文里」的声明直接矛盾** ——
声明与实现对不上，就是掩饰。

**处置**：新增 `_classify_lines()` 围栏状态机（``` 与 ~~~ 各自配对），围栏内的行原样保留、
不参与标题/结构过滤；HTML 注释剥离只作用于围栏外（代码里的 `<!-- -->` 是代码）；
`_ONLY_STRUCT_RE` 移除 `~`。新增门 `test_fenced_code_only_file_is_not_a_skeleton`。
