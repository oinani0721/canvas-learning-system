## 1. Round 1 findings 与处置

Codex round-1 用真实夹具跑了探针（`OUTPUTS_SYMLINK` / `VAULT_SYMLINK` / `VAULT_MODULE` /
`INHERITED_ENV` / `ENTRYPOINT_NOOP` / `PAIR_FINAL`），不是纸面推断。

### BLOCKER-1 · vault 内 `decay_beta.py` 任意代码执行 + 整份环境继承

> 未鉴权的普通表单 POST 会启动继承完整后端环境变量的子进程，而 picker 又直接导入所选 vault 内的
> `.claude/scripts/decay_beta.py`。恶意 vault 代码可用后端权限任意写文件、读取 API key。

**处置 = 部分整改 + 如实登记**

- ✅ **环境继承已堵**：新增 `_child_env()` 白名单（`PATH/HOME/TMPDIR/TZ/LANG/LC_ALL/LC_CTYPE/SYSTEMROOT`
  + `PYTHONDONTWRITEBYTECODE=1` + `PYTHONNOUSERSITE=1`）。`PYTHONPATH`（能让 `import decay_beta`
  解析到**库外**的另一个模块）、`PYTHONSTARTUP`、以及后端进程持有的任何密钥都不再进子进程。
  门：`test_child_env_is_allowlisted_not_inherited`；变异 M11。
- ⚠️ **代码执行面未消除，如实登记**：picker 仍会 import 库内 `decay_beta.py`。这是**生产器既有设计**
  （库自己带衰减参数），宿主 launchd 每小时跑批同样在 import 它。本端点**没有提升任何权限**，
  新增的只是一个触发面；而这个触发面已被 §HIGH-3 的同源门收窄到"本页发起的提交 / 本机脚本"。
  在不改 `daily_review_run.py`/`send_bark.py`、不推翻"库内 decay 参数"设计的前提下，本卡边界内
  无可行的根除方法。→ **上用户裁决点 D-5**。

### BLOCKER-2 · symlink 逃逸（写到库外 / 根外）

> `<vault>/outputs -> <根外目录>` 后 refresh 的两个 `今日复习.*` 都写到了根外；整个 vault 做 symlink
> 也会被 `_list_vault_dirs` 接纳。两个 symlink 别名还因 `key = str(vault_dir)` 得到不同锁和 TTL 账。

**处置 = CLOSED（真修）**

- `_assert_write_target_contained()`：vault 的 realpath 必须在 VAULTS_ROOT 内
  （`vault_outside_root` 503）；`<vault>/outputs` 的 realpath 必须在 vault 内
  （`outputs_outside_vault` 503）。门：两条 symlink 用例；变异 M10。
- `_refresh_key()` 改用 realpath 做 key → 同一物理库的两条别名共用同一把锁与同一本去抖账。
  门：`test_symlink_aliases_share_one_debounce_ledger`；变异 M15。
- ⚠️ **残余（如实登记，与本仓 C1 的 TOCTOU 记录同口径）**：判定与子进程真正 `open()` 之间非原子，
  判定后现换链仍可绕过。堵住的是"已经存在的逃逸链"，不是"判定后现换链"。

### HIGH-1 · 退出码 0 被直接记成重建成功

> 用 `DAILY_REVIEW_PICK` 指向仅 `exit(0)` 的脚本，router 返回 200 / `rebuilt=true` /
> `rebuild_count=1`，同时 `entry.status=no_projection` 且根本没有 `outputs/`；页面调用还会 303
> 进一步隐藏失败。

**处置 = CLOSED（真修）**

- rc=0 之后**读回校验**：`no_projection` → 503 `projection_missing_after_rebuild`；
  `corrupt` → 503 `projection_corrupt_after_rebuild`。
- 两种失败**都不提交 TTL mark / 计数** —— 否则用户修好之前的每次点击都被去抖吃掉，永远修不回来。
  门里专门用 `TTL=300s` 连点两次锁住这一点。
- 表单路径失败改渲染 HTML 错误页并**保持原状态码**，不再 303。
- 门：`test_zero_exit_without_projection_is_not_success`、
  `test_zero_exit_with_corrupt_projection_is_not_success`、
  `test_form_path_failure_renders_error_page_and_keeps_status`；变异 M13 / M14 / M12。

### HIGH-2 · 跨进程锁缺失 + MD/JSON 跨代配对

> `threading.Lock` 只约束当前后端进程，没有加入 launchd 的 C1a 跨进程锁；两个 `os.replace` 也只保证
> 单文件原子性。确定性交错 `A-MD → B-MD → B-JSON → A-JSON` 最终得到 `MD=B、JSON=A`。

**处置 = 窗口收窄 + 如实登记（未 CLOSED）**

- 生产器 `main()` 改为**先把两份内容全部渲染好，再连着发布两次** —— 窗口从"一次 `json.dumps` 的
  时长"收窄到"一次文件 I/O 的时长"。
- **未做**：跨进程锁与真正的配对原子性。理由如实写下：
  - 跨进程锁要复刻 `daily-review-push.sh` 的 mkdir 锁协议 + `send_bark.vault_key` 的命名规则，
    而 `send_bark.py` 在本车道硬边界之外；
  - 真正的配对原子性要目录级换名或跨进程锁，而 VirtioFS 上的锁行为**不可证**（卡文自己就是这么
    裁的：底线押原子性不押锁）。
  - runner 路径的配对窗口（`ensure_payload` 里两次 `atomic_write` + `os.utime`）本卡碰不到，
    收窄只对 `main()` 路径生效。
- → **上用户裁决点 D-6**（要不要单开一张卡做跨进程锁与配对原子性）。
- Codex 另指出测试"用裸 picker 代替 runner"——这一替换及其理由写在测试 docstring 与验收单 §边界 6，
  不假称跑了 runner。

### HIGH-3 · 无鉴权 / 无 CSRF

> 没有 `Depends(require_internal_api_key)`、Origin/CSRF 门或其他调用者校验；普通跨站 HTML form 也能
> 发送该 POST，CORS 至多阻止读取响应，不能阻止副作用。

**处置 = CSRF 已修；鉴权是真缺口，上裁决点**

- ⛔ **施工方更正自己的错误陈述（重要）**：我在 round-2 送审时对 Codex 说
  "`require_internal_api_key` 在本仓不存在、全站无鉴权" —— **这是错的**。我当时只 grep 了
  `backend/app/core/*.py` 与 `backend/app/api/deps.py` 两处，据此下了全称判断。
  实况：它定义在 `backend/app/security.py`，并且是本仓**成体系的写侧鉴权约定** ——
  `sync.py`(×3) / `boards.py` / `memory.py`(×5+) / `exam_sessions.py` / `system.py`(×2) / chat router
  全都挂了 `Depends(require_internal_api_key)`；现网容器里 `INTERNAL_API_KEY` **已配置**。
  Codex 这一条报得对，我的反驳无效。

- ⚠️ **但它与卡文要求正面冲突**：`require_internal_api_key` 读自定义请求头
  `X-CLS-Internal-Key`，而**纯 HTML 表单发不出自定义头**。卡文 (a) 硬要求"页面加刷新表单按钮
  （纯 HTML form POST，零 JS）"。两者不可兼得：
  - 挂鉴权 ⟹ 按钮必死（403），只剩 curl/脚本可用；
  - 保按钮 ⟹ 端点对"能连到这个端口的人"是无鉴权的。
  用 cookie 承载 key 也不成立：`GET /overview/page` 本身无鉴权，谁都能先 GET 一次把 cookie 拿走。

- ✅ **CSRF 真修**（这条与鉴权是两件事，别混）：`_assert_same_origin()` —— 有 `Sec-Fetch-Site`
  必须是 `same-origin`/`none`；有 `Origin` 必须同源；两个头都没有（curl / 本地脚本）则放行。
  门：`test_cross_site_form_post_is_blocked`；变异 M16。
  **它挡住的只有"用户浏览器被别的网页当枪使"**——因为浏览器不允许页面 JS 伪造这两个头。
  它**不是鉴权**：LAN 上一条 curl 可以随手把这两个头填成同源。不要把它当作 HIGH-3 的答案。

- ⛔ **残余（真缺口，不粉饰）**：后端 bind `0.0.0.0`（既有 P0 登记项），因此局域网内任意机器
  都能直接 POST 这个端点 → 触发一次投影重建 → 连带执行该库的 `decay_beta.py`。
  → **上用户裁决点 D-7**（保按钮 / 挂鉴权弃按钮 / 先把 bind 收到 127.0.0.1）。
- ⚠️ **另一条残余**：同机的任意进程仍能直接调它 —— 那样的进程本来就能直接读写这些文件，
  与 D-5 同源。

### MEDIUM · 线程池耗尽

> 同 vault 的重复请求会阻塞等待锁，最长等待 120 秒，持续占用 FastAPI 共享工作线程。

**处置 = CLOSED（施工方自查 S-2 已先行修掉，与本条同因）**

- `lock.acquire(blocking=False)` + `reason=in_progress`。门：
  `test_second_click_while_rebuild_in_flight_returns_in_progress`（若实现改回阻塞，该用例会挂死而非
  静默通过）。
- Codex 附带指出"失败不写 TTL mark → 排队请求会依次再启动子进程"：`in_progress` 已消除并发放大；
  串行连点在失败态下每次只多起一个 ~40ms 就退出的进程，且**故意不给失败加去抖**——加了会让用户
  修好后还要等窗口过期才能重试。

**7/7 全红** —— ⚠️ 但其中 **R3b 这一条的标注是错的**，收官审计抓到并已实测确认：

> R3b 名为「tmp 不用 O_NOFOLLOW」，实际把 `O_EXCL | O_NOFOLLOW` **整体**替换成了
> `O_TRUNC` —— **两个 flag 一起删**。所以它变红是 `O_EXCL` 造成的，与 O_NOFOLLOW 无关。
> 单独只删 `O_NOFOLLOW`（保留 `O_EXCL`）实测：**5 条 atomic_write 用例全绿 = 那是一道死门**。
>
> 根因：`os.open(path, O_CREAT|O_EXCL)` 遇到任何已存在的名字（软链也是一个名字）都抛
> `FileExistsError`，所以在本调用形态下 **O_NOFOLLOW 被 O_EXCL 完全遮蔽**，是纵深防御而非承重件。
>
> 这违反了本仓已记录的纪律「负验证变体必须只禁掉目标那一层」——一次改两层，红了也不知道是谁红的。
> 处置：保留 O_NOFOLLOW（零成本的纵深防御），把该测试的 docstring 改成如实描述它证的是 O_EXCL，
> 并在其中写明「将来若去掉 O_EXCL，必须补一条真能打红 O_NOFOLLOW 的用例，不能沿用这一条」。

（R2 因分支不可达从清单移除，见上表如实登记。）

### 6.1 被证伪的那条（记录下来，避免以后重复报）

> 「并发撕裂门用 pick 替代 runner，runner 的 `os.utime` 把 mtime **回拨**这一形态零覆盖，

**判定：不成立。** 发布证明是 `if after_fp == before_fp` —— **等值**检查（"相对调用前变过"），

### 6.4 审计过程中我另外自己抓到的

- **发布证明差点在最常见路径上误判**：实测发现 `generated_at` 是**秒级**精度，同一秒内的
  多次重建产出**逐字节相同**的 JSON（sha 全等）。若指纹只用 sha，用户连点第二下就 503。
  已补 `test_repeated_refresh_with_zero_changes_still_succeeds`。
- **mtime 是随文件系统而变的假设**：`/vaults` VirtioFS 与宿主 APFS 都是 6/6 纳秒级，但容器
  `/tmp` 的 overlayfs **6 次 os.replace 只得 3 个不同 mtime、inode 还在两个值间轮换**。
  已把指纹加固成 `(inode, mtime_ns, sha)` 三元组，并把残余如实写进 docstring：该误判方向是
  **fail-closed**（用户见 503 而非假成功，盘上数据仍正确），且在生产挂载上不可达。
- **我自己写了一条 flaky 断言**：`assert len(set(shas)) == 1` 依赖 5 次刷新不跨秒边界，首跑即红。
  改成确定性的结构断言（`generated_at` 无小数秒）。
