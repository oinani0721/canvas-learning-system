## 五之三 「红」的定义与 bisect 谓词的不一致（如实声明）

runner 的谓词是三分的：`N failed` → BAD、`N passed` → GOOD、其余（含 collect / import error）→ **SKIP**。这意味着「测试因仓库自身原因无法被收集」在二分过程中**不计为 BAD**。

而 qa_38_6 merged_view / story_38_6 / 第 27 条这 3 条的 first-bad 结论，恰恰建立在「59586af1 起该测试文件整体 collect error」之上 —— 也就是说，结论用的「红」= 「不再 pass」，比 runner 谓词里的「红」= 「failed」更宽。两者不一致，后果是这 3 条的正式 bisect 日志明写 `UNRESOLVED`（58 / 58 / 59 个 possible 候选），**不能说成「bisect 已唯一收敛」**。

本卡的处理：不改判据重跑（那会把 collect error 当 BAD，可能把「测试文件恰好在那时被改坏」误报成生产回归），而是把承重证据换成两条各自独立的实测 —— good 端 `59586af1^` 实测 pass、59586af1 上单点探针实测 collect error，并在 §一 逐行标注「未唯一收敛 + possible 最早者」。若接收卡需要更强的结论，应先明确「collection failure 是否计入 BAD」这一口径，再按统一判据重跑并归档。此项由 Codex round-1 MEDIUM 指出。

## 六 方法学声明（本卡定位过程中被实测挡下的假绿）

1. **判据不能用 pytest 退出码**：老 commit 的 `backend/pytest.ini` addopts 含 `--cov --cov-fail-under=85`，实测覆盖率 23%，故即使「1 passed」退出码也是 1。`git bisect run` 把 rc=1 判 bad ⇒ GOOD 端也会被判 bad，收敛到错误的 first-bad 而流程毫无异常。本卡 runner 只读 pytest 摘要行（`N failed` / `N passed`），退出码仅记录不作判据。
2. **`timeout` 在 macOS 不存在**：卡文 §〇 模板里的 `timeout 300` 实测 `command not found` → rc=127，而 `git bisect run` 把 127 当 bad ⇒ 每一步都判 bad。本卡改用 `perl -e 'alarm N; exec @ARGV'`，并把超时（142）映射为 125(skip) 而非 bad。
3. **端点 checkout 失败必须显式校验**：`git checkout --detach <GOOD>` 失败时树仍停在 BAD 端，runner 会把 BAD 端结果当成 GOOD 端结果，产出「good 端也红 ⇒ 候选被推翻」的假结论（epic30 首轮即如此，存档 `-r2-checkout-failed.txt`）。修复后脚本比对 `git rev-parse HEAD` 与期望 GOOD，不符即 rc=99 不进入 bisect。
4. **二分是否收敛必须显式校验**：端点验证通过（`ENDPOINT_STATUS=INTERVAL_OK`）不代表 `git bisect run` 跑成了 —— 中途 checkout 被 local change 阻断时 git 直接 `Aborting`，存档里没有 first-bad 行却看不出异常。修复后脚本检查 `git bisect log` 是否含 `# first bad commit`，否则标 `BISECT_RUN_FAILED`。
5. **不能往 scratch 树放 `.env`**：`backend/.env` 在部分老 commit 是 tracked（且含 `bolt://localhost:7691` 现网 URI），放一份消毒副本 = local change ⇒ 下一次 checkout Aborting。改为全部配置经环境变量注入（pydantic-settings 优先级 env > dotenv），既无 local change 也不连现网、不写 live vault（`VAULTS_ROOT` 指向临时目录）。
6. **测试写 tracked 文件也会阻断二分**：`backend/data/review_data.db` 被测试写入后成为 local change。runner 每步跑完执行 `git checkout -- .` 恢复。
7. **sparse-checkout 的取舍会造成伪失败**：仓库根与 `backend/` 根都存在非法字节序列文件名（macOS 无法创建，树内切换直接中止），`_bmad/**/workflow.yaml` 在切换时反复报 local changes。但把 `src/` 排除掉会让老 commit 的 `tests/conftest.py → app.main → endpoints/rollback.py → from src.rollback import` 失败，runner 判 SKIP，**看起来像「测试那时不存在」**。最终 pattern 为白名单式并显式保留 `/src/`。
8. **`git log` 的搜索面**：首次在主仓（`main` 分支）跑 `git log -S ... -- <file>` 对 5 个文件返回空，误读为「函数从未出现」；这些文件只在车道分支历史里。所有历史查询均改在车道树执行。
9. **`grep ... | head; echo $?` 取的是 `head` 的退出码**（恒 0），不能用作「有无命中」的判据。
10. **`time (cmd | tail)` 会让 `$pipestatus[1]` 失真**，不再指向被测命令。
