## 1. 本阶段要证明什么

Phase 0A 不是把所有 `User：` grep 到一张表，而是建立一条之后可以机械审计的证明链：

```text
获批的来源边界
  → 不可变 SourceOccurrence
  → 人工/模型辅助原子化 AtomicAnnotation
  → duplicate / supersedes / decision authority
  → 用户批准的全部 ExternalReviewBatch 或逐项 Waiver
  → ChatGPT 回复归档
  → Codex 对全部回复逐事实复核与 reconciliation
  → 分歧交用户裁定并回写 A02
  → Product Intent Contract（A03）
```

只有这条链完成后，才允许进入 Phase 0B 和后续产品实现。marker、行数、旧 tracker、模型摘要和文件名都不能替代有效原子需求的分母。

## 3. A01 Source Manifest 的建议边界

### 3.1 互斥 Source Plane

A01 必须把“字节对象”和“它在哪个来源面出现”分开：`SourceObject` 是 content-addressed bytes，`SourceBinding` 是 `plane + locator + SourceObject` 的一次绑定。同一 bytes 只解析一次，但所有 path/ref/commit 绑定必须保留为 provenance alias。每个 binding 恰好属于下列一个互斥面：

| Plane ID | 纳入对象 | 互斥规则 |
|---|---|---|
| `PLANE-REPO-HEAD` | HEAD tree 中的 path/blob binding | 只代表 committed HEAD，不代表 index/worktree |
| `PLANE-REPO-INDEX` | 与 HEAD 不同的 staged add/modify/delete binding | 只记 index delta；与 HEAD 相同的 entry 不重复入面 |
| `PLANE-REPO-WORKTREE-MODIFIED` | 与 index 不同的 tracked 工作树 bytes | 仅 modified binding |
| `PLANE-REPO-WORKTREE-DELETED` | index 存在但 worktree 缺失的 path | 删除本身是 binding；旧 bytes 从 index/HEAD object 取得 |
| `PLANE-REPO-WORKTREE-UNTRACKED` | 不在 index 的本地 path/bytes | 不得默认为产品事实，先视为用户资产 |
| `PLANE-GIT-REFS` | heads/remotes/tags/stash/checkpoint 全部 reachable commit/path/blob binding | 与 current planes 共享 SourceObject，但 commit/ref binding 不丢失 |
| `PLANE-EXTERNAL-READONLY` | 锚定 PRD、授权 Vault/transcript/backup 等 repo 外来源 | 每个 root 独立授权，不与 repo plane 混算 |

repo-wide 文本容器至少覆盖根目录、`_bmad-output`、`docs`、`_decisions`、`openspec`、`_prd-register`、`.gdr`、`.claude`、`_bmad`、`_bmad-archive`、`_archive` 以及 backend/frontend/scripts。Markdown、Canvas JSON、JSON/JSONL、YAML、纯文本和对话导出必须分别由声明过的 parser adapter 处理；未知容器或解析失败必须进入失败分桶，不得被 Markdown 计数静默遮蔽。

### 3.2 Root 与授权边界

Root 是授权/隐私边界，plane 是物理 provenance，两者正交；archive 不能因同时属于 HEAD 而重复计数。

| Root ID | 当前状态 | 规则 |
|---|---|---|
| `ROOT-REPO-CURRENT` | boundary approval pending（proposed include） | 覆盖 HEAD/index/worktree 五个 current plane；只读，不清理、不覆盖 |
| `ROOT-GIT-REFS` | boundary approval pending（proposed include） | 全 reachable refs；blob 只解析一次，绑定全保留 |
| `ROOT-ANCHORED-PRD` | boundary approval pending（proposed include read-only） | 锚定 PRD；公开层只存获批 locator 或 opaque ID、receipt commitment |
| `ROOT-ACTIVE-VAULT` | boundary approval pending | 原文/路径只在 private ledger；public 只留 opaque ID 与 keyed commitment |
| `ROOT-EXTERNAL-PRIVATE-01` | local census known；export unauthorized | 不外发原文；逐批脱敏，不能安全改写则逐项 waiver |
| `ROOT-TRANSCRIPTS` | source unavailable | 只有用户导出并授权后才能纳入；未导出的聊天不能声称已扫描 |
| `ROOT-GRAPHITI-MEMORY` | tool unavailable in this session | 只可作 discovery hint/derived source，不能覆盖原始 blob/transcript |
| `ROOT-OTHER-BACKUPS` | unknown | 用户逐根确认已纳入或排除；未裁定时保持 pending，不计 complete |

`archive-derived` 仅是 `SourceBinding.classification_overlays` 上的分类标记，不是第九个 physical root，不能自行产生授权或第二份 binding/occurrence。repo 内 archive/backup/template/review pack/generated docs 必须继承其实际 provenance 的 `ROOT-REPO-CURRENT` 或 `ROOT-GIT-REFS`；repo 外 archive/backup 必须绑定到另一个明确列举、逐 root 获得 boundary receipt 的 physical root（现有类别无法表达时须通过新 schema revision 新增）。长期 Goal/原则确认不等于 A01 boundary receipt；在精确 boundary approval 前，拟纳入的 physical root 仍是 `boundary-approval-pending`。

### 3.3 默认排除

可以排除依赖、build/cache、二进制、数据库/索引、模型权重与 secret 正文，但必须记录规则版本、逐对象排除 reason code 与授权 receipt。以下不能静默排除：archive、backup、template、review pack、generated docs、损坏 Markdown、大文件、非法 UTF-8 或含 NUL 文本；它们应进入 `excluded/unreadable/parse-error/source-unavailable/pending` 分桶，使完整性门 fail closed。

### 3.4 A01 per-object 证明链与分母

```text
BoundaryRevision(parent + cutoff + roots + ruleset + user receipt)
  -> SourceRoot
  -> SourceBinding(plane + opaque locator token；private locator map 不提交)
  -> SourceObject(content identity)
  -> ScanAttempt(parser + outcome + error)
  -> SourceOccurrence
  -> AtomicAnnotation
```

- A01 每个 revision 必须有 `manifest_revision_id`、`parent_manifest_payload_sha256`、`manifest_payload_sha256`、`scan_cutoff_at_utc`、完整的 `source_object_inventory`、`source_binding_inventory`、`scan_attempt_inventory`、`scan_attempt_count`、`inventory_state_counts`、parser/normalizer 版本和精确 `boundary_approval` receipt；不得只保留聚合计数或一个不可重放的总 commitment。
- `source_object_inventory` 以 `source_object_id + object_revision` 标识不可变 revision，保存 `content_identity/scan_state/reason_code/candidate_count/candidate_commitment/current_scan_attempt_id/exclusion_approval_receipt_commitment`；`source_binding_inventory` 以 `binding_id` 为业务唯一键，保存 `root_id/plane_id/classification_overlays/source_object_id/locator_token/vcs_oid/authorization_state/authorization_receipt_commitment`；`scan_attempt_inventory` 以 `scan_attempt_id` 为业务唯一键，保存所绑定的 `source_object_id + object_revision`、ruleset/parser 版本、起止时间、outcome/error 和 public/private receipt。`inventory_state_counts.total` 只计全部 SourceObject，`approved_object_total` 只计获批 object 分母，`binding_total` 只计 SourceBinding，`scan_attempt_count` 只计 ScanAttempt，四者不得混为一个分母。
- 每个获批 SourceObject 恰好一个当前结果：`scanned / excluded / unreadable / parse-error / source-unavailable / pending`。`scanned` 再分 `with-candidates / no-candidate`，两者都保留 scan receipt。
- 分母公式固定为：`inventory_state_counts.approved_object_total = scanned + excluded + unreadable + parse_error + source_unavailable + pending`；六个集合互斥，必须与获批 object ID 集逐 ID 相等。同时 `inventory_state_counts.total = len(source_object_inventory)`、`inventory_state_counts.binding_total = len(source_binding_inventory)`、`scan_attempt_count = len(scan_attempt_inventory)`；checker 必须证明 `approved_object_total <= total`，不能拿未授权对象、binding 或 attempt 稀释分母。
- `scan_completeness=complete` 时 `unreadable=parse_error=source_unavailable=pending=0`。若用户决定不再追索某对象，必须用绑定该 object revision 的逐项 receipt 将其转为 `excluded`；不得让失败或 pending 原地通过。
- 每个 `scan_state=scanned` 且当前 `ScanAttempt.outcome=scanned-with-candidates` 的 object，其 scanner candidate 数必须与 A02 `SourceOccurrence` 逐 ID 对齐；每个 included occurrence 至少映射一个 atom。A02 空数组不能靠 vacuous truth 通过。
- 当前 A01 draft 已声明 8 个 physical root、7 个 plane 以及 object/binding/scan-attempt inventories 与相应 counts；`archive-derived` 仅作 binding classification overlay。但 inventories 仍为空、counts 仍为 0，invariant checker 仍为 `not-run`；这只是 `boundary-review/incomplete`，不是“无批注”或 A01 complete 证据。
- **结构现况（不得误报完成）**：最新 A01 schema 已表达 `SourceObject.object_revision`、独立 `scan_attempt_inventory`、`current_scan_attempt_id` 与绑定 object revision 的逐对象 `exclusion_approval_receipt_commitment`。这只消除了先前的 shape 缺口；在真实 inventory、receipt 和独立 checker 全部通过前，仍不可声称 apply-ready/complete。

## 4. Parser 契约

### 4.1 三层召回

1. **T1 高精度**：大写 `User`、编号/空格/修正/Comment、明确中文“用户批注/反馈/修正/原话”。
2. **T2 异常大小写与 emphasis 变体**：`user/USer`、marker 被粗体符号拆开、表格/blockquote/list 嵌套。
3. **T3 broad discovery**：role 字段、代码、转述、无冒号编号等；必须人工分类，不能直接进入有效需求分母。

至少覆盖：`User：`、`User:`、`User ：`、`User :`、`User 修正：`、`User1/User2/User 2`、`User Comment:`、用户批注/反馈/原话、表格/行中/同一行多 marker、多行续写、空槽、HTML 注释、模板/示例/引用、`[!BMAD-ANNO]` 以及学习 callout。

### 4.2 解析不变量

- 保存原始 bytes；NFKC、空格/冒号折叠只生成 comparison field。
- 使用 Markdown 状态机/AST 识别 heading、table、blockquote、HTML comment、fenced code 和 continuation。
- Discovery、来源分类、atomization 三步分离。
- Git blob 以 OID 去重解析；同 blob 的路径/ref/commit 全保留 alias。
- 大文件必须流式扫描；NUL/非法编码不能静默当 0。
- 修正链不得只靠相似度自动覆盖，必须保留人工/用户裁定。

## 5. 三个物理数据层

### 5.1 Private Truth Layer（默认 repo 外）

- 目录权限目标 `0700`、文件 `0600`。
- 保存私人绝对路径、Vault 映射、原始 bytes、精确 locator、round/Q ID、raw digest、private prompt/reply、用户批准原文与 waiver 私人理由。
- raw SHA-256 只可在 private layer 用于本机去重/比对，不得作 public identifier、public evidence 或跨边界 locator。向 public 投影时必须换成 §5.4 的 domain-separated HMAC commitment。
- 密钥 ID/轮换、备份恢复、保留/删除期和删除 receipt 都属于 private policy，须在扫描私有 root 前获用户批准。
- “repo 内 gitignored”只作为用户明确批准的降级方案；默认不使用。

### 5.2 Public Audit Projection（可提交）

- 只允许 opaque ID、严格枚举、聚合统计、获批的非私人 repo-relative locator、public canonical payload SHA 和 keyed commitment。
- 只有 `root_id=ROOT-REPO-CURRENT AND plane_id=PLANE-REPO-HEAD` 的已提交公开证据，在 privacy scan 通过后才可使用 A02 `publicRepoLocator`（POSIX repo-relative path + nullable `line`）。index、dirty/worktree、Git refs/history、PRD、archive、Vault、transcript、Graphiti memory、backup 和任何 external root 一律 opaque，即使内容看似 P0/P1 也不例外。
- `publicRepoLocator.relative_path` 还必须是 NFC 的 repo-relative BMP path，并拒绝 C0/C1 control、Unicode `General_Category=Cf`（含 bidi control）、surrogate/astral code point、noncharacter、反斜杠、绝对路径、URL/percent encoding 和 `..` 穿越；checker 必须用冻结的 Unicode allowlist 复检并证明 canonical path 仍位于该 public root 下。
- A01 `source_binding_inventory.locator_token`、A02 `SourceOccurrence.locator_token` 和 private evidence locator 都是随机 opaque ID；它们不是 path 的编码。公开层禁止绝对路径、用户名、Vault 名、私有 URL/query、可猜测文件名与用私密语义编码的“opaque” ID。
- public/private 必须共享同一组随机对象 ID；private locator map 不提交。对 A01 `unreadable/parse-error/source-unavailable/pending` 只存 object-level token、reason code 和 commitment，不伪造 byte span/line hint；A02 的 `pending/source-unavailable` occurrence 必须令 `utf8_byte_start/utf8_byte_end/line_hint/anchor_before_commitment/anchor_after_commitment/public_content_commitment` 全为 `null`。每个 occurrence 的 `source_binding_id` 必须唯一反查到 A01 binding，且该 binding 的 `source_object_id/locator_token` 与 occurrence 完全一致。
- 未知字段一律拒绝；采用 allowlist，而不是事后 denylist 脱敏。

### 5.3 External Review Pack

- `size_policy=standard` 的正常批是确定字节内容，包含 6–8 个同主题原子需求。`size_policy=final-tail` 可为 1–5 个，但仅在同主题再无其他 eligible atom，且 `size_exception_reason_code=final-theme-tail` 并有绑定精确 annotation revision 集合的 `size_exception_user_receipt_commitment` 时合法；禁止用 padding/重复项凑数。
- 用户批准的 private `pack_payload_commitment` 必须与实际发送 bytes 的 domain-separated HMAC 完全相等；改一个字节即生成新 batch `record_revision` 并重新审批。
- pack、prompt、reply 默认留 private；public 只留 keyed commitment、状态与无私人正文的 reconciliation 证据，不留对 private bytes 的裸 SHA。
- 包内不预填 Codex 结论，保持 ChatGPT 盲审。

### 5.4 Canonical Hash Profile（冻结）

A01 与 A02 的 `hash_profile_id` 必须完全等于 `CLS-CANONICAL-JCS-NFC-SHA256-HMAC-V2`。`§5.4` 是该 profile 的 normative envelope；schema 中的 description 只是它的投影，不得另造第二套规则。

**Canonical bytes**

1. JSON payload 在序列化前对所有 string key/value 做 Unicode NFC；NFC 后 key 冲突必须拒绝。随后按 RFC 8785/JCS 序列化为 UTF-8。原始 source bytes 保持不变，不做 NFC。
2. `null` 与 absent 不等价。语义为 sequence 的数组保持 schema 指定顺序；语义为 set 的数组按 schema 声明的 stable business key 升序排列后再 JCS。未声明数组语义或 duplicate business key 必须拒绝。
3. 下表中的 `\0` 是单个 NUL byte `0x00`，不是反斜杠、字符 `0` 或 JSON escape 的两个字节。`domain_bytes` 是表中 NUL 终止的 ASCII bytes，payload 前不再加长度、换行或额外分隔符。

**Public SHA-256 envelope**

`public_digest = SHA-256(domain_bytes || payload_bytes)`。只有不含私密材料的 public payload 可用此公开 digest：

| 用途/字段 | `domain_bytes` | `payload_bytes` 与排除字段 | 序列化 |
|---|---|---|---|
| A01 `manifest_payload_sha256` | `CLS/A01-MANIFEST/v2\0` | A01 public manifest 排除 `manifest_payload_sha256` 和完整 `invariant_check`；parent hash 保留 | 64 位 lowercase hex |
| A01 public `SourceObject.content_identity` | `CLS/A01-SOURCE-OBJECT/v2\0` | 精确原始 public source bytes；无 JSON/NFC，无排除字段 | `sha256:<64 lowercase hex>` |
| A02 `projection_payload_sha256` | `CLS/A02-PROJECTION/v2\0` | A02 public projection 排除 `projection_payload_sha256` 和完整 `invariant_check` | 64 位 lowercase hex |
| A02 record digest：`AtomicAnnotation.record_payload_sha256` 与 event `payload_before_sha256/payload_after_sha256` | `CLS/A02-RECORD/v2\0` | 对应的 `SourceOccurrence/AtomicAnnotation/ExternalReviewBatch/ExternalReviewWaiver` record；若 record 含 `record_payload_sha256`，先排除该字段。create event 的 `payload_before_sha256=null`，其余 event 指向上一 subject revision 的 record digest | 64 位 lowercase hex 或 schema 允许的 `null` |
| A02 `event_payload_sha256` | `CLS/A02-EVENT/v2\0` | 完整 event 排除 `event_payload_sha256`；`previous_event_sha256`、`payload_before_sha256`、`payload_after`、`payload_after_sha256` 保留 | 64 位 lowercase hex |

A01 `invariant_check.checked_manifest_payload_sha256` 必须等于上表 A01 manifest digest；A02 `manifest_payload_sha256` 必须等于被引用 A01 revision 的该 digest；A02 `invariant_check.checked_projection_payload_sha256` 必须等于 projection digest。上述两个 projection 排除整个 `invariant_check` 是为消除 checker report 反向引用被检 digest 导致的循环。

`generator/parser/redaction ruleset/checker executable/public evidence/public scan report` 等 `*_sha256` 是已批准 public artifact 精确 bytes 的完整性身份，不新增 canonical object/projection domain，也不得用于 private bytes。A01/A02 `invariant_check.report_payload_sha256` 固定为 public checker report 在排除自身 `report_payload_sha256` 后的 NFC + JCS bytes 之 plain SHA-256；它位于 manifest/projection hash scope 之外。checker 必须同时复算这些辅助 public artifact SHA；若 artifact bytes/scope 未冻结或含私密材料则拒绝。

**Private HMAC envelope**

凡 private bytes/canonical private JSON 投影到 public，计算式唯一固定为：

`commitment_hex = HMAC-SHA256(K_audit_local, domain_bytes || canonical_or_raw_private_bytes)`

private JSON 使用上述 NFC + JCS bytes；原始文本/文件/发送 pack 使用它们的精确 raw bytes。`K_audit_local`、key ID/mapping、private bytes 和 raw SHA 都不得进入 public projection。

A01/A02 共用且只能使用三个 serialized tag/base-domain；一律为 `hmac-sha256:<TAG>:<64 lowercase hex>`：

| `<TAG>` | `domain_bytes` | 适用 commitment |
|---|---|---|
| `CLS_PRIVATE_CONTENT_v2` | `CLS/PRIVATE-CONTENT/v2\0` | A01 private content/candidate/scan report/boundary scope/private projection/refs/index/dirty/untracked；A02 source content/anchor、private evidence、reply、Codex reconciliation |
| `CLS_EXTERNAL_PACK_v2` | `CLS/EXTERNAL-PACK/v2\0` | `pack_payload_commitment`、`approved_pack_commitment`、`sent_pack_commitment` |
| `CLS_APPROVAL_RECEIPT_v2` | `CLS/APPROVAL-RECEIPT/v2\0` | A01 root/binding authorization、逐对象 exclusion 和 boundary approval receipt；A02 redaction/deferred/batch/waiver/final-tail/user actor 的 trusted receipt |

A01 只使用 `CLS_PRIVATE_CONTENT_v2` 和 `CLS_APPROVAL_RECEIPT_v2`；`CLS_EXTERNAL_PACK_v2` 只属于 A02 ExternalReviewBatch。A01 的精确字段映射为：

- `content_identity`（私有）、`candidate_commitment`、private `ScanAttempt.receipt.report_payload_commitment`、`boundary_approval.scope_commitment`、`private_projection_commitment`、`vcs_snapshot.refs_inventory_commitment`、`vcs_snapshot.index_inventory_commitment`、`vcs_snapshot.dirty_delta_commitment`、`vcs_snapshot.pre_artifact_untracked_inventory_commitment` → `hmac-sha256:CLS_PRIVATE_CONTENT_v2:<hex>`。
- root/binding `authorization_receipt_commitment`、`SourceObject.exclusion_approval_receipt_commitment` 和 `boundary_approval.user_approval_receipt_commitment` → `hmac-sha256:CLS_APPROVAL_RECEIPT_v2:<hex>`。

任何 field-specific 或 v1 serialized tag/domain 均属于与当前 `hash_profile_id` 不兼容的结构。当前 A01 schema 只允许上述两个统一 tag，并已从 manifest hash scope 排除完整 `invariant_check`；任何后续回退都必须 fail closed，而不是降级本契约。

任一 tag、domain byte、payload preprocessing、排除字段或序列化形式不匹配，即使 hex 长度正确也必须 fail closed。

## 6. A02 不是一张平表

必须拆成四类实体：

1. **SourceOccurrence**：`occurrence_id + record_revision`、`manifest_revision_id/source_object_id/source_binding_id`、parser rule、marker/source/discovery state。每个 `source_binding_id` 必须唯一连接 A01 SourceBinding 并匹配其 `source_object_id/locator_token`；`included/excluded` 才有 byte span，`pending/source-unavailable` 的 span、line hint、anchors 与 content commitment 必须全为 `null`。对象级失败仍须由 A01 `ScanAttempt` 保存 error/retry/commitment。
2. **AtomicAnnotation**：`annotation_id + annotation_revision`、occurrence aliases、requirement kind、OBJ 映射、validity/local-review/implementation/evidence 正交状态、duplicate/supersedes DAG、privacy、owner/next action，以及 `export_eligibility`、`redaction_approval_commitment`、`external_review_batch_id/external_review_waiver_id`。`deferred` 额外必须有绑定当前 annotation revision 的 `deferred_approval_commitment` 和 `deferred_until_utc`。
3. **ExternalReviewBatch**：`batch_id + record_revision`、annotation revision refs、`size_policy`、pack/redaction/approval/sent/reply/reconciliation commitment、`destination_provider=openai-chatgpt`、`destination_product=chatgpt`、model label、opaque `destination_session_token` 与各状态时间；session token 在发送前必须为 `null`，从 `sent` 起必须存在，terminal revision 则按 `terminal_from_state` 保留同一约束。
4. **ExternalReviewWaiver**：`waiver_id + record_revision`，只绑定一个 annotation revision payload，只能由真实用户逐项批准，可过期/撤销/被替代；`requested` 时 `user_approval_receipt_commitment=null`，到 `granted` 才必须有可验证的 receipt，不得由 agent 或 automation 代签。

所有转换写 append-only `LedgerEvent`。每个 event 必须内联完整 `payload_after`，并包含 schema 字段 `event_id/ledger_sequence/event_type/subject_kind/subject_id/subject_revision/actor/actor_receipt_commitment/occurred_at_utc/previous_event_sha256/payload_before_sha256/payload_after/payload_after_sha256/event_payload_sha256`。只存 hash/ref 而没有完整 `payload_after` 的“事件”不符合当前 A02 schema，不可重放，一律拒绝；waiver 进入 superseded 必须写 `event_type=waiver-superseded` 且 `payload_after.state=superseded`。

`subject_revision` 必须等于 atomic annotation 的 `payload_after.annotation_revision`，或 SourceOccurrence/ExternalReviewBatch/ExternalReviewWaiver 的 `payload_after.record_revision`；同一 subject 的 revision 只能单调 append。`payload_before_sha256/payload_after_sha256` 必须用 §5.4 的 A02 record envelope 分别绑定前后 revision；create event 的 before 为 `null`，后续 event 的 before 必须等于同一 subject 上一 revision 的 digest。二者都不能取代完整 `payload_after`。

current projection 必须完全由 genesis + ordered events replay 生成；若持久化 current arrays，它们只是 materialized cache，必须与 replay 的 canonical bytes 一致。任何记录不得 in-place 改写历史 revision。原 Goal 的综合 disposition 不能同时冒充候选分类、事实复核、实现和外审状态。

## 7. External review 状态机

```text
atom export_eligibility:
  pending -> blocked-private -> eligible
          -> prohibited-secret
          -> not-required-invalid-candidate / not-required-noncanonical
batch: redaction-pending -> prepared -> approval-pending -> approved-to-send
      -> sent -> reply-received -> codex-reconciled
      -> superseded / invalidated
waiver: requested -> granted -> revoked / expired / superseded
```

- `prepared/approved-to-send/sent` 都不等于 reviewed。
- `export_eligibility=eligible` 必须绑定当前 `annotation_revision`、当前脱敏 bytes、`privacy_scan_state=pass` 和 `redaction_approval_commitment`；不能仅由 `privacy_class` 自动推导。`P4-secret` 必须是 `prohibited-secret`，不得进 batch。
- 外审目的地固定为 `destination_provider=openai-chatgpt` 且 `destination_product=chatgpt`；必须记录 schema-safe `destination_model`、不可逆的 `destination_session_token` 和 trusted sent receipt。session token 不能是 URL、标题、账号、prompt/reply 或可逆 locator；Codex 自审、未知 provider/product 或其他模型不得冒充 ChatGPT 审查。
- 只有 batch 中的 atom revision ref 全部存在且 `eligible`，`pack_payload_commitment = approved_pack_commitment = sent_pack_commitment`，`approval_receipt_commitment`、`sent_receipt_commitment`、`destination_session_token`、`reply_commitment`、`codex_reconciliation_commitment` 和相应时间全部存在，且 checker 证明 session token 绑定该精确 sent receipt，才派生 `externally-reviewed`。
- annotation revision payload 改变后，旧批准和旧 waiver 自动失效；旧 waiver 必须用 `waiver-superseded` event 留下可重放的 superseded revision，而不是原位删除。
- waiver 必须绑定精确 atom revision/record commitment/reason/expiry policy 与 trusted user receipt；批量、类别、旧 revision 或 agent 自行 waiver 无效。
- review denominator 为当前有效 canonical atom；duplicate 必须通过 alias 映射到被审 canonical atom，superseded/rejected/excluded 的退出理由和授权仍保留。分母中每项终局严格二选一：`externally-reviewed XOR external-review-waived`。
- 有 waiver 时只能声称“除用户逐项豁免外均完成 ChatGPT 审查”。

## 8. 必须由 validator 机械证明的不变量

JSON Schema 只证明单个对象的 shape/type/enum/conditional-required，不能代替跨文件不变量。必须有独立 invariant checker；A01 固定 `validator_id=cls-a01-invariant-checker-v2` 并用 `validator_executable_sha256`、A02 用 `checker_executable_sha256` 固定实际运行的 checker artifact，`pass/complete` 时不得为空。`complete` 命令须先跑 schema，再运行该 content-addressed checker，任一失败均非零退出。checker 至少证明：

1. §3.4 的 SourceRoot/Binding/Object/ScanAttempt/Occurrence 跨引用全部存在，plane 互斥；`inventory_state_counts.approved_object_total` 六分桶公式、`total`、`binding_total` 与 `scan_attempt_count` 均逐 ID 成立，ScanAttempt/current attempt/outcome、object revision 和 exclusion receipt 互相一致。schema 已表达这些 shape，但 checker 仍必须独立验证集合关系，不得信任文档自填的 `pass`。
2. `complete` 时 unreadable、parse error、source unavailable、pending、未知 ruleset 和未裁定 root 皆为 0；逐项排除必须有绑定当前 object revision 的 trusted user receipt。
3. 每个 occurrence 恰好一个 classification；其 `source_binding_id` 唯一解析到 A01 binding，且 `source_object_id/locator_token` 相等；`pending/source-unavailable` 的 span/anchor/content 字段全空。每个 included occurrence 至少映射一个 atom；A01 scanner candidate IDs 与 A02 occurrences 全等。
4. 每个有效 canonical atom 至少一个 occurrence，且恰好映射 OBJ-01–08 或 explicit non-goal；duplicate/supersedes 跨引用存在、无环，历史来源不删除。
5. genesis 加按 `ledger_sequence=1..N` 排序的 append-only events 能重放出 projection，projection canonical bytes 完全相等；`previous_event_sha256` 链无断裂，非 create event 的 `payload_before_sha256` 等于同一 subject 上一 revision digest，`subject_revision` 与 `payload_after.annotation_revision/record_revision` 一致且单调，`waiver-superseded` 的 payload 确为 superseded waiver revision。
6. A01/A02 `hash_profile_id` 完全相等，所有 canonical envelope SHA/HMAC 按冻结的 §5.4 的 5 个 public SHA domain + 3 个 HMAC domain 重算一致，辅助 public artifact SHA 也按其冻结 bytes/scope 复算；自身 hash 不参与自身计算，manifest/projection 排除完整 `invariant_check`，public 不含 private raw SHA 或 field-specific/v1 tag。
7. 状态所需 timestamp/receipt/commitment 全部存在且单调；`codex-reconciled` 不得在 approved/sent/reply 之前，revoked/expired 不得倒退；sent-or-later batch 的 opaque session token 必须绑定 trusted sent receipt，并在相应 terminal revision 中保留。
8. trusted receipt 必须由冻结的本机 trust root 验证，绑定 action、subject/revision、canonical payload commitment、scope 和 time；单纯 `actor=user` 字符串或裸 receipt hash 不是批准证据。
9. active/open 项 owner 与 next action 非空；`disposition=deferred` 有 `deferred_approval_commitment` 和未过期 `deferred_until_utc`；`verified` 同时具有实现证据和真实 UAT。
10. 每个 reviewed atom 都能反查到 `destination_provider=openai-chatgpt`、`destination_product=chatgpt`、schema-safe model、opaque `destination_session_token`、`export_eligibility=eligible`、`redaction_approval_commitment`、精确 `external_review_batch_id`、`pack_payload_commitment = approved_pack_commitment = sent_pack_commitment`、`sent_receipt_commitment`、`reply_commitment` 和 `codex_reconciliation_commitment`；每个 waived atom 都有当前 revision 的 trusted user receipt；reviewed 与 waived 互斥。
11. `size_policy=standard` 为 6–8；1–5 只能是符合 §5.3 的 `size_policy=final-tail`；无 orphan batch/atom/waiver/ref。
12. public/private opaque ID 集一致，public secret/private canary 为 0；公开 locator 仅允许 CURRENT+HEAD，并通过 NFC、BMP、Unicode Cf/bidi/noncharacter/control、path traversal、root containment allowlist 与 privacy scan。
13. 相同 snapshot 重跑 canonical payload 与 commitment 相同；source/ruleset/authorization 改变必须生成新 revision，旧 revision 不改写。

## 9. 先验收 schema + invariant checker，再跑 final census

### A01 最小门

- strict schema：未知字段、错版本、错类型、非 object root 全部拒绝。
- 临时真实 Git 仓覆盖 HEAD/index/worktree-modified/worktree-deleted/worktree-untracked/Git refs 互斥面，以及 rename、deleted blob、multi-ref、archive 和 external backup root。
- A01 逐 object inventory、六分桶公式与 A02 occurrences 跨引用逐 ID 通过 checker；空 ledger 不能通过。
- A01 schema 已声明的 object/binding/scan-attempt inventories、object revision、逐对象 exclusion receipt 与三类 counts 必须与 §3.4 一致；这些字段存在只代表 shape 可表达，真实 cross-reference 与 receipt trust 仍必须由 content-addressed checker 验证。
- 同 snapshot 两次 canonical payload/commitment 相同；任一来源/规则/授权变化产生 delta。
- 所有 marker 代际与负例有 fixture。
- 无 size/NUL/非法编码静默跳过。
- public projection 的私人路径、原文、private raw SHA、secret canary 命中为 0；public/private locator map、Unicode/path allowlist 和 commitment 边界经 checker 复算。

### A02 最小门

- 一 occurrence 拆多 atom、多 occurrence 合 duplicate、correction supersede 可 replay。
- event 内联的完整 `payload_after` 能从 genesis 完整 replay projection；cycle、orphan、重复 ID、断链、非法状态/时间转换以及错误 `waiver-superseded` payload 全部拒绝。
- `prepared/approved/sent` 均无法通过 reviewed gate。
- pack 改一个字节后审批失效；`pack_payload_commitment = approved_pack_commitment = sent_pack_commitment`；自动/类别/旧 revision waiver 全拒绝。
- 每个 atom 的 `export_eligibility`、`redaction_approval_commitment`、`destination_provider=openai-chatgpt`、`destination_product=chatgpt`、opaque `destination_session_token` 与 sent receipt 绑定、trusted approval receipt、`reply_commitment` 和 `codex_reconciliation_commitment` 通过跨引用 checker。
- verified 缺代码或 UAT 任一证据即拒绝。
- 所有分子/分母由 A01 per-object inventory + A02 event replay 联合生成，不接受 ledger 自说自话或手写统计。
