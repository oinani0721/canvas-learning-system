### 2.5 M13：实测**证伪**了原注释，不是补证据

原注释（`runtime_sha.sh` snapshot 段）：「compgen -G 的展开结果本身就按 collating
sequence 排好序，所以不必引入外部 sort」。

绑定环境实测（`GNU bash 3.2.57(1)-release (arm64-apple-darwin25)`，六个文件
`p__{zeta,alpha,Mid,beta,10,2}.jsonl`）：

```
$ /bin/bash --noprofile --norc -c 'builtin compgen -G "p__*.jsonl"'
p__alpha.jsonl  p__2.jsonl  p__Mid.jsonl  p__zeta.jsonl  p__beta.jsonl  p__10.jsonl   ← readdir 顺序
$ /bin/bash --noprofile --norc -c 'for f in p__*.jsonl; do printf "%s\n" "$f"; done'
p__10.jsonl  p__2.jsonl  p__alpha.jsonl  p__beta.jsonl  p__Mid.jsonl  p__zeta.jsonl   ← 排序（同 ls）
$ LC_ALL=C … compgen -G …   ← 与默认 locale **逐字相同**，可见它压根没走排序
```

**pathname expansion 排序、`compgen -G` 不排序，两者不能互相推断。** 原断言为假。

处置：加 `SORT_BIN=/usr/bin/sort`（绝对路径 + 可执行校验 + **fail-closed**，不像
`DIFF_BIN` 那样软降级）+ `LC_ALL=C` 钉死字节序。排序**刻意拆出管道**：

```bash
__raw="$(builtin compgen -G "$g" || true)"      # `|| true` 只给「无匹配」用
[ -n "$__raw" ] || continue
__sorted="$(builtin printf '%s\n' "$__raw" | LC_ALL=C "$SORT_BIN")" || { …GATE-BROKEN…; exit 1; }
```

理由：串成 `compgen … | sort || true` 的话，**sort 自己坏掉**也会被同一个 `|| true` 吞掉
⇒ glob 项整组静默消失、门照样打印 unchanged —— 正是脚本里那道 compgen 自检要防的
假绿的翻版。

危害等级如实说：顺序不稳定造成的是**假红**（before/after 因排列不同而字符串不等），
不是假绿。假红比假绿轻，但门一旦以「爱误报」出名，下一个人就来放宽它。

## 4. 诚实边界

### 4.1 这几道门不比什么

- runtime 文件门**只看清单里那几个具名文件**（3 固定 + 1 glob）。同族的
  `lancedb_pending_index__*.jsonl`（`lancedb_index_service.py:76`）**仍不在清单里** ——
  本卡明确不扩面（扩面会让门变严，属另一张卡的范围决策）。
- 它只比首尾两个时刻；命令中途写进去、结束前又改回原内容，照判 unchanged。
- AST 门是**静态**分析。它证明的是源码里没有那几种形态，不证明运行时没有别的路径。
- 本卡新加的 6 条探针都在 **tmp 假 backend** 上跑。它们证明的是「门对这些场景给出
  正确结论」，不证明真实 lifespan 一定会产出那些文件名（那一条由 §2.2 的 `[5b]` 单独
