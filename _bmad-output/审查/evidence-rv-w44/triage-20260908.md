### 3.3 ⛔ 覆盖面登记（本卡**不**证明的部分）

⚠️ **本节初版把探针的实际输入说反了，本卡外审 LOW-4 指出后已实测更正。**

初版写「探针只覆盖『stderr 已关闭』这一种坏法，`sys.stderr` 被替换成 `write()` 抛异常的对象**未覆盖**」
——**方向是反的**。HEAD `lifespan_isolation_guard_probes.py:1772-1776` 的实际输入是：

```python
class Boom:
    def write(self, *a, **k):
        raise ValueError("I/O operation on closed file")
    def flush(self, *a, **k):
        raise ValueError("I/O operation on closed file")
```

随后 `sys.stderr = Boom()`（:1779）。这**恰恰就是**「替换成 `write()` 抛异常的对象」，
而且 `write` 与 `flush` 双桩，比一个真正已关闭的 stderr 覆盖面更**宽**。
初版是被**异常消息字符串**里的 `"I/O operation on closed file"` 误导——
消息文本里有 "closed file" 不代表输入真的是一个已关闭的流。
（教训：描述覆盖面要看**实际构造**，不看它抛出的消息长什么样。）

### 3.4 ⛔ 新发现：HIGH-3 的同型残留（本卡外审 HIGH-1，本卡独立验证 CONFIRMED）

本卡初版写「两处打印/落盘全在 try 内」——**漏了第三处**。`_final_accounting` 里：

```python

1278:        try:
1279:            write_ledger(path, ledger)
1280:        except Exception as exc:  # noqa: BLE001 —— 落盘失败要说话，但不能盖掉结账

1291:        try:                      ← 保护块从这里才开始
...
```

`:1278` 的 `try` **只覆盖 `write_ledger`**，不覆盖它自己 `except` 体里的 `:1281`。

**本卡独立验证**（外审自述其片段实验「没有实际写盘，完整 guard 与真实文件系统故障组合未验证」，
