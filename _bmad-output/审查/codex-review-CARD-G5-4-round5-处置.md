## 处置（结构性转向：黑名单 → 白名单）

| # | 发现 | 处置 |
|---|---|---|
| H2 | 无据行的"禁数字字符"既有绕过（仨/皕/零）又有误伤（十分/一致） | **整行固定文案白名单**：无据行必须整行等于 `- <信号名>：无据（<原因>）`，原因逐字取自 `_NODATA_REASONS` 五条常量（与 SKILL.md 模板同源）。字符层面的攻防就此终结——自由文案一律 FAIL，也就不存在"数字混进来"的可能 |
| H3 | 有数行尾部用黑名单外字符构造 `仨/仨` 仍能追加第二组计数 | 尾部除禁 Unicode 数值外，**再禁任何 `/` 斜线结构**——X/N 这个*结构*本身就是计数载体，与用什么字符写无关 |
| H4 | 派生断言写在种子段**之外**（派生段/①段/散文行）绕过段内白名单 | 升级为**全局行白名单**：fallback 下任何含「派生」的行必须整行匹配五种合法用法之一（规模自陈行/段落标题/无来源结论信号行/关系类型分布行/「派生角色成员」叙述），每种都对应 scan JSON 里**有据**的字段。不再判断某行"是不是在断言子女数" |
| M3-绕过 | 引用块内的围栏（`> ``` `）与四空格短闭合未被识别 | `_strip_code_blocks` 先剥任意层引用前缀再判围栏 |
| M3-误伤 | 合法的四空格缩进三级列表被当缩进代码块删除 → 误报"③段缺信号行" | **不再剥缩进代码块**；改由信号行严格模板自身拒绝四空格缩进（`^(?! {4}\|\t)` 前瞻）。既堵住"藏在缩进块里"，又不误伤列表 |
