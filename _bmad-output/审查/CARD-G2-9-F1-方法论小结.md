# CARD-G2-9-F1 方法论小结 —— 五轮外审里反复出现的几类错

> 给后续卡（尤其 `CARD-G2-9-F2`）看的。都是本卡实际栽过的，不是通则复述。

## 一 判据坏了，比被测物坏了更常见

本卡有 **6 次**「判据报错但代码没问题」，每次都靠「先证伪判据、再怀疑被测物」捞回来：

| # | 判据 | 坏法 |
|---|---|---|
| 1 | `connect` 溯源 v2 | 只认 `db_path` 变量名 ⇒ 漏掉 fixture 里的 `path = tmp_path_factory…`（**假绿**） |
| 2 | 同上 v3 | 收集表达式内**所有** Name ⇒ f-string 里的目录名片段被当成路径根（**误报**） |
| 3 | 同上 v4 | 取「最左根」下钻 ⇒ `str(db_path)` 被取成 `str`（**误报**） |
| 4 | §二.7 判据 ② | `awk '/^async def _amain/,0'` 把 `_amain`+`_run_canary_cli`+`main` 一起罩住 ⇒ 数字对但**覆盖面宽于主张** |
| 5 | 负控 6/8 的 nodeid | `parametrize` 叠加时**离函数最近的 id 在最左**，我写反了 ⇒ 0 命中 ⇒ **假 NOT-KILLED** |
| 6 | 存档引用 | 手写时间戳错两次 ⇒ 补了「文档引用 vs 实有文件」判据当场抓出 |
| 7 | `*.stderr*` 未入库 | 判据面（`grep 'stderr'`）比协议约束（`*.stderr*`）**宽**，加上中文路径转义让 `git cat-file -e` 误报 ⇒ 差点把别卡的历史文件当成自己的越界。判据面**必须恰好等于**它要验的那条约束；非 ASCII 路径一律 `-c core.quotepath=false` |

**通用防线**：每条判据都配**验伪锚**——逐项从安全集里移除，看它是否真的产生越界。
本卡的溯源判据最终形态就是这样（四个安全名逐个移除，各自都能让判据翻红 ⇒ 无冗余项）。

## 二 「XPASS(strict) 会自动提醒」是有前置条件的

`xfail(strict=True)` 做跨卡交接，前提是**用例里不能有别的断言**：

- xfail 吞掉用例内**任何**失败，**fixture setup 阶段也不例外**（实测，不是推测）。
- 更要命：缺陷被修好时，写在同一用例里的「前提断言」会**先**翻转失败 ⇒ 结果停在 XFAIL
  ⇒ **承诺的报红永远不来**。
- 修法：前提拆到**不带 xfail 的独立用例**。
- 但拆开后前提门凭什么代表缺陷锁那份夹具？⇒ 共用 **module-scope fixture**。
  关键**不是**「fixture 失败不被吞」（照样吞），而是**不带 xfail 的前提门也用它** ⇒ 它那里 ERROR。
- 共享又引入**顺序依赖**：缺陷锁会改库，前提门里任何**实时**查询都会读到改后状态而假红。
  ⇒ 依赖共享状态的检查**全搬进 fixture**，前提门只留「复述自检结果 + 纯函数断言」。
- 参数化 + 共享库 = 后跑的参数看到先跑的残局 ⇒ **每个参数组合一个独立库**。

**XPASS 至少有三种成因**，写 reason 时要列全：F2 真修好 / 上游某个修复被撤 /
删除本身失败而异常被生产代码吞掉。第三种从门里分辨不出来。

## 三 改动的影响面 = diff 能看见的 + **可达性变化**

本卡最重的一条发现（外审提出，我复核成立）：
我修分页盲区（枚举从「前 10 张」扩到全库），**没改任何归属口径**，
却让一条既有的错误删除路径**从碰不到变成碰得到** —— 那些新变可达的行**不在 diff 里**。

⇒ 复审时要专门问一句：**「我修好之后，哪些原本走不到的代码现在走得到？」**
（姊妹方向来自 U10-A 车道：**「我加的这道防线会不会误伤？」** —— 同一问题的两个方向。）

本卡把它做成了**负控 6/8**：拆掉分页收口，对应的门就从 xfail 翻成 XPASS 报红
⇒「本卡打开了这个可达面」成了门锁住的事实，而不只是探针说的。

## 四 一个规则在 N 处同形重写，第 N+1 处必然漏

归属规则在 `da690bf8` 上散成两类共四处：**判断**两处（`resolve_table_name:790` 的
`startswith(f"{vid}_")`、`list_vault_tables:846` 的 `startswith(prefix)`）+ **名字构造**两处
（`resolve_table_name:792`、`_fingerprint_table_name:997` 的 `f"{vid}_…"`）。
而**启动自愈那处一个都没有** —— 那就是本卡要修的缺陷。
（写这句时我先写成「三处同形」，`git show da690bf8 | grep -n startswith` 实测只有**两处判断** ⇒ 已更正。）
修法是**收成单点**（`_owns_table`），不是在漏写处补一份。

证明「单点与原实现逐字同语义」不能靠读代码：本卡的做法是把 `da690bf8` 的原判据
**按行号切出来、逐字校验后 `exec`**，与新实现在 128 组合上对撞，并配验伪锚
（把 default 口径换成错误读法，看对撞是否能发现分歧）。

## 五 同一缺陷的不同消费路径，触发条件可以差一整个条件

同样是「短 id vault 认领长 id vault 的表」：

| 路径 | 需要 schema 漂移? | 有指纹表豁免? | 入口 |
|---|---|---|---|
| `_cache_tables` 启动自愈 | **要** | **有**（`endswith`） | 进程启动 |
| `drop_vault_tables` | **不要** | **没有** | 用户点「删除索引」 |

⇒ 登记触发条件时**按路径分别列**，不要合成一份「四条件」——那会让门槛更低的那条被漏记。
（本卡第一版正是这么漏的，外审第三轮才指出。）
