### H-3（.env.<vault> 的密钥写入早于 chmod 600）
⚠️ 更正：我最初写成「每次 apply 都命中」，**错了**。逐行实测后的准确条件如下。

$ grep -n 'seed_env_file\|chmod' scripts/deploy-vault.sh
  :546  mv "$ENV_FILE.tmp" "$ENV_FILE"
  :547  chmod 600 "$ENV_FILE"        <- seed **自己就收紧了**
  :564 / :688  `if [ ! -f "$ENV_FILE" ]; then seed_env_file; fi`   <- seed 只在文件**不存在**时跑
  :769  os.open(p, ... O_CREAT, 0o600)   <- 文件已存在时 mode 参数被内核忽略
  :783  chmod 600 "$ENV_FILE"        <- 步 3 到这一行才收紧

=> 首次 apply：seed 建文件并在 :547 chmod 600 ⇒ 步 3 写入时**已是 0600，无窗口**。
   二次 apply：文件是首次留下的 0600 ⇒ **同样无窗口**。
   **命中条件 = `.env.<vault>` 由脚本以外的来源预先存在且权限较宽**（典型：用户想预置
   NEO4J_PASSWORD 等键而手建，缺省 umask 落 0644；或 `--env-dir` 指向已有同名文件的目录）。
   此时 seed 被跳过 ⇒ :547 不执行 ⇒ 密钥在 :769-778 写进 0644 文件、:783 才收紧。
   单用户 macOS 风险低；多用户/共享机器上是真实的密钥可读窗口。
   修法方向（留给人审裁定，本卡不改）：B4 写入**之前**先 chmod，或 seed 用 `(umask 077; …)`。
$ ls -l .env.* → 只有 .env.example（5244B）；车道树内无任何 .env.<vault> 残留。
