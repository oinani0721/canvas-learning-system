这些负控跑在**中间 HEAD** 上，都已被最终 HEAD `8fe610bd` 上重跑的同名段取代
（见上一级目录的 `negctl-{1..10}-*.txt`）。留在这里是因为：

     **绑定形态**漏报；整改后同一段变成 `owners - allowed = ['def:verify']`、GATE FAIL。
   - `negctl-9-*`（绑 `e64fc5c5`）：`调用点门 owners - allowed = []（空 = 这一条它看不见）`
     与 `调用图门 reachable(verify) = ['_write_report']` 并排打印 —— 这是「为什么需要两条门」
     最直接的一份证据。

绑定的 HEAD 写在每份存档的第 2 行，不要把它们与最终 HEAD 的那一套混用。

所以它必须留档作废，不能悄悄重跑了事。
