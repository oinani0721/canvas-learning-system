HIGH — 只加 --text 不够。awk 的字符串是 NUL 终止的: 一条新增行里只要标记**前面**出现
NUL, index() 就看不见它(实测 `+x<NUL> # <标记>` 判 MISS 且 rc=0)。git 把完整字节交出来
了, awk 却只看到 NUL 之前那一截。round-1 的 6-3 把标记放第一行、NUL 放第二行, 恰好避开
了这个缺口。修法: 喂 awk 之前 `LC_ALL=C tr '\000' '?'` 等长归一化(行号与各种前缀不受
影响, 也不会凭空造出标记)。新增对照 case-h1-nul-before-marker.sh + 真 hook 负控 B。

MEDIUM-1 — 管道的 rc 是末段的。`tr … | wc … | tr …` 里首段 tr 在 UTF-8 locale 下遇非法
字节序列会报 Illegal byte sequence 并少数一个, 整链却 rc=0(本机 LANG 实测就是
en_US.UTF-8)。修法: 字节处理一律钉 LC_ALL=C, 且拆成能各自核 rc 的步骤。

MEDIUM-2 — SEEN==EXPECTED 只说明「没少读」, 不说明「读到过」: 空清单遇上 read 报错会得到
0 == 0 而通过。修法: 往记录流末尾追一条绝不可能是真实路径的结束哨兵(git 路径不以 / 开头),
主循环必须真的读到它。新增对照 case-m2-empty-read-error.sh。

LOW — lefthook 2.1.6 起的是 `sh -c`, 那个 sh 由进程 PATH 查找, 不是硬编码 /bin/sh。注释
改为「按 PATH 查找; 本机当前解析到 /bin/sh = bash 3.2.57」。

另: 对照套件改为**两种解释器都跑**(bash 与 sh, 后者才是真实 runner)。据此如实降级 6-5 的
主张 —— `:` 是 POSIX 特殊内建, 在 sh 下重定向失败本来就会退出 shell, 那条守卫在真实
runner 下的收益是「把静默退出变成有诊断的阻断」, 不是「把放行变成阻断」。已写进注释。
