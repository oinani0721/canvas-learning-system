### 3.3 修复：逐行正则 → 命令解析

B1–B4 同源于一句话：**逐行正则替代不了命令解析**。因此把"行 → git occurrences"这一步换成真词法分析（`scripts/lib/scan_git_occurrences.py`）：

| 修复 | 做法 |
|---|---|
| B1 签名粒度 | 签名细化为 `add:ALL` / `add:path` / `commit` / `push:<remote>` / `push:DEFAULT`。**`git add -A` 与 `git add openapi.json` 不再共享签名** |
| B2 一行多命令 | 按 `&&` `\|\|` `;` `\|` 拆 simple command，**逐 occurrence 出签名**；引号外的 `#` 起注释并丢弃 |
| B3 命令链/引号/全局选项 | 不再按首 token 丢整行；`shlex` 剥引号（`"git"` 可执行名）；跳过 `-C/-c/--git-dir/--work-tree`；跳过 `if/!/then/while` 等 shell 关键字前缀；剥离 yaml 的 `run:` 键前缀 |
| B4 递归闭包 | 沿 `bash/sh/node/python/source` 递归展开，带 visited set 与深度上限 6 |
| B4 exec-form | settings hook 的 `args` 数组拼进命令 |
| B5 覆盖面 | 新增 `~/.claude/plugins` 来源；扩展名含 `.cmd` |
| H6 hooksPath | 改用 `git rev-parse --git-path hooks` **实际解析**，不硬编码 |
| H6 lefthook | 检测到 `extends:` / `remotes:` 即报 `UNANALYZABLE`（静态扫不到被合并的外部配置）；额外扫 `lefthook-local.yml` |
| H6 LaunchAgent | 改用 `plistlib`（兼容 binary plist），读 `Program` 与 `ProgramArguments` |
| H7 负例 | N0–N10 扩至 **N0–N16**，Codex 的每个 BLOCKER 场景都成为回归锁 |

### 3.5 ⚠️ ACK 机制的自陈风险（如实记录，未回避）

登记表含 **15 条 `ACK`**（已人工核查的解析边界），当前环境实际触发 12 条。每条都实测过"该文件 `git add/commit/push` 计数 = 0"。

**但必须如实说明其局限**：`ACK` 是按 `<source>::UNANALYZABLE` **整体**登记的，而非绑定到具体的行与命令。这意味着：**同一来源日后新增的另一条无法解析的命令，会被同一条 ACK 覆盖掉而不报警**。

这是当前设计的**已知残留风险**，已作为 round-2 的重点审查方向提交给 Codex。收紧方向（尚未实施）：ACK 绑定到 `文件路径 + 行号 + 命令内容 SHA`，任何变化即失效重审。
