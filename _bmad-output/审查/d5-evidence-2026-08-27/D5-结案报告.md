## 摩擦点汇总（24 条去重为三类）

### A. SKILL 设计缺口（转"board-recap 维护卡"候选，按命中频次排序）

1. **单次调用铁律 × 原样落盘的保真冲突**（3/4 agent 独立命中，最高优先）：HARD-NAV-1 禁止同板同轮二次调用，导致返回体只能经 LLM 转写落盘（~8KB 单行 JSON 转写面大）或冒截断风险。建议：SKILL 允许首刀 `curl -o` 直接落盘再 cat 查看。
2. **UTC/本地跨日双问题**（4/4 命中）：报告 recap_date 是本地日而新鲜度段全 UTC，人读易惑；symlink 预检要手填"今日日期"但预检发生在 scan 之前（鸡生蛋），填 UTC 日即错。建议：新鲜度段附本地时间括注 + 预检日期改由脚本产出。
3. **MCP 工具缺位路径未写进 SKILL**：工具不可用时的 HTTP 等价调用与 `{ok,error,manifest}` 包裹形状全靠 recap_scan.py 注释兜底，SKILL 正文只字未提。
4. **board_name_mismatch 无呈现条款**（CS 61B 灰区裁量成功但属运气+素养）。
5. 幂等询问次序：同日重跑时审计快照先于用户"续读/覆盖"选择被覆盖。
6. `include_exam_history` 参数与端点默认行为轻微漂移。
7. "从未考察"与"检验历史 in_progress"并存时的措辞调和依赖 LLM 自觉。
8. 模板占位行照抄即死（占位符检查设计如此，但属最易踩返工点——本轮 4 agent 全部预判规避）。
